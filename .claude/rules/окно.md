# Окно просмотра FlexRt.Ui

Решения пользователя: WPF + BlazorWebView, компоненты Radzen.Blazor (MIT), файл
выбирается диалогом «Открыть pdata.fwc…», имена дерева как в TIA, вкладки
Properties/Info справа в заголовке инспектора с иконками. Окно только
просматривает: файлов не пишет, проект ПЛК не читает. Поведение окна глазами
пользователя — `docs/текущее-поведение/окно-просмотра.md`.

## Структура

```
src/FlexRt.Ui/
App.xaml, MainWindow.xaml(.cs)   окно WPF с BlazorWebView, службы BlazorWebView и Radzen
Components/ Shell/               Viewer (корень: открытие файла, состояние), Toolbar, StatusBar
            Tree/                ProjectTree, Icon — дерево проекта как в TIA
            Screens/             ScreenCanvas — холст экрана с масштабом
            Inspector/           PropertiesPanel, PropertyValue — панель Properties/Info
Panel/                           PanelFileDialog — выбор pdata.fwc
      Screens/                   ScreenItem, ScreenItems, ScreenKind, StartScreenColumn — экраны для окна
wwwroot/                         index.html; css/ — base, shell, tree, canvas, inspector
```

## Связь с ядром

- Окно стоит рядом с консолью справа от ядра: пользуется только публичным API
  ядра, ядро про окно не знает. Окно только читает панель (`FwxReader.Read`) и
  строит строки листа «Экраны» (`ScreensTable`), `ExtractionRun` не вызывает и
  `IExtractionReporter` пока не реализует — реализация у интерфейса одна
  (`ConsoleReporter`). Разделить `ExtractionRun` на чтение и выгрузку для окна —
  открытый вопрос.
- Окно повторяет значения колонки Вид листа «Экраны» (`ScreenKind`) и заголовки
  колонок `Name`, `Start screen`: меняется `ScreensTable` — проверь окно.
  Неизвестный вид окно кладёт в папку «Вид не опознан»; пропажа колонки Name или
  несовпадение числа строк с числом экранов — ошибка чтения в строке состояния.
- Регистрация служб BlazorWebView и Radzen в `MainWindow` — единственное
  исключение из правила «без DI».

## Проверка окна

- Запущенное окно держит `FlexRt.Core.dll` в своём `bin`: сборка решения падает
  с MSB3027. Своё окно закрой, запущенное пользователем — только с его согласия.
- Поведение окна автоматически не проверяется. Меняется то, чем оно пользуется
  (`FwxReader`, `ScreensTable`, модели экранов), — открой в окне шаговую копию
  экранов (`samples/screens/05_popup.fwc`).
- Проверять окно: запуск exe с `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`,
  DOM и клики — через CDP. Клавиатуру эмулировать только если на переднем плане
  именно диалог открытия файла (иначе ввод уходит в другое окно).
- Radzen: панель разделителя, которая стоит не последней, не сжимается
  (`flex-shrink: 0`) — задавай размер ей; цвета компонентов меняй переменными
  `--rz-*`, а не перебиванием свойств: правила Radzen для наведения сильнее.
