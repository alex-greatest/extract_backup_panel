# Окно просмотра FlexRt.Ui

Решения пользователя: WPF + BlazorWebView, компоненты Radzen.Blazor (MIT), файл
выбирается диалогом «Открыть pdata.fwc…», имена дерева как в TIA, вкладки
Properties/Info справа в заголовке инспектора с иконками. Окно показывает
панель; данные ПЛК читает, если их выбрали; файлы пишет только по кнопкам
сохранения (ниже): книги Excel, выбранная картинка и все картинки в zip.

Решения пользователя по тексту запуска и данным ПЛК: консоль больше не печатает,
её текст (`RunTranscript`, без строк экспортов; строка `Файл ПЛК:` — только с
выбранными данными ПЛК): строки Info — на вкладке Info моноширинным шрифтом,
предупреждения и ошибки — на отдельной вкладке «Ошибки» (иконка уровня у строки,
ниже — разделы, которые не построены). На заголовке «Ошибок» — иконка и число по
худшему уровню (красные при ошибке, жёлтые при одних предупреждениях, при нуле
— ничего); после открытия с проблемами — уведомление Radzen (`NotificationService`,
`<RadzenNotification />` в `Viewer`) на 6 с, вкладка сама не переключается;
число — ещё и в строке состояния. Кнопка
«Данные ПЛК» (меню `RadzenSplitButton`): «Файл PEData.plf…», «Карта ПЛК…»
(диалог папки), «Без данных ПЛК»; выбор живёт до закрытия окна, открытая
панель перечитывается. Панель с несколькими соединениями и выбранными данными
ПЛК — `ОШИБКА: не поддерживается…` на «Ошибках» с концом «панель показана без данных
ПЛК» (в консоли — «файлы не созданы»: конец передаётся в `PlcDataReader.Read`),
панель без данных ПЛК («Данные ПЛК» — «не задан»). Не прочитан сам файл —
`Не удалось прочитать…` на «Ошибках» и «Файл не прочитан» в строке состояния; упал
следующий шаг — панель не показывается, на «Ошибках» и в строке состояния
`ОШИБКА: <шаг>: <причина>` (сводка панели не построена, экраны не разобраны,
картинки не разобраны, данные ПЛК не обработаны, разделы не построены). Поведение окна глазами
пользователя — `docs/текущее-поведение/окно-просмотра.md`.

Решения пользователя по таблицам разделов: разделы — листы `panel_data.xlsx` и
языки `PDATA.xlsx` (дерево: «Сводка», HMI tags, HMI alarms ▸ Discrete alarms,
Analog alarms, System events, Alarm classes, Alarm groups, Screens, «Тексты» ▸
язык); папка Screens открывает таблицу листа «Экраны», число у неё — строки
этой таблицы; тексты строит окно, а не ядро; в «Сводке» без данных ПЛК «Данные
ПЛК» — «не задан», модель панели и версия Runtime — «неизвестно» (файлы рядом с
`pdata.fwc` окно не читает); раздел, который ядро построить не смогло, остаётся
в дереве с ⚠ и ошибкой, сообщение — на вкладке «Ошибки»; фильтр, скрывший
выбранную строку, снимает выбор; Ctrl+C копирует выбранную строку через Tab.
Панель без тегов окно показывает, хотя консоль `panel_data.xlsx` тогда не
пишет, — оставлено как есть.

Решения пользователя по картинкам: узел «Картинки» с числом картинок — в корне
дерева после Screen management и «Вид не опознан», перед «Тексты»; картинок
нет — узла нет. Картинки — все из `FwxDocument.Pictures` в порядке ядра
(сначала `PICTURE`, затем `TILED_PICTURE`), имя — как у файла консоли
(`PictureExporter.FileName`: `PICTURE_5.png`). Щелчок по узлу — галерея
миниатюр в центре (заголовок `pdata.fwc ▸ Картинки`, внизу `Картинок: N`),
выбрана первая; щелчок по плитке — выбор. Properties: General — Name, Table,
Number (с единицы, как в hex), Format (`PNG`/`JPG`), Bytes, Width, Height (из
заголовка файла: PNG — `IHDR`, JPEG — первый `SOFn`; не прочитаны —
«неизвестно»), справа — картинка в натуральную величину. На всё окно — двойной
щелчок по плитке или щелчок по картинке в Properties: тёмный слой поверх окна,
картинка вписана в него (маленькие увеличиваются без сглаживания), подпись
`имя · W × H px · i из N`; ← и → (и кнопки ‹ ›) — соседняя картинка, на краях
списка не листает, выбор в галерее идёт следом (выбор картинки, как и строки,
снимает ошибку действия в строке состояния); Esc, щелчок по фону или ✕ —
закрыть, щелчок по картинке не закрывает. Фокус всё время на слое: кнопки его не
забирают, Tab внутри слоя ничего не делает (к кнопкам окна под слоем не
уйти); новое открытие панели и выбор другого узла закрывают просмотр.

Решения пользователя по сохранению в Excel: на панели инструментов после
«Данные ПЛК» — меню `RadzenSplitButton` «panel_data.xlsx» с пунктами «Вся
книга…» и «Текущий лист…» и кнопка «PDATA.xlsx…»; кнопки доступны, когда
панель открыта и не читается, заняты во время сохранения. Файл выбирается
диалогом «Сохранить как» (фильтр `*.xlsx`, Windows спрашивает о перезаписи);
имя по умолчанию — `panel_data.xlsx`, `PDATA.xlsx`, у листа — имя листа
(`Теги.xlsx`); папка — последнего сохранения до закрытия окна, до первого —
папка `pdata.fwc`. Книга — то, что показано в окне, а не книга консоли:
«Сводка» как в окне (модель и Runtime «неизвестно», без данных ПЛК «Данные
ПЛК» — «не задан»), листа «Ошибки» нет никогда (ошибки — в окне). Вся книга —
листы в порядке книги консоли («Сводка», «Теги», «Системные события»,
«Дискретные алармы», «Аналоговые алармы», «Классы алармов», «Группы
алармов», «Экраны»): «Теги» пишется и без тегов, листы алармов — те, что есть
в дереве, «Экраны» — если экраны есть; раздел, который не построен, не
пишется. «Текущий лист…» доступен у построенного раздела книги (не у экрана,
не у языка текстов) и пишет одну книгу с его листом той же раскладки.
`PDATA.xlsx` пишет экспортёр консоли `XlsxExporter` из строк языков панели.
Итог — уведомление Radzen на 6 с: «Сохранено» и путь (зелёное), «Сохранено не
всё» с листами, пропущенными из-за непостроенных разделов, «… не записан»
(ни один раздел не построен, в STRINGSTORE нет строк — диалог тогда не
показывается) — жёлтое; ошибка записи (файл открыт в Excel) — «Не удалось
сохранить: <путь>: <причина>», красное и в строке состояния (если за время
записи не открыли другой файл); сбой самого диалога — «Не удалось сохранить:
диалог сохранения: <сообщение>». «Текущий лист…» без построенного раздела
книги ничего не делает. Отмена диалога ничего не меняет.

Решения пользователя по сохранению картинок: на панели инструментов после
«PDATA.xlsx…» — меню `RadzenSplitButton` «Картинки» с пунктами «Выбранная
картинка…» и «Все в zip…»; меню доступно, когда сохранять можно и картинки в
панели есть, «Выбранная картинка…» — когда в галерее выбрана картинка. Картинка
пишется как есть, имя по умолчанию — имя файла консоли (`PICTURE_16.jpg`),
фильтр — её формат; архив — `images.zip`, в корне все картинки под именами и в
порядке папки `images` консоли (`PictureArchiveExporter` ядра, записи без
сжатия). Диалог, папка, итог и ошибки — как у Excel.

Все сохранения пишут во временный файл рядом с выбранным
(`имя.<guid>.расширение`) и заменяют им выбранный только после удачной записи:
сбой (диск, файл занят) не портит прежний файл, временный удаляется.

## Связь с ядром

- Окно стоит рядом с консолью справа от ядра: пользуется только публичным API
  ядра, ядро про окно не знает. `ExtractionRun` окно не вызывает (он пишет
  файлы): `PanelLoader` читает панель `FwxReader.Read`, текст собирает `RunTranscript`
  (`PanelRead`, при ошибке чтения — `PanelReadFailed`), данные ПЛК читает
  `PlcDataReader.Read` — тот же шаг, что в `ExtractionRun`.
- Разделы листов `panel_data.xlsx` окно строит из описания книги ядра
  `PanelDataBook` — того же, по которому пишет консоль: какие листы есть, из
  каких таблиц и в каком порядке (`PanelDataBook.TryBuild`, каждый лист
  отдельно); с данными ПЛК — по сопоставлению и проекту из `PlcData`, без них
  (или при «не поддерживается») — `TagMatcher.Match(doc, null)`, как консоль без
  данных ПЛК. Своё у окна — узлы дерева: имя как в TIA, путь и значок по имени
  листа и порядок алармов в папке HMI alarms — одна таблица `PanelViews.Nodes`.
  Лист ядра без строки в ней — разделы не строятся, панель не открывается:
  `ОШИБКА: разделы не построены: … у листа «X» нет узла в дереве окна`. Раздел
  хранит сам лист ядра (`PanelSection.Report`), его и сохраняет. Листа «Экраны»
  нет (экранов нет) — раздел Screens пустой, папки Screens в дереве нет.
  Группировку текстов и имя листа `0x<lcid>` окно повторяет как `XlsxExporter`:
  меняется ядро — проверь окно.
- Окно повторяет значения колонки Вид листа «Экраны» (`ScreenKind`) и заголовки
  колонок `Name`, `Start screen`: меняется `ScreensTable` — проверь окно.
  Неизвестный вид окно кладёт в папку «Вид не опознан»; пропажа колонки Name или
  несовпадение числа строк с числом экранов — `ОШИБКА: экраны не разобраны: …`.
- Картинки окно берёт из `FwxDocument.Pictures` (`PanelPictures.From` — отдельный шаг
  `PanelLoader`, картинки лежат в `LoadedPanel` рядом с экранами, а не в разделах);
  имя — `PictureExporter.FileName` ядра, то же, что у файла консоли: меняется имя в
  ядре — меняется и в окне. В разметке у `img` — адрес
  `https://pictures.flexrt/<номер открытия>/<имя>` (`PictureHost`), а не `data:`:
  через мост Blazor идут только адреса, браузер кэширует картинки и грузит миниатюры
  лениво. Байты отдаёт `MainWindow` (WebView2 `WebResourceRequested`, фильтр
  `PictureHost.Filter`) из картинок службы `PictureSelection` — той же, что у
  `Viewer`; картинки нет у открытой панели — 404. Номер открытия не даёт показать из
  кэша одноимённую картинку прежней панели.
  Ширину и высоту даёт ядро — `Parsing/Panel/Pictures/PictureSize` (исключений не
  бросает; JPEG — с байтами заполнения 0xFF и маркерами без длины; тест
  `Unit/Panel/PictureSizeTests`); консоль размер не выводит.
- Сбой построения одного раздела не мешает остальным и экранам: раздел с пустой
  таблицей и `PanelSection.Error`. Ошибка чтения файла — «Файл не прочитан»,
  ошибка экранов или данных ПЛК — панель не открывается, шаг назван.
- Сохраняет окно через ядро: всю книгу и лист — `ReportSheetsExporter` из
  готовых таблиц разделов (`ReportSheet`: «Сводка» и «Теги» — раскладка
  `SummarySheet`, `TagsSheet`, остальные — таблица с первой строки), `PDATA.xlsx`
  — `XlsxExporter`; имя файла по умолчанию — `PanelDataExporter.FileName`,
  `XlsxExporter.FileName`, текст ячейки в таблицах и свойствах —
  `ReportCell.Display`. Листы всей книги — разделы `PanelView.Book` в порядке
  `PanelDataBook` (в дереве алармы идут иначе); имена листов разделов —
  константы `Name` классов `*Sheet` ядра. Тест `WindowWorkbookTests` проверяет
  то, что окно берёт из ядра: книга из листов `PanelDataBook.TryBuild`, записанная
  `ReportSheetsExporter`, равна книге консоли (окно пишет те же объекты
  `ReportSheet`), а сбой одного листа не мешает остальным. Узлы дерева и выбор
  разделов в `PanelViews` тестами не покрыты.
- Строка состояния — одна строка: путь и красная ошибка действия сжимаются с
  многоточием (`status-long`), полный текст — в `title`; короткие части не
  сжимаются. Ошибка действия (`_notice`: сбой сохранения, Ctrl+C) не гаснет по
  таймеру — сбрасывается выбором узла или строки, новым открытием, удачным
  сохранением. Всплывающие уведомления Radzen переносят длинный текст по любому
  символу (`shell.css`). Текст исключений .NET не переводится (решение
  пользователя); свои сообщения — по-русски.
- Регистрация служб BlazorWebView, Radzen и `PictureSelection` в `MainWindow` —
  единственное исключение из правила «без DI».
- Панель свойств по умолчанию — 360 px высотой (`Viewer`, размер панели редактора
  `calc(100% - 360px)`): группа General картинки (7 полей) помещается целиком, с
  нижней рамкой.

## Проверка окна

- Запущенное окно держит `FlexRt.Core.dll` в своём `bin`: сборка решения падает
  с MSB3027. Своё окно закрой, запущенное пользователем — только с его согласия.
- Поведение окна автоматически не проверяется. Меняется то, чем оно пользуется
  (`FwxReader`, построители таблиц листов, модели экранов, `RunTranscript`,
  `PlcDataReader`), — открой в окне шаговую копию экранов
  (`samples/screens/05_popup.fwc`); данные ПЛК — `samples/plc/pdata-one-connection.fwc`
  с `samples/plc/PEData.plf`.
- Картинки: PNG и JPEG вместе — `samples/a603/pdata.fwc` (76 картинок, 4 JPEG).
- Диалог папки карты (`OpenFolderDialog`) заполняется так же, но поле имени —
  `Edit` с AutomationId `1152`, а не `1148`.
- Диалог «Сохранить как»: имя, вписанное `WM_SETTEXT` в `Edit` `1001`, диалог
  не берёт — `BM_CLICK` по «Сохранить» пишет имя по умолчанию в папку прошлого
  сохранения (или `pdata.fwc`); файл после проверки перенеси оттуда. Диалог —
  окно верхнего уровня процесса: ищи его среди детей корня UIA, поиск по всем
  потомкам рабочего стола слишком долгий (UIA может не видеть его вовсе — тогда
  Win32 `EnumWindows` по pid и классу `#32770`). Файл уже есть — второй `#32770`
  «Заменить?»: `BM_CLICK` по «Да» не срабатывает, нужен `WM_COMMAND` `IDYES` (6)
  самому диалогу; пока он открыт, вызовы CDP ждут. Ошибку записи проверяй
  блокировкой файла (`FileShare.None`). Сохранение проверяй сверкой листов с
  книгами консоли (с теми же данными ПЛК): отличаться должна только «Сводка».
- Проверять окно: запуск exe с `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`,
  DOM и клики — через CDP. Клавиатуру эмулировать только если на переднем плане
  именно диалог открытия файла (иначе ввод уходит в другое окно). Без эмуляции
  клавиатуры диалог заполняется сообщениями `WM_SETTEXT` полю имени и
  `BM_CLICK` кнопке «Открыть» по их дескрипторам.
- Radzen: панель разделителя, которая стоит не последней, не сжимается
  (`flex-shrink: 0`) — задавай размер ей; цвета компонентов меняй переменными
  `--rz-*`, а не перебиванием свойств: правила Radzen для наведения сильнее.
- Radzen DataGrid: у каждого раздела свой экземпляр таблицы (`@key` по разделу),
  иначе фильтр колонки переносится на колонку другого типа и окно падает;
  числовые колонки хранят `long?`, текстовые — строку.
