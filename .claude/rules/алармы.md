# Системные события, алармы, классы и группы алармов

Установленное поведение и известные ограничения области (см. «Правила по областям» в
`CLAUDE.md`): не меняй без решения пользователя. Меняется код — меняются XML-документация и этот файл.

## Установленное поведение

- `SYSMSGHANDLER` (системные события): в файлах один элемент, читаются все
  элементы подряд в один список; в элементе на +0x2a u16 — число
  событий N, с +0x2c — N пар u32 (ID события, номер строки текста в
  `STRINGSTORE`, один для всех языков). Поля до +0x2a и байты после пар не
  читаются (в A603A0097 после пар 40 байт неизвестной структуры). Элемент
  короче 0x2c или пары не помещаются в элемент — `FwxFormatException`:
  предупреждение, событий нет. Лист «Системные события» в
  `panel_data.xlsx` — после «Теги»: заголовок `ID` и по колонке на язык в порядке
  `STRINGSTORE` (`0x409 — English (United States)`), строки по возрастанию ID;
  нет строки текста — ячейка пустая; событий нет — листа нет. Строка
  `Системных событий: N` в тексте запуска после `Тегов:` и на «Сводке».
- Дискретные алармы (сверено с TIA на A603A0097 по шаговым копиям):
  - `MSG_NUMEVENT` — элемент на аларм: u32 0, u32 R (ссылок, по две на поле), R
    ссылок по 8 байт, u32 строка текста, u32 вторая строка (имя соединения, не
    выводится), u16 ID, u8 класс (5 бит — номер класса в `MSG_NUMHANDLER`, 3 бита —
    число полей), u8 флаги (`0x40` — Report On, биты 1…5 — ID группы), u16 код на поле, нули до
    кратности 4; длина не сходится, R нечётно или > 0x20, число полей ≠ R/2 —
    `FwxFormatException`: предупреждение, алармы до сбоя остаются. Поле:
    первая ссылка — элемент `DATALINK`; код `0x8000` — текстовый список, иначе
    тег с длиной в младшем байте; метка в тексте — ESC `T` номер `0xFF`;
  - `MSG_NUMHANDLER` — на +0x2c u16 N алармов, два u16[N], u16 K классов и K
    записей по 0x24: +0x00 строка Display name, +0x20 ID класса; длина не
    сходится — `FwxFormatException`, класс у алармов `?`;
  - `AREAPTR` — элемент на тег: имя, вид u32 (1: назначение на +0x08 —
    `0x4e` срабатывание, `0x4f` квитирование PLC, число пар на +0x10, пары с
    +0x18; 2: квитирование HMI, `0x4f` на +0x10, число пар на +0x18, пары с
    +0x20), пары u16 ID аларма и u16 бит; незнакомый — пропуск, одно
    предупреждение на таблицу. Тег — запись `VAR` со ссылкой на элемент;
    ссылки нет — имя `?`, адрес «неизвестно». Таблица прочитана не целиком
    (пропуск или обрыв) — у аларма без найденного тега `? | ? | неизвестно`, а не
    `<No tag>`;
  - лист «Дискретные алармы» после «Системные события», нет алармов — листа нет:
    `ID`, текст на каждом языке (поля — `<Tag : длина, имя HMI-тега>`, тег — по
    совпадению связи `DATALINK` со связью тега в `DATALINK_READWR`, не найден —
    `?`; `<Text list, ?>`: имени списка нет), Alarm class (ID 1, 2, 3, 4, 33, 34 —
    Errors, Warnings, System, Diagnosis events, Acknowledgement, No
    Acknowledgement; свой — Display name: в Excel на первом языке, в окне — на
    выбранном, решение пользователя 2026-10-21), Alarm group (ID группы
    числом, без группы — `<No alarm group>`), Trigger tag/bit/address,
    HMI acknowledgment tag/bit/address, PLC acknowledgment tag/bit (адреса в TIA
    нет), Report `On`/`Off`; тега нет — `<No tag>`, бит 0, адрес пуст; строки по
    возрастанию ID. Колонки Name нет: имени аларма нет ни в панели, ни в ПЛК;
  - адрес бита: абсолютный — слово = начало + 2·(бит/16), бит 0…7 в байте +1,
    8…15 в байте +0 (`%DB80.DBX1.0`); символьный — PLC tag + `.x<бит>`, у массива
    `[бит/16].x<бит%16>`; нет данных ПЛК — «неизвестно», нет тега в ПЛК —
    «отсутствует в файле ПЛК», внутренний тег — номер бита, как в TIA (сверено на
    Project1: срабатывание бит 0 → `0`, бит 5 → `5`, квитирование HMI бит 4 →
    `4`; квитирование PLC внутренним тегом TIA не даёт); таймер, счётчик или
    неразобранная связь — «неизвестно»;
  - строка `Дискретных алармов: N` в тексте запуска после `Системных событий:` и на «Сводке».
- Аналоговые алармы (сверено с TIA на шаговых копиях A603A0097, 4 аларма, и
  Project1, 7 алармов):
  - `MSG_ANALOGCREAT` — элемент на аларм, раскладка как у `MSG_NUMEVENT` (ID,
    текст, класс, группа, Report, поля); номер класса — в списке классов
    `MSG_ANALOGHANDL`; таблицы нет, пока в панели нет аналоговых алармов;
  - `MSG_ANALOGHANDL` — раскладка как у `MSG_NUMHANDLER` (N на +0x2c, два u16[N],
    K классов по 0x24); есть во всех панелях; длина не сходится — класс `?`;
  - `MSG_ANALOG_OBSE` — элемент на аларм: u32 (всегда 1), u32 R, R ссылок по 8
    байт в любом порядке (ссылка на `VAR` — тег предела), u16 ID, u8 Limit mode
    (1 Higher, 0 Lower), u8 вид значения, u32 значение (у вида 3 — 8 байт float64);
    длина не 8 + 8·R + 8 (+4 у вида 3) или R > 0x20 — `FwxFormatException`: предупреждение, пределы до сбоя
    остаются, у остальных алармов Trigger tag, Limit, Limit mode — `?`;
  - тег срабатывания — HMI-тег, запись `VAR` которого ссылается на элемент
    `MSG_ANALOG_OBSE` (`(0x108, n, 0, 0x8019)`); нет — `?`;
  - Limit: тег предела — имя HMI-тега; константа по байту вида: 1 — целое со
    знаком (сверено: `-7`, DInt `1000`), 0 — без знака (гипотеза) — числом; 2 —
    float32, 3 — float64 (сверено: LReal `1.5`) — текстом в инвариантной культуре
    (`12.5`, `13`, `1.5`); другой — `?`;
  - лист «Аналоговые алармы» после «Дискретные алармы», нет алармов — листа нет:
    `ID`, текст на каждом языке (поля — как у дискретных), Alarm class (как у
    дискретных), Alarm group (как у дискретных), Trigger tag, Limit, Limit mode,
    Report; строки по возрастанию ID.
    Колонки Name нет. Данные ПЛК не используются;
  - строка `Аналоговых алармов: N` в тексте запуска после `Дискретных алармов:` и на «Сводке».
- Классы алармов (сверено с TIA на шаговых копиях A603A0097 и Project1, V21):
  - классы — записи `MSG_NUMHANDLER`, а если их нет — `MSG_ANALOGHANDL` (в
    известных файлах одинаковы); запись 0x24: +0x00 строка Display name, +0x04,
    +0x08, +0x0c строки Incoming, Outgoing, Acknowledged, +0x10…+0x1c четыре u32
    цвета (байты R, G, B, признак) в порядке колонок листа, +0x20 u8 ID, +0x21
    u16 State machine, +0x23 0. Классов System и Diagnosis events в этих
    таблицах нет, на листе их нет;
  - Log: `RECMSG` (Id 0x43) — u32 1, u32 R, R ссылок по 8 байт (одна, на
    `MSG_HNDQUEUE` 0x1a), u16 2 (не разобрано), u16 K, K u16 ID классов журнала,
    нули до кратности 4 (Log у Warnings добавил ID 2); `ARCHIVES` (Id 0x44) —
    элемент на журнал: u16 3, u16 длина имени в символах, имя UTF-16LE, нули до
    кратности 4, u32 R, R ссылок по 8 байт (u16 таблица, u16 элемент, два слова;
    журналы данных — на `RECVAR` 0x42, журнал алармов — на элемент `RECMSG`),
    остальное не читается, R не ограничено. Log класса — имя журнала со ссылкой
    на элемент `RECMSG`, где есть ID класса;
  - E-mail address: `MSG_LOGGER` (Id 0x25, пустой список есть во всех панелях) —
    u32 1, u32 R, ссылки, u16 1, u16 K, K записей по 6 байт: u16 ID класса, u16
    Id таблицы (`FUNC_SEND_EMAIL` 0x107), u16 номер элемента, нули до кратности 4;
    `FUNC_SEND_EMAIL` — на +0x50 u32 длина в байтах и адрес
    UTF-16LE (наблюдение на 4 элементах, адреса до 21 символа); `SEND_EMAIL` (0x106)
    не читается. Начало элемента `RECMSG` и `MSG_LOGGER` разбирает общий код.
    Несколько журналов или адресов у класса — берётся первый (не встречалось);
  - сбой разбора `RECMSG`, `ARCHIVES`, `MSG_LOGGER` или `FUNC_SEND_EMAIL`
    (длина не сходится, R > 0x20 в `RECMSG`/`MSG_LOGGER`, первое слово `ARCHIVES`
    не 3, адрес не помещается) — `FwxFormatException`: предупреждение,
    лист всё равно пишется; если `RECMSG` или `ARCHIVES` прочитана не целиком,
    Log класса без найденного журнала — `?`, если `MSG_LOGGER` или
    `FUNC_SEND_EMAIL` — E-mail address без найденного адреса `?`;
  - лист «Классы алармов» после «Аналоговые алармы», нет классов — листа нет:
    `ID`, `Display name <язык>` на каждом языке
    (`Display name 0x409 — English (United States)`), Name (Errors, Warnings,
    Acknowledgement, No Acknowledgement по ID; свой — `?`: Name в панели не
    хранится, а вывод его из непереведённого Display name пользователь
    отклонил), State machine (`0c 03` — `Alarm with single-mode
    acknowledgment`, `04 01` — `Alarm without acknowledgment`, иначе `?`; других
    в TIA нет), Log (нет — `<No log>`), E-mail address (нет — пусто),
    `Background color "Incoming"`, `Background color "Incoming/Outgoing"`,
    `Background color "Incoming/Acknowledged"`,
    `Background color "Incoming/Outgoing/Acknowledged"` — `R, G, B` с заливкой
    ячейки этим цветом, текст белый при яркости 0.299R + 0.587G + 0.114B < 64;
    признак `0x20` — «цвета классов выключены» без заливки (флажок цветов
    классов в Runtime settings выключен, цвета в файле нет — установлено на
    Project1, V21), другой признак — `?`; затем `Incoming <язык>`,
    `Outgoing <язык>`, `Acknowledged <язык>`. Строки по возрастанию ID. Колонка
    Alarm class листов алармов не меняется (свой класс — Display name на первом
    языке в Excel, на выбранном — в окне);
  - строка `Классов алармов: N` в тексте запуска после `Аналоговых алармов:` и на «Сводке».
- Группы алармов (сверено с TIA на шаговых копиях Project1, V21):
  - группа аларма — в байте флагов элемента `MSG_NUMEVENT` и `MSG_ANALOGCREAT`:
    ID группы `<< 1` (биты 1…5; группы 1, 2, 17, 31 — `02`, `04`, `22`, `3e`; 0 —
    без группы), Report — бит `0x40` того же байта (группа 1 с Report — `42`);
    биты 0 и 7 не встречались и не читаются. Имени группы и списка групп в
    `pdata.fwc` нет; группа, не назначенная ни одному аларму, в файл не попадает;
  - лист «Группы алармов» после «Классы алармов»: `ID`, `Discrete alarms`,
    `Analog alarms` — группы, назначенные хотя бы одному аларму, по возрастанию ID,
    и число алармов каждого вида; групп нет — листа нет. Колонки Name нет;
  - строка `Групп алармов: N` (число групп на листе) в тексте запуска после
    `Классов алармов:` и на «Сводке».
- Колонки текстов на языках у листов «Системные события», «Дискретные
  алармы», «Аналоговые алармы» и «Классы алармов» помечены языком
  (`ReportTable.ColumnLanguages`: LCID колонки, у остальных `null`; таблица
  строится `ReportTable.WithLanguages` из `ReportColumn`, колонки текстов —
  `AlarmLanguageTexts.Columns(префикс)` / `LanguageText.Columns`; строки языков
  у алармов, системных событий и подсказок экранов — общий `Export/LanguageStrings`
  (`LanguageStrings.Of(doc)` — один на документ, запоминается),
  цвета `R, G, B` с заливкой — `Export/RgbText`). Ячейка Alarm
  class своего класса несёт Display name на каждом языке
  (`ReportCell.LanguageTexts`, `AlarmLanguageTexts.LanguageCell`), её текст —
  первый язык. В Excel пометка и тексты на языках не
  пишется; по ней окно показывает колонки выбранного языка (`окно.md`).

## Известные ограничения

- Системные события: с TIA сверены Project1 (English) и A603A0097 (English,
  русский, polski) — 585 событий, все тексты совпали. Русские тексты CCB-A13 с
  TIA не сверены (совпали с A603A0097).
  Хвост `SYSMSGHANDLER` в A603A0097 и поля до +0x2a не разобраны. Других
  свойств событий нет.
- Дискретные алармы: с TIA сверен только A603A0097 (V21, 355 алармов); CCB-A13
  (2000) — нет проекта. Имени аларма, имени текстового списка и имени своего
  класса нет ни в панели, ни в ПЛК (выгрузка с ПЛК и карта проверены); они есть
  только в `PEData.plf` исходного проекта с панелью (`docs/формат-plf/алармы-hmi.md`,
  программа не читает). Абсолютный тег M сверен на Project1 (`%MW10` бит 9 →
  `%M10.1`). Не проверены: абсолютные теги I/Q, символьный массив с
  нижней границей не 0, длина поля тега (сверена на одном поле).
- Аналоговые алармы: сверена одна шаговая копия A603A0097 (4 аларма), реального
  бэкапа с ними нет (в CCB-A13 их нет). Виды предела 1, 2, 3 сверены на Project1
  (Int, DInt, Real, LReal); вид 0 (без знака) — гипотеза, другие типы не проверены.
  `MSG_ANALOG_OBSE` +0x00 и слова ссылки на
  `MSG_ANALOGHANDL` не разобраны.
- Классы алармов: сверены шаговые копии A603A0097 и Project1 (V21), реального
  бэкапа с журналом алармов или адресом письма нет. Два журнала алармов и два
  адреса у разных классов сверены на Project1; положение адреса в
  `FUNC_SEND_EMAIL` (+0x50) — наблюдение на 4 элементах (до 21 символа);
  `SEND_EMAIL`, u16 перед K в `RECMSG`/`MSG_LOGGER` и байты `ARCHIVES` после
  ссылок не разобраны. Name своего класса в панели нет. Классы System и Diagnosis events
  не выводятся: в списках классов их нет; +0x20 заголовка `SYSMSGHANDLER` похоже
  на цвет — наблюдение, не разобрано. Common alarm class и Flashing не искались.
- Группы алармов: сверены только шаговые копии Project1 (V21, TP700 Comfort); в
  реальных бэкапах (A603A0097, CCB-A13) группы алармам не назначены. Имя группы
  (`Alarm_group_1`) есть только в `PEData.plf` исходного проекта — его не читаем
  (решение пользователя: в выгрузке ПЛК и на карте данных панели нет). V17 не
  проверялся.
