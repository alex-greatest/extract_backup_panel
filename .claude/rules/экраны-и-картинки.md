# Экраны и картинки

Установленное поведение и известные ограничения области (см. «Правила по областям» в
`CLAUDE.md`): не меняй без решения пользователя. Меняется код — меняются XML-документация и этот файл.

## Установленное поведение

- Экраны (сверено с TIA на шаговых копиях Project1, V21, `data/real/steps-screens/`):
  - `SCREEN` (Id 0x7) — элемент на запись: u16 вид (3 — экран, 1 — служебная
    запись pop-up без имени), u16 длина имени, имя UTF-16LE, нули до кратности 4,
    u32 R (≤ 0x20), R ссылок по 8 байт (u16 Id таблицы, u16 номер элемента —
    `Screen.References`; два слова не читаются), 8 байт, u16 ширина, u16
    высота, 6 байт, u16 N, N пар (u16 номер элемента, u16 Id таблицы) — объекты;
    хвост, последние 20 байт — `FFFFFFFF | xxxxxxxx | RR GG BB 00 | 00100000 |
    00000000` (наблюдение на 15 файлах, V17 и V21); на длине записи − 12 — цвет
    фона R, G, B (`Screen.BackgroundRgb`; сверено с TIA: шаг
    `data/real/steps-screen-props/02_bg_color.fwc`, 49 экранов A603A0097 с BackColor
    из XML TIA), 4-й байт и остальной хвост не читаются; после пар меньше 12 байт —
    цвета нет (`null`), запись остаётся, после таблицы одно сводное предупреждение
    `SCREEN: цвет фона не прочитан у записей: N (после объектов меньше 12 байт),
    первая — запись k @ 0x…` (решение пользователя: записи не теряются); оно
    пишется и тогда, когда разбор оборвала следующая запись, — перед её
    предупреждением. Порядок записей компилятор меняет. Объекты шаблона
    вливаются в экран, имени и ссылки на шаблон нет; окна Global screen — в
    `SCREEN_SYS` (не читается);
  - `ADAPTVALUECHANG` (Id 0x5f) — элемент со ссылкой на `GUI` (Id из TOC): u32 1,
    u32 R, R ссылок, u16 (0x12), u16 K, u32 (2), K пар (u16 номер экрана, u16 номер
    записи `SCREEN` с нуля); у остальных элементов читается только начало со
    ссылками; нет таблицы или `GUI` — номеров нет, без сообщения;
  - `GUI` (Id 0x16), первый элемент: u32 1, u32 R, R ссылок, на +0x14 от конца
    ссылок (+0x34 при R = 3) u16 — номер стартового экрана; нет таблицы —
    стартовый экран «неизвестно», без сообщения;
  - `VIEW_DYN` (Id 0x5), элемент, на который ссылается пара объектов записи
    `Overview` (SCREEN, запись 0) с Id `VIEW_DYN` (в файлах элемент один, 36 байт;
    пары нет или она ведёт за последний элемент — `FwxFormatException` со смещением
    таблицы, высоты нет; записи `Overview` в документе нет — SCREEN нет или её разбор
    оборвался раньше — высоты нет, без второго предупреждения; решения пользователя): u32 1, u32 R,
    R ссылок (во всех файлах одна — `ADAPTVALUECHANG` 0), на +0x06 от конца
    ссылок (+0x16 при R = 1) u16 — высота Permanent area
    (`FwxDocument.PermanentAreaHeight`; сверено с TIA: шаг
    `data/real/steps-screen-props/15_overview_height.fwc`, 60 → 80; у A603A0097 и
    CCB-A13 — 0); нет таблицы — высоты нет (`null`), без сообщения; остальные
    поля (размер панели, запись стартового экрана) не читаются
    (`docs/формат-fwx/таблица-view-dyn.md`). Высоту экранов при её смене TIA
    сам не пересчитывает (после шага 15 экраны и в TIA, и в файле — 420), но
    импорт экрана с высотой ≠ панель − Permanent area отклоняет;
  - `LIMIT` (Id 0x11) — Visibility экрана (сверено с TIA на шагах
    `data/real/steps-animations/` 01–08, Project1, V21; `LimitParser`, разбирается
    после `SCREEN`, список `FwxDocument.ScreenVisibilities`): читаются только
    элементы, на которые ссылается не служебная запись `SCREEN` (ссылка с Id
    `LIMIT` из TOC; слова ссылки — 0x10 и 0, не проверяются); в таблице есть
    элементы другой раскладки (с именем, как `VAR`; на A603A0097) — не читаются.
    Элемент: u32 1, u32 R (1…0x20), R ссылок, первая — тег (u16 Id, u16 номер
    записи `VAR` с нуля), за ссылками 8 байт (на +0x01 бит 0x08 — Visible, снят —
    Invisible; остальное не читается), From и To по 16 байт: u16 тип, 6 байт,
    8 байт значения — тип 5 f64, тип 2 i16, другой — значения нет и
    предупреждение `LIMIT: запись N @ 0x…: тип значения From 0x… не известен,
    From не прочитано`. Элемент экрана не сходится (выходит за таблицу, короче
    8 байт, первое u32 не 1, R = 0 или > 0x20, значения не помещаются) или
    ссылка ведёт за последний элемент — предупреждение с таблицей и смещением,
    у этого экрана Visibility `?`, остальные экраны читаются (решение
    пользователя 2026-10-26); элементы, на которые экраны не ссылаются, проверяет
    только `TableLayoutCheck`; каталог смещений таблицы испорчен — Visibility нет
    ни у одного экрана, предупреждение; нет таблицы — Visibility нет, без сообщения
    (`docs/формат-fwx/таблица-limit.md`);
  - вид: есть номер — `Screen`; на запись ссылается объект служебной записи (Id
    `SCREEN`) — `Pop-up screen`; имя `Slide-in screen top/left/bottom/right`
    (TIA не даёт переименовать) — `Slide-in screen`; запись 0 (`Overview`, в ней
    объекты Permanent area) — `Permanent area`; иначе `?`;
  - сбой разбора (длина, первое слово `SCREEN` не 3 и не 1, R > 0x20, имя,
    ссылки, пары, номер или высота Permanent area не помещаются) —
    `FwxFormatException`: предупреждение, записи до сбоя остаются (сбой `VIEW_DYN`
    — высоты нет); `ADAPTVALUECHANG` прочитана не целиком — у
    экрана без найденного номера Number `?` (и вид `?`, если иначе не опознан);
  - лист «Экраны» после «Группы алармов», экранов нет — листа нет: `Name`,
    `Number` (числом, нет — пусто), `Start screen` (`Yes` у экрана с номером из
    `GUI`), `Width`, `Height`, `Background color` (`182, 182, 182` — R, G, B
    десятичными, как в TIA, ячейка залита этим цветом, как цвета классов алармов —
    `RgbText`; цвет не прочитан — `?` без заливки; решение пользователя),
    `Visibility tag` (имя тега `VAR`; ссылка не на `VAR` или записи нет — `?`
    без предупреждения), `Visibility from`, `Visibility to` (целое — числом,
    дробное — текстом; не прочитано — `?`), `Visibility` (`Visible` /
    `Invisible`) — `ScreenVisibilityCells`: у экрана без ссылки на `LIMIT`
    пусто, ссылка есть, а элемент не прочитан — `?` во всех четырёх (решение
    пользователя 2026-10-26); `Tooltip <язык>` — колонка на
    каждый язык панели в порядке STRINGSTORE (`Tooltip 0x409 — English (United
    States)`, помечена языком для списка языков окна), `Вид`; служебные записи не выводятся; у Permanent
    area Name — `Permanent area`, Height — высота из `VIEW_DYN`, а не высота
    записи `Overview` (вся панель; решение пользователя), высоты нет — `?`; строки: Permanent area, экраны по возрастанию
    номера, остальные в порядке файла. Колонки шаблона нет;
  - строки `Экранов: N` (число экранов вида `Screen`) и `Стартовый экран: <имя>
    (<номер>)` (номера нет — `неизвестно`, экрана с номером нет — `неизвестно
    (<номер>)`) в тексте запуска после `Групп алармов:` и на «Сводке»;
  - подсказка экрана (Tooltip) — пара из `INFO_HANDLER` (`формат-панели.md`)
    с Id `SCREEN` и номером записи `SCREEN` с нуля, текст — строка языков с тем же
    номером на каждый язык Runtime; в интерфейсе TIA подсказка — только простой
    текст, перенос строки — CRLF (сверено с TIA на `data/real/steps-screen-props/`
    и `data/real/steps-tooltip-langs/`); подсказка, заданная через Openness, —
    с разметкой `<body><p>…</p></body>`. На лист «Экраны» (`ScreenTooltips`) и в
    свойства экрана окна текст идёт как есть, без снятия разметки (решение
    пользователя); пары нет или нет строки на языке — пустая ячейка; у записи
    несколько пар — первая; строки языков — общий `LanguageStrings.Of(doc)`.
    Колонки подсказки помечены группой `Tooltip` (`ReportTable.ColumnGroups`).
    Таблицу листа `ScreensTable.Build` строит один раз на документ и запоминает
    (`ConditionalWeakTable`): её берут и экраны окна, и лист «Экраны». Только экраны:
    подсказки объектов не выводятся. В окне подсказка — блок Tooltip справа от
    полей General (`окно.md`).
- Картинки (наблюдение на 193 картинках `samples/pdata.fwc`, A603A0097, CCB-A13):
  - `PICTURE` (Id 0x86) — элемент на картинку: u32 1, u32 0, u16 1, u16 1 (не
    читаются), на +0x0c u32 длина, с +0x10 файл PNG или JPEG целиком, нули до
    кратности 4; `TILED_PICTURE` (Id 0x15c) — длина на +0x1c, файл с +0x20 (на
    +0x10 и +0x12 u16 ширина и высота, на +0x14 четыре u16 — гипотеза: поля
    растягивания; не читаются). Формат — по сигнатуре: `89 50 4E 47 0D 0A 1A 0A` —
    `png`, `FF D8 FF` — `jpg`. Байты после картинки не проверяются (решение
    пользователя);
  - длина не помещается в элемент, равна 0, данные выходят за элемент, сигнатура
    не PNG и не JPEG — `FwxFormatException`: предупреждение, картинки
    таблицы до сбоя остаются, после — нет (незнакомый формат не пропускается —
    решение пользователя); нет таблицы — картинок из неё нет, без сообщения;
  - имя картинки (`PictureArchiveExporter.EntryName`) —
    `<таблица>_<n>.<png|jpg>`, n — номер элемента таблицы с 1 (`PICTURE_5.png`,
    `TILED_PICTURE_1.png`); сначала `PICTURE`, затем `TILED_PICTURE`; одинаковые
    картинки не объединяются. Пишет картинки только окно по кнопкам сохранения:
    одну как есть или все архивом `images.zip` (записи в корне под этими именами,
    без сжатия; `окно.md`);
  - строка `Картинок: N` (всего из обеих таблиц) в тексте запуска после `Стартовый
    экран:` и на «Сводке»;
  - ширина и высота — `PictureSize` (только для окна): PNG —
    u32 big-endian на 0x10 и 0x14 (`IHDR`), JPEG — u16 big-endian высота и ширина
    первого `SOFn` (0xC0–0xCF кроме 0xC4, 0xC8, 0xCC), сегменты пропускаются по длине,
    байты заполнения 0xFF и маркеры без длины (0x01, 0xD0–0xD7) — тоже; SOS раньше SOF
    или файл кончился — размера нет, без исключения. На 88 картинках `samples/pdata.fwc`
    и `samples/a603` размер прочитан у всех; у 7 (PNG и JPEG) сверен с раскодированным
    браузером окна.

## Известные ограничения

- Экраны: шаги только на Project1 (V21, TP700 Comfort); у A603A0097 (V21, TP1900)
  номера и размеры всех 49 экранов сверены с TIA (выгрузка экранов в XML через
  Openness, 2026-10-21; расхождения с числом в имени — `022_ResultsCharts` 23,
  `415_I_S06` 108 — настоящие номера в TIA); CCB-A13 с TIA не сверялся (номер
  совпал с числом в начале имени у 6 из 9 экранов). V17 с несколькими
  экранами с TIA не сверялся (CCB-A13 — Runtime V17, 10 экранов, проекта нет). Шаблон экрана не определяется: имени нет ни в панели,
  ни в выгрузке ПЛК (`Project1_upload`), ни на картах ПЛК — только в `PEData.plf`
  исходного проекта. Индикатор алармов Global screen в записи `Overview` —
  гипотеза; `SCREEN_SYS`, ссылки записи `SCREEN` (кроме ссылки на `LIMIT`) и хвост (кроме цвета фона), поля `GUI` кроме номера
  стартового экрана, поля `VIEW_DYN` кроме высоты Permanent area и прочие
  элементы `ADAPTVALUECHANG` не разобраны. Высота Permanent area сверена с TIA
  на одном шаге одного проекта (V21, изменена через Openness, не в интерфейсе
  TIA).
- Картинки: проверены только по длине и сигнатуре на трёх файлах (V17 и V21),
  с TIA не сверялись. Какой объект экрана показывает картинку и её имя в проекте
  не определяются; поля `TILED_PICTURE` до длины не разобраны. Других форматов
  (BMP, GIF, ICO, EMF/WMF, SVG) в известных файлах нет.
