# Экраны и картинки

Установленное поведение и известные ограничения области (см. «Правила по областям» в
`CLAUDE.md`): не меняй без решения пользователя. Меняется код — меняются XML-документация и этот файл.

## Установленное поведение

- Экраны (сверено с TIA на шаговых копиях Project1, V21, `data/real/steps-screens/`):
  - `SCREEN` (Id 0x7) — элемент на запись: u16 вид (3 — экран, 1 — служебная
    запись pop-up без имени), u16 длина имени, имя UTF-16LE, нули до кратности 4,
    u32 R (≤ 0x20), R ссылок по 8 байт (u16 Id таблицы, u16 номер элемента —
    `Screen.References`; два слова не читаются), 8 байт, u16 ширина, u16
    высота, 6 байт, u16 N, N пар (u16 номер элемента, u16 Id таблицы) — объекты;
    хвост, последние 20 байт — `FFFFFFFF | xxxxxxxx | RR GG BB 00 | 00100000 |
    00000000` (наблюдение на 15 файлах, V17 и V21); на длине записи − 12 — цвет
    фона R, G, B (`Screen.BackgroundRgb`; сверено с TIA: шаг
    `data/real/steps-screen-props/02_bg_color.fwc`, 49 экранов A603A0097 с BackColor
    из XML TIA), 4-й байт и остальной хвост не читаются; после пар меньше 12 байт —
    цвета нет (`null`), запись остаётся, после таблицы одно сводное предупреждение
    `SCREEN: цвет фона не прочитан у записей: N (после объектов меньше 12 байт),
    первая — запись k @ 0x…` (решение пользователя: записи не теряются); оно
    пишется и тогда, когда разбор оборвала следующая запись, — перед её
    предупреждением. Порядок записей компилятор меняет. Объекты шаблона
    вливаются в экран, имени и ссылки на шаблон нет; окна Global screen — в
    `SCREEN_SYS` (не читается);
  - `ADAPTVALUECHANG` (Id 0x5f) — элемент со ссылкой на `GUI` (Id из TOC): u32 1,
    u32 R, R ссылок, u16 (0x12), u16 K, u32 (2) — заголовок списка `ValueChangeList`,
    общий с цветами Limits I/O field; K пар (u16 номер экрана, u16 номер записи
    `SCREEN` с нуля); у остальных элементов читается только начало со
    ссылками; нет таблицы или `GUI` — номеров нет, без сообщения;
  - `GUI` (Id 0x16), первый элемент: u32 1, u32 R, R ссылок, на +0x14 от конца
    ссылок (+0x34 при R = 3) u16 — номер стартового экрана; нет таблицы —
    стартовый экран «неизвестно», без сообщения;
  - `VIEW_DYN` (Id 0x5), элемент, на который ссылается пара объектов записи
    `Overview` (SCREEN, запись 0) с Id `VIEW_DYN` (в файлах элемент один, 36 байт;
    пары нет или она ведёт за последний элемент — `FwxFormatException` со смещением
    таблицы, высоты нет; записи `Overview` в документе нет — SCREEN нет или её разбор
    оборвался раньше — высоты нет, без второго предупреждения; решения пользователя): u32 1, u32 R,
    R ссылок (во всех файлах одна — `ADAPTVALUECHANG` 0), на +0x06 от конца
    ссылок (+0x16 при R = 1) u16 — высота Permanent area
    (`FwxDocument.PermanentAreaHeight`; сверено с TIA: шаг
    `data/real/steps-screen-props/15_overview_height.fwc`, 60 → 80; у A603A0097 и
    CCB-A13 — 0); читается только этот элемент (`FwxReader.CheckedItem`), записи
    каталога и границы других элементов проверяет только `TableLayoutCheck`;
    нет таблицы — высоты нет (`null`), без сообщения; остальные
    поля (размер панели, запись стартового экрана) не читаются
    (`docs/формат-fwx/таблица-view-dyn.md`). Высоту экранов при её смене TIA
    сам не пересчитывает (после шага 15 экраны и в TIA, и в файле — 420), но
    импорт экрана с высотой ≠ панель − Permanent area отклоняет;
  - `LIMIT` (Id 0x11) — Visibility экрана (сверено с TIA на шагах
    `data/real/steps-animations/` 01–08, Project1, V21; `LimitParser`, разбирается
    после `SCREEN`, список `FwxDocument.ScreenVisibilities`): читаются только
    элементы, на которые ссылается не служебная запись `SCREEN` (ссылка с Id
    `LIMIT` из TOC; слова ссылки — 0x10 и 0, не проверяются); в таблице есть
    элементы другой раскладки (с именем, как `VAR`; на A603A0097) — не читаются.
    Элемент: u32 1, u32 R (1…0x20), R ссылок, первая — тег (u16 Id, u16 номер
    записи `VAR` с нуля), за ссылками 8 байт (на +0x01 бит 0x08 — Visible, снят —
    Invisible; остальное не читается), From и To по 16 байт: u16 тип, 6 байт,
    8 байт значения — тип 5 f64, тип 2 i16, другой — значения нет и
    предупреждение `LIMIT: запись N @ 0x…: тип значения From 0x… не известен,
    From не прочитано`. Элемент экрана не сходится (выходит за таблицу, короче
    8 байт, первое u32 не 1, R = 0 или > 0x20, значения не помещаются), его
    запись каталога смещений выходит за файл или даёт отрицательную длину или
    ссылка ведёт за последний элемент — предупреждение с таблицей и смещением,
    у этого экрана Visibility `?`, остальные экраны читаются (решение
    пользователя 2026-10-26; элемент читается по номеру, `FwxReader.CheckedItem`,
    без обхода каталога); элементы, на которые экраны не ссылаются, и их записи
    каталога проверяет только `TableLayoutCheck`; несколько экранов на одном
    испорченном элементе — одинаковое предупреждение на каждый экран; нет
    таблицы — Visibility нет, без сообщения
    (`docs/формат-fwx/таблица-limit.md`);
  - события экрана Loaded и Cleared (сверено с TIA на шагах
    `data/real/steps-events/` 09–24, Project1, V21, TP700 Comfort, 148 функций против
    карты TIA `*.json`; 13 событий A603A0097 — через Openness; `ScreenEventParser`, разбирается после `SCREEN`, список
    `FwxDocument.ScreenEvents`; решения пользователя 2026-10-29): первая ссылка
    не служебной записи `SCREEN` на `FUNC_LIST` — Loaded, на `ADAPTDEMULTIPLE` —
    Cleared (`FunctionListReader`). `FUNC_LIST`: u32 1, u32 R, R ссылок (не
    читаются), u16 N, N пар (u16 Id таблицы, u16 номер элемента).
    `ADAPTDEMULTIPLE`: u32 (0, не проверяется), u32 R = 1, ссылка на `FUNC_LIST`
    или одну функцию `FUNC_*` (все 26 ссылок экранов в 84 копиях; элементы со
    ссылкой на `VARSYS` — условия Loaded, экраны на них не ссылаются), u32. Функция `FUNC_*` (`FunctionReader`): u32 1, u32 R, R
    ссылок, u32 подкод, u32 виды параметров по 2 бита от старших (01 ссылка, 10
    VARIANT, 00 конец), блоки VARIANT по 16 байт, строки за ними; ссылки на
    `TIMER` — не параметры. Ссылка-параметр (`FunctionReferences`): `VAR` —
    тег (сверено: внутренние, теги ПЛК с символьным доступом и абсолютным адресом,
    член DB — копия 24); `ADAPTLOOPBREAKE` и элемент `LIMIT` с именем (первое
    слово 3; сверено с TIA на A603A0097) — по первой ссылке до `VAR` (не дальше трёх
    посредников); другая таблица — `RECVAR 4` (имя таблицы и номер элемента с
    единицы); таблицы нет в TOC — `?`. VARIANT (`FunctionValueReader`): тип 3
    слово 0 — i32, слово 2 — объект (u16 элемент, u16 Id таблицы; имя —
    `NamedElement`: u16, u16 длина, UTF-16LE; пустое — `VIEW_OCX 10`), 5 — f64, 8 —
    строка (смещение текста от начала блока, перед текстом u32 длина в байтах),
    0x12 — объект проекта (u32 номер, u32 вид), 0x13 — u32; другой тип — `?` и
    предупреждение `FUNC_X: запись N @ 0x…: тип параметра k 0x… (слово 0x…) не
    известен, параметр не прочитан`. Имена функций и параметров — словарь
    `SystemFunctionCatalog` (ресурс `Parsing/Panel/Functions/SystemFunctions.json`,
    ключ — имя таблицы TOC и подкод; 134 записи; ошибка словаря — исключение
    при первом обращении, ловит тест). Неразличимые пары — два имени (HTMLBrowser
    и ScreenObject на 0x1002, 0x1003, 0x50c, 0x50d); RecipeView и
    SystemDiagnosticView на 0x1–0x4 — RecipeView, если элемент объекта ссылается на
    `RECIPE_FACTORY` (наблюдение на 3 объектах), иначе оба. Сбой списка
    (ссылка за последний элемент — в сообщении имя экрана, элемент вне таблицы,
    первое слово не 1, R, пары или ссылки не помещаются, Id таблицы нет в TOC,
    ссылка `ADAPTDEMULTIPLE` ведёт не на `FUNC_LIST` и не на `FUNC_*`) —
    предупреждение с таблицей и смещением, событие «не прочитано» (`Functions` — `null`); сбой одной функции —
    предупреждение, функция «не прочитано» (`Arguments` — `null`), остальные
    функции события читаются; нет таблиц — событий нет, без сообщения. Тексты
    вкладки Events окна — `Export/ScreenEvents/ScreenEventTexts` (всегда Loaded и
    Cleared; тег по имени `VAR`, не найден — `?`; f64 целое — без дробной части;
    объект проекта — `журнал #2`, `отчёт #0`, `текстовый список #31`, другой вид —
    `объект 0x0 #2`; пары — через « / »; не опознана — `FUNC_X (подкод 0x3)`,
    параметры без имени — `Параметр k`). В Excel, «Сводку» и текст чтения события
    не идут (решение пользователя);
  - вид: есть номер — `Screen`; на запись ссылается объект служебной записи (Id
    `SCREEN`) — `Pop-up screen`; имя `Slide-in screen top/left/bottom/right`
    (TIA не даёт переименовать) — `Slide-in screen`; запись 0 (`Overview`, в ней
    объекты Permanent area) — `Permanent area`; иначе `?`;
  - сбой разбора (длина, первое слово `SCREEN` не 3 и не 1, R > 0x20, имя,
    ссылки, пары, номер или высота Permanent area не помещаются) —
    `FwxFormatException`: предупреждение, записи до сбоя остаются (сбой `VIEW_DYN`
    — высоты нет); `ADAPTVALUECHANG` прочитана не целиком — у
    экрана без найденного номера Number `?` (и вид `?`, если иначе не опознан);
  - лист «Экраны» после «Группы алармов», экранов нет — листа нет: `Name`,
    `Number` (числом, нет — пусто), `Start screen` (`Yes` у экрана с номером из
    `GUI`), `Width`, `Height`, `Background color` (`182, 182, 182` — R, G, B
    десятичными, как в TIA, ячейка залита этим цветом, как цвета классов алармов —
    `RgbText`; цвет не прочитан — `?` без заливки; решение пользователя),
    `Visibility tag` (имя тега `VAR`; ссылка не на `VAR` или записи нет — `?`
    без предупреждения), `Visibility from`, `Visibility to` (целое — числом,
    дробное — текстом; не прочитано — `?`), `Visibility` (`Visible` /
    `Invisible`) — `ScreenVisibilityCells`: у экрана без ссылки на `LIMIT`
    пусто, ссылка есть, а элемент не прочитан — `?` во всех четырёх (решение
    пользователя 2026-10-26); `Tooltip <язык>` — колонка на
    каждый язык панели в порядке STRINGSTORE (`Tooltip 0x409 — English (United
    States)`, помечена языком для списка языков окна), `Вид`; служебные записи не выводятся; у Permanent
    area Name — `Permanent area`, Height — высота из `VIEW_DYN`, а не высота
    записи `Overview` (вся панель; решение пользователя), высоты нет — `?`; строки: Permanent area, экраны по возрастанию
    номера, остальные в порядке файла. Колонки шаблона нет;
  - строки `Экранов: N` (число экранов вида `Screen`) и `Стартовый экран: <имя>
    (<номер>)` (номера нет — `неизвестно`, экрана с номером нет — `неизвестно
    (<номер>)`) в тексте запуска после `Групп алармов:` и на «Сводке»;
  - подсказка экрана (Tooltip) — пара из `INFO_HANDLER` (`формат-панели.md`)
    с Id `SCREEN` и номером записи `SCREEN` с нуля, текст — строка языков с тем же
    номером на каждый язык Runtime; в интерфейсе TIA подсказка — только простой
    текст, перенос строки — CRLF (сверено с TIA на `data/real/steps-screen-props/`
    и `data/real/steps-tooltip-langs/`); подсказка, заданная через Openness, —
    с разметкой `<body><p>…</p></body>`. На лист «Экраны» (`ScreenTooltips`) и в
    свойства экрана окна текст идёт как есть, без снятия разметки (решение
    пользователя); пары нет или нет строки на языке — пустая ячейка; у записи
    несколько пар — первая; строки языков — общий `LanguageStrings.Of(doc)`.
    Колонки подсказки помечены группой `Tooltip` (`ReportTable.ColumnGroups`).
    Таблицу листа `ScreensTable.Build` строит один раз на документ и запоминает
    (`ConditionalWeakTable`): её берут и экраны окна, и лист «Экраны». На лист идут только
    экраны; подсказка I/O field — только в окне (ниже). В окне подсказка экрана — блок
    Tooltip справа от полей General (`окно.md`).
- Объекты экранов (`ScreenObjectParser`, разбирается после `SCREEN`, список
  `FwxDocument.ScreenObjects`; решения пользователя 2026-11-02;
  `docs/формат-fwx/объекты-экрана.md`): по каждой не служебной записи `SCREEN` —
  пары её списка объектов; `VIEW_DARK` (u32, u32 R, R ссылок, пара) — объект в
  ней; `VIEW_MOVE` (u32, u32 R, R ссылок, u16, u16 N, N пар) — вложенные объекты
  (вложенность до 8); `VIEW_DYN` — не объект. Рамка (`ObjectBoundsReader`): вид
  3 и 1 — за ссылками (у `VIEW_OCX` ещё 4 байта) u32 стиль, i16 Left, Top, Right,
  Bottom; вид 0x0b (контрол) — с +0x1a от конца ссылок, если на +0x18 байт 0x50 и
  на +0x19 флаги сжатия 0; в `VIEW_MOVE` ровно из двух объектов — контрола и
  объекта без имени с рамкой — рамка контрола (объект без имени не выводится); другой вид — рамки нет.
  Сверено с TIA: 413 объектов A603A0097 (Openness), 3 Trend view и 2 f(x) trend
  view (Layout); окна алармов, рецептов, диагностики, Status/Force — тем же
  правилом, с TIA не сверены. Рамка не прочитана — объекта нет; вышла за экран
  (отрицательные или за ширину и высоту записи) — объект есть; в обоих случаях и
  при сбое элемента (таблицы нет в TOC, номер за последним элементом, обёртка не
  помещается) — предупреждение с таблицей и смещением (`VIEW_BUTTONS @ 0x…: запись
  1: объект Exit экрана Root screen: положение не прочитано` / `рамка 720, 360,
  180×58 выходит за экран 800×420`): элемент из списка экрана читается один раз
  (у объекта шаблона сообщения — с первым экраном), «положение не прочитано» и
  сбой — одно на элемент, рамка за экраном — одно на элемент и размер экрана;
  остальные объекты читаются. Объекты шаблона входят в каждый экран и от своих не отличаются, тип
  объекта читается только у I/O field (ниже). Выводятся только на холст окна (`окно.md`), не в Excel и
  не в текст чтения.
- I/O field (`IoFieldParser`, разбирается после `ScreenObjectParser`, список
  `FwxDocument.IoFields`, по элементу один раз; решения пользователя 2026-11-02/03;
  `docs/формат-fwx/поле-ввода-вывода.md`, `стили-объектов.md`; сверено с TIA:
  шаговые копии `data/real/steps-iofield/` 00–45, 47, 48, 50, 53, 55, 60–62, 66–67
  Project1 и все 105 полей A603A0097 через Openness): элемент `VIEW_IN` с кодом `0x5DC000` или `VIEW_OUT` с кодом
  `0x5CC000` (u32 на +0x10 от конца ссылок; другой код — не поле, без сообщения).
  Режим — таблица и у `VIEW_IN` u16 на +0x2c (`0xFFFF` Input/output, 0 Input);
  Display format — u32 +0x20 (0 String … 6 Date/time); знаки после запятой — u16
  +0x24; поля формата с +0x2e (`VIEW_IN`) / +0x2c (`VIEW_OUT`): длина шаблона, знак,
  Leading zeros, у `VIEW_IN` Hidden input (u16 +0x0a полей формата, `0xFFFF`; у
  `VIEW_OUT` — нет), Units (u16 длина с нулём, u16, UTF-16). Ссылки поля читаются
  один раз и идут во все читатели ниже (тег, Limits, Flashing, Authorization). Тег (`IoFieldTagReader`) —
  первая ссылка на `VAR`, иначе через `ADAPTVALUECHANG` первой ссылки на `VAR` или
  `VARLIST` с именем; не найден (в том числе ссылка за последний элемент) — тег
  `null`, `TagVia` — таблица и номер первой ссылки, поле читается. Тип тега — код
  записи `VAR` (`HmiTag.TypeCode`). Стили — три ссылки в конце блока (u32 +0x14 —
  его размер от +0x18), не выровнены за Units; метка `00 FE FF 9F` на границе 4
  байт, за ней ссылка на `FONT` (`BorderStyleReader`, `TextStyleReader`,
  `FillStyleReader`, `FontReader`; таблица — по Id ссылки, имя проверяется). Метка
  не на месте, длина Units не сходится, нет ссылки на стиль, сбой элемента стиля —
  предупреждение с таблицей и смещением, поля нет (объект рисуется рамкой).
  Цвета Limits (`IoFieldLimitReader`): первая ссылка поля на `ADAPTVALUECHANG`, за
  ссылками элемента — список `ValueChangeList` (u16, u16 K, u32 вид, общий с номерами
  экранов); вид 3 — K пар по 8 байт (u32 ключ, R, G, B, 0): ключ 4 — High limit
  violated, 5 — Low limit violated, 0 — фон (не читается). Ссылки нет (у тега нет
  Range) или вид не 3 — цветов нет (`IoField.Limits` — `null`), без сообщения; ключа
  нет — цвет `null`; элемент не сходится (ссылка за последний элемент, пары не
  помещаются) — предупреждение с таблицей и смещением, поле остаётся с цветами «не
  прочитано» (решение пользователя 2026-11-03). Пределы Range (`LIMIT`) не читаются.
  Margins — байты `PS_Text` +0x1c…0x1f: Top, Bottom, Left, Right (`TextStyleReader`,
  `TextMargins`): элемент короче 0x20, но не короче 0x1a — Margins `null`, поле остаётся,
  в окне «не прочитано», предупреждение `PS_Text @ 0x…: запись N: длина 0x1a, Margins не
  прочитаны` — одно на элемент стиля (решение пользователя 2026-11-10); короче 0x1a —
  предупреждение стиля, поля нет. Flashing
  (`IoFieldFlashingReader`) — ссылка поля на `TIMER` со вторым словом 105 — Standard,
  иначе Disabled (в списке Type TIA; в Openness — None): слово 55 у служебных
  `HmiScreenItemData` — не мигание, Advanced на TP700 в файл не попадает (шаг 59
  совпал с Disabled). Flash on limit violation не читается — байты не найдены. Allow operator control — бит `0x08000000`
  стиля окна снят (u32 на +0 от конца ссылок); Authorization (`IoFieldSecurityReader`) —
  u32 номер права с нуля за ссылками элемента `SECURITY_MONITO` по ссылке поля,
  ссылки нет — `null`; элемент не сходится — предупреждение, поля нет; текст — 0 User
  administration, 1 Monitor, 2 Operate, другой — `?`. Tooltip —
  `Export/ScreenObjects/IoFieldTooltips` (объект строит `ScreenItems` окна; `INFO_HANDLER`
  разбирается после `IoFieldParser`): пара с элементом поля, у элемента несколько пар —
  первая, текст — строка языков как есть, с разметкой подсказки из Openness; язык не
  выбран или его нет в панели — первый язык, пары нет — пусто.
  Тексты и сборка Format pattern (текста шаблона в файле нет) —
  `Export/ScreenObjects/IoFieldTexts`: у Real и LReal (`TagTypeNames.IsFloat`, без
  бита массива и бита `0x80`) знаки после запятой — в шаблоне с точкой, у целого —
  Decimal places (сдвиг), у Date/Time шаблона нет; Field length у Decimal не
  известен (в файле нет); текст раздела Limits без цветов (`LimitsAbsent`) и ячейка
  цвета Limits (`LimitColor`: не прочитан — «не прочитано»). Выводятся только в окно
  (`окно.md`).
- Картинки (наблюдение на 193 картинках `samples/pdata.fwc`, A603A0097, CCB-A13):
  - `PICTURE` (Id 0x86) — элемент на картинку: u32 1, u32 0, u16 1, u16 1 (не
    читаются), на +0x0c u32 длина, с +0x10 файл PNG или JPEG целиком, нули до
    кратности 4; `TILED_PICTURE` (Id 0x15c) — длина на +0x1c, файл с +0x20 (на
    +0x10 и +0x12 u16 ширина и высота, на +0x14 четыре u16 — гипотеза: поля
    растягивания; не читаются). Формат — по сигнатуре: `89 50 4E 47 0D 0A 1A 0A` —
    `png`, `FF D8 FF` — `jpg`. Байты после картинки не проверяются (решение
    пользователя);
  - длина не помещается в элемент, равна 0, данные выходят за элемент, сигнатура
    не PNG и не JPEG — `FwxFormatException`: предупреждение, картинки
    таблицы до сбоя остаются, после — нет (незнакомый формат не пропускается —
    решение пользователя); нет таблицы — картинок из неё нет, без сообщения;
  - имя картинки (`PictureArchiveExporter.EntryName`) —
    `<таблица>_<n>.<png|jpg>`, n — номер элемента таблицы с 1 (`PICTURE_5.png`,
    `TILED_PICTURE_1.png`); сначала `PICTURE`, затем `TILED_PICTURE`; одинаковые
    картинки не объединяются. Пишет картинки только окно по кнопкам сохранения:
    одну как есть или все архивом `images.zip` (записи в корне под этими именами,
    без сжатия; `окно.md`);
  - строка `Картинок: N` (всего из обеих таблиц) в тексте запуска после `Стартовый
    экран:` и на «Сводке»;
  - ширина и высота — `PictureSize` (только для окна): PNG —
    u32 big-endian на 0x10 и 0x14 (`IHDR`), JPEG — u16 big-endian высота и ширина
    первого `SOFn` (0xC0–0xCF кроме 0xC4, 0xC8, 0xCC), сегменты пропускаются по длине,
    байты заполнения 0xFF и маркеры без длины (0x01, 0xD0–0xD7) — тоже; SOS раньше SOF
    или файл кончился — размера нет, без исключения. На 88 картинках `samples/pdata.fwc`
    и `samples/a603` размер прочитан у всех; у 7 (PNG и JPEG) сверен с раскодированным
    браузером окна.

- Экраны: шаги только на Project1 (V21, TP700 Comfort); у A603A0097 (V21, TP1900)
  номера и размеры всех 49 экранов сверены с TIA (выгрузка экранов в XML через
  Openness, 2026-10-21; расхождения с числом в имени — `022_ResultsCharts` 23,
  `415_I_S06` 108 — настоящие номера в TIA); CCB-A13 с TIA не сверялся (номер
  совпал с числом в начале имени у 6 из 9 экранов). V17 с несколькими
  экранами с TIA не сверялся (CCB-A13 — Runtime V17, 10 экранов, проекта нет). Шаблон экрана не определяется: имени нет ни в панели,
  ни в выгрузке ПЛК (`Project1_upload`), ни на картах ПЛК — только в `PEData.plf`
  исходного проекта. Индикатор алармов Global screen в записи `Overview` —
  гипотеза; `SCREEN_SYS`, ссылки записи `SCREEN` (кроме ссылки на `LIMIT`) и хвост (кроме цвета фона), поля `GUI` кроме номера
  стартового экрана, поля `VIEW_DYN` кроме высоты Permanent area и прочие
  элементы `ADAPTVALUECHANG` не разобраны. Высота Permanent area сверена с TIA
  на одном шаге одного проекта (V21, изменена через Openness, не в интерфейсе
  TIA).
- События экранов: сверены с TIA только на шагах Project1 (V21, TP700 Comfort);
  словарь — 142 функции из 197; второй параметр LogTag (`RECVAR`) и второй тег GetDataRecordName (таблица 0) не
  разобраны; таблицы журналов, отчётов и текстовых списков не разобраны — имён нет;
  у окна Global screen имени в файле нет (`SCREEN_SYS 7`); события объектов не
  читаются (`docs/открытые-вопросы.md`).
- Объекты экранов: сверены с TIA только на A603A0097 (V21, TP1900) и трендах
  Project1 (V21, TP700); V17 (CCB-A13) — только без предупреждений и в пределах
  экранов. Рамка окон-контролов из соседнего объекта сверена лишь у Trend view;

  Тип объекта TIA (кроме I/O field), признак объекта шаблона и порядок наложения не
