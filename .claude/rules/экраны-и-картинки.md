# Экраны и картинки

Установленное поведение и известные ограничения области (см. «Правила по областям» в
`CLAUDE.md`): не меняй без решения пользователя. Меняется код — меняются XML-документация и этот файл.

## Установленное поведение

- Экраны (сверено с TIA на шаговых копиях Project1, V21, `data/real/steps-screens/`):
  - `SCREEN` (Id 0x7) — элемент на запись: u16 вид (3 — экран, 1 — служебная
    запись pop-up без имени), u16 длина имени, имя UTF-16LE, нули до кратности 4,
    u32 R (≤ 0x20), R ссылок по 8 байт (не читаются), 8 байт, u16 ширина, u16
    высота, 6 байт, u16 N, N пар (u16 номер элемента, u16 Id таблицы) — объекты;
    хвост не читается. Порядок записей компилятор меняет. Объекты шаблона
    вливаются в экран, имени и ссылки на шаблон нет; окна Global screen — в
    `SCREEN_SYS` (не читается);
  - `ADAPTVALUECHANG` (Id 0x5f) — элемент со ссылкой на `GUI` (Id из TOC): u32 1,
    u32 R, R ссылок, u16 (0x12), u16 K, u32 (2), K пар (u16 номер экрана, u16 номер
    записи `SCREEN` с нуля); у остальных элементов читается только начало со
    ссылками; нет таблицы или `GUI` — номеров нет, без сообщения;
  - `GUI` (Id 0x16), первый элемент: u32 1, u32 R, R ссылок, на +0x14 от конца
    ссылок (+0x34 при R = 3) u16 — номер стартового экрана; нет таблицы —
    стартовый экран «неизвестно», без сообщения;
  - вид: есть номер — `Screen`; на запись ссылается объект служебной записи (Id
    `SCREEN`) — `Pop-up screen`; имя `Slide-in screen top/left/bottom/right`
    (TIA не даёт переименовать) — `Slide-in screen`; запись 0 (`Overview`, в ней
    объекты Permanent area) — `Permanent area`; иначе `?`;
  - сбой разбора (длина, первое слово `SCREEN` не 3 и не 1, R > 0x20, имя,
    ссылки, пары или номер не помещаются) — `FwxFormatException`: предупреждение,
    код 1, записи до сбоя остаются; `ADAPTVALUECHANG` прочитана не целиком — у
    экрана без найденного номера Number `?` (и вид `?`, если иначе не опознан);
  - лист «Экраны» после «Группы алармов», экранов нет — листа нет: `Name`,
    `Number` (числом, нет — пусто), `Start screen` (`Yes` у экрана с номером из
    `GUI`), `Width`, `Height`, `Вид`; служебные записи не выводятся; у Permanent
    area Name — `Permanent area`; строки: Permanent area, экраны по возрастанию
    номера, остальные в порядке файла. Колонки шаблона нет;
  - строки `Экранов: N` (число экранов вида `Screen`) и `Стартовый экран: <имя>
    (<номер>)` (номера нет — `неизвестно`, экрана с номером нет — `неизвестно
    (<номер>)`) в консоли после `Групп алармов:` и на «Сводке».
- Картинки (наблюдение на 193 картинках `samples/pdata.fwc`, A603A0097, CCB-A13):
  - `PICTURE` (Id 0x86) — элемент на картинку: u32 1, u32 0, u16 1, u16 1 (не
    читаются), на +0x0c u32 длина, с +0x10 файл PNG или JPEG целиком, нули до
    кратности 4; `TILED_PICTURE` (Id 0x15c) — длина на +0x1c, файл с +0x20 (на
    +0x10 и +0x12 u16 ширина и высота, на +0x14 четыре u16 — гипотеза: поля
    растягивания; не читаются). Формат — по сигнатуре: `89 50 4E 47 0D 0A 1A 0A` —
    `png`, `FF D8 FF` — `jpg`. Байты после картинки не проверяются (решение
    пользователя);
  - длина не помещается в элемент, равна 0, данные выходят за элемент, сигнатура
    не PNG и не JPEG — `FwxFormatException`: предупреждение, код 1, картинки
    таблицы до сбоя остаются, после — нет (незнакомый формат не пропускается —
    решение пользователя); нет таблицы — картинок из неё нет, без сообщения;
  - папка `images` (константа в `Program.cs`, с `FLEXRT_OUT` — `images` внутри
    неё) перед записью удаляется целиком и создаётся заново, картинок нет — пустая;
    файл на картинку `<таблица>_<n>.<png|jpg>`, n — номер элемента с 1, как в
    hex (`PICTURE_5.png`, `TILED_PICTURE_1.png`); сначала `PICTURE`, затем
    `TILED_PICTURE`; одинаковые картинки не объединяются. Экспорт четвёртый:
    `[Картинки -> файлы] N картинок -> <папка>`;
  - строка `Картинок: N` (всего из обеих таблиц) в консоли после `Стартовый
    экран:` и на «Сводке».

## Известные ограничения

- Экраны: шаги только на Project1 (V21, TP700 Comfort); A603A0097 и CCB-A13 с TIA
  не сверялись (номер совпал с числом в начале имени у 47 из 49 и 6 из 9 экранов;
  расхождения, например `022_ResultsCharts` — 23, не проверены). V17 с несколькими
  экранами с TIA не сверялся (CCB-A13 — Runtime V17, 10 экранов, проекта нет). Шаблон экрана не определяется: имени нет ни в панели,
  ни в выгрузке ПЛК (`Project1_upload`), ни на картах ПЛК — только в `PEData.plf`
  исходного проекта. Индикатор алармов Global screen в записи `Overview` —
  гипотеза; `SCREEN_SYS`, ссылки и хвост записи `SCREEN`, поля `GUI` кроме номера
  стартового экрана и прочие элементы `ADAPTVALUECHANG` не разобраны.
- Картинки: проверены только по длине и сигнатуре на трёх файлах (V17 и V21),
  с TIA не сверялись. Какой объект экрана показывает картинку и её имя в проекте
  не определяются; поля `TILED_PICTURE` до длины не разобраны. Других форматов
  (BMP, GIF, ICO, EMF/WMF, SVG) в известных файлах нет.
