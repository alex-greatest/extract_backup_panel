# ARCHIVES — журналы панели

Журналы панели (в TIA: Historical data → Data logs и Alarm logs): имя журнала
и ссылки на то, что в него пишется. Программа читает таблицу в
`Parsing/Panel/Alarms/ArchivesParser.cs` ради одного — имени журнала алармов
для колонки **Log** класса аларма; классы журнала — в `RECMSG`
([таблица-recmsg.md](таблица-recmsg.md)).

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md).
Проверено на A603A0097 (V21): два журнала данных и один журнал алармов; на
Project1 (V21): два журнала данных и два журнала алармов (`Alarm_log_1` →
`RECMSG` 0, `Alarm_log_2` → `RECMSG` 1).

## Таблица

`Id` = 0x44. Элемент на журнал. В `samples/pdata.fwc` (Project1) и CCB-A13
таблицы нет.

## Элемент

| Смещение | Значение | Статус |
|---|---|---|
| +0x00 u16 | 3 (как первое слово записи `VAR`) | наблюдение |
| +0x02 u16 | длина имени в символах | установлено на файлах |
| +0x04 | **имя журнала** UTF-16LE (`OP70_AlarmsHistory`), нули до кратности 4 | установлено: совпало с TIA |
| дальше u32 | R — число ссылок | установлено на файлах |
| R × 8 байт | ссылки: u16 Id таблицы, u16 номер элемента, два u16 (`0x58, 0x58`) | установлено на файлах |
| дальше | не разобрано | — |

Ссылки:

- журнал алармов — одна ссылка `(0x43 RECMSG, номер элемента)`;
- журнал данных — ссылки на элементы `RECVAR` (0x42): у обоих журналов
  A603A0097 по 2 ссылки, на элементы 0, 1 и 2, 3. Гипотеза: по ссылке на тег
  журнала. Поэтому число ссылок программа не ограничивает.

После ссылок (не разобрано, наблюдение): числа, повтор имени журнала и путь
хранения (`\Storage Card SD\Alarms\`, `\Storage Card SD\Trend\`).

## Что делает программа

- Читает имя и ссылки каждого элемента; байты после ссылок не читает.
- Элемент короче 4 байт, первое слово не 3, имя или ссылки не помещаются в
  элемент — `FwxFormatException` с таблицей и смещением: предупреждение,
  код 1; у классов, журнал которых не найден, Log — `?`.
