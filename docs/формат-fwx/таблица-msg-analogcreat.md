# MSG_ANALOGCREAT — аналоговые алармы

Аналоговые алармы панели (в TIA: HMI alarms → Analog alarms): ID, текст,
класс, Report и поля вывода в тексте. Программа читает таблицу в
`Parsing/Panel/Alarms/MsgAnalogCreatParser.cs`, раскладку элемента — общим с
`MSG_NUMEVENT` кодом `Parsing/Panel/Alarms/AlarmMessageLayout.cs`. Класс — номер
записи в `MSG_ANALOGHANDL`
([таблица-msg-analoghandl.md](таблица-msg-analoghandl.md)), тег срабатывания,
предел и Limit mode — в `MSG_ANALOG_OBSE`
([таблица-msg-analog-obse.md](таблица-msg-analog-obse.md)), тексты — в
`STRINGSTORE`.

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md):
установлено на файлах, наблюдение, гипотеза.

Таблица появляется только когда в панели есть хотя бы один аналоговый аларм:
до первого шага её не было ни в одном файле. Владелец по шагам добавлял алармы и
менял свойства (Limit, Limit mode, предел-тег, ID, класс, Report, поле тега в
тексте, теги срабатывания Int, Real и UInt); лист сверен со списком Analog
alarms из TIA.

## Элемент

`Id` = 0x124. Элемент на аларм, в порядке создания алармов, а не по ID.
Раскладка та же, что у `MSG_NUMEVENT`
([таблица-msg-numevent.md](таблица-msg-numevent.md)):

| Смещение | Значение | Статус |
|---|---|---|
| +0x00 u32 | 0 во всех элементах | наблюдение |
| +0x04 u32 | R — число ссылок, по две на поле вывода (0, 2) | установлено на файлах |
| +0x08 | R ссылок по 8 байт | установлено на файлах |
| дальше u32 | номер строки **текста** в `STRINGSTORE`, один для всех языков | установлено: `ANA1`…`ANA3`, `VVVV` |
| u32 | номер второй строки: `HMI_ST7` — имя соединения панели | наблюдение; не выводится |
| u16 | **ID** аларма | установлено: ID 1 → 7 сменился здесь |
| u8 | младшие 5 бит — **номер класса** в списке `MSG_ANALOGHANDL`; старшие 3 — число полей | установлено: Errors 0, Warnings 1 |
| u8 | флаги: бит `0x40` — **Report = On**; биты 1…5 — **ID группы** аларма (`ID << 1`, 0 — без группы), как у `MSG_NUMEVENT` | Report установлено: Off → On; группа — на Project1: без группы `00`, группа 31 `3e` |
| u16 на поле | код поля, затем нули до кратности 4 | как у `MSG_NUMEVENT` |

Поле тега в тексте (аларм 1, `ANA2`): ссылки `(DATALINK, 8, 0, 0x8069)` и
`(0, 0, 0, 0x19)`, код `0x7905` — длина 5; связь `DATALINK` 8 совпала со связью
HMI-тега `DB_ST7_BasicLogic_Work_Mode_Machine_mode_no`. Метка поля стоит в
начале текста (`1B 54 01 FF` + `ANA2`); в русском и польском тексте `ANA2` нет,
есть только метка. TIA показывает текст так же, как программа:
`<Tag : 5, DB_ST7_BasicLogic_Work_Mode_Machine_mode_no>ANA2` (сверено).

## Что делает программа

- Читает все элементы по порядку; каждый аларм сразу добавляется в документ.
- Ошибки — как у `MSG_NUMEVENT`: длина не сходится с R, R нечётно или больше
  0x20, число полей в байте класса не равно R/2 — `FwxFormatException` с
  таблицей и смещением: предупреждение, код 1, алармы до сбоя выводятся.
- Лист «Аналоговые алармы» в `panel_data.xlsx`: ID, текст на каждом языке с
  подписями полей, класс, группа, тег срабатывания, Limit, Limit mode, Report; строки
  по возрастанию ID.

## Чего в pdata.fwc нет

Имени аларма (Name: `Analog alarm_1`) и имени группы (`Alarm_group_31`) — как и у дискретных.
