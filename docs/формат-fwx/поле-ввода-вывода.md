# I/O field — элементы VIEW_IN и VIEW_OUT

Поле ввода-вывода TIA (I/O field): режим, тег, формат, Hidden input, Units, цвета
Limits, Flashing, Security, Tooltip и ссылки на стили и шрифт. Программа читает поле в
`Parsing/Panel/Screens/IoFieldParser.cs` (тег — `IoFieldTagReader.cs`, цвета Limits —
`IoFieldLimitReader.cs`, Flashing — `IoFieldFlashingReader.cs`, Authorization —
`IoFieldSecurityReader.cs`), стили, шрифт и Margins — [стили-объектов.md](стили-объектов.md);
положение и имя — как у любого объекта, [объекты-экрана.md](объекты-экрана.md).

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md):
установлено на файлах, наблюдение, гипотеза.

## Какой элемент — I/O field

В VIEW_IN и VIEW_OUT лежат и другие объекты. Тип различает u32 на +0x10 от
конца ссылок элемента (начало — как у `VAR`: вид, имя, R, R ссылок):

| Код | Таблица | Объект | Статус |
|---|---|---|---|
| `0x5DC000` | VIEW_IN | I/O field, Input и Input/output | установлено |
| `0x5CC000` | VIEW_OUT | I/O field, Output | установлено |
| `0x98C000` | VIEW_OUT | Text field | наблюдение (347 объектов A603A0097 по именам) |
| `0x88C000` | VIEW_OUT | Symbolic I/O field | наблюдение (15 объектов по именам) |

Элемент с другим кодом программа не читает как поле (без сообщения).

## Раскладка от конца ссылок (E)

| Смещение | Поле | Статус |
|---|---|---|
| E+0x00 | u32 стиль окна, E+0x04 — рамка (как у всех объектов); бит `0x08000000` — Allow operator control снят (шаг 55) | установлено |
| E+0x0c | u32: 1 у VIEW_IN, 0 у VIEW_OUT | наблюдение |
| E+0x10 | u32 код типа (таблица выше) | установлено |
| E+0x14 | u32 размер блока от E+0x18 до конца ссылок на стили; растёт с длиной Units | установлено |
| E+0x18 | u32 `0x8000000E` у VIEW_IN, `0x80000009` у VIEW_OUT | наблюдение |
| E+0x20 | u32 Display format: 0 String, 1 Decimal, 2 Hexadecimal, 3 Binary, 4 Date, 5 Time, 6 Date/time | установлено |
| E+0x24 | u16 знаков после запятой: у Real — из шаблона, у целого — Decimal places (сдвиг); за ним u16, всегда 3 | установлено |
| E+0x2c | только VIEW_IN: u16 `0xFFFF` — Input/output, 0 — Input | установлено |

Дальше — поля формата, начало P: у VIEW_IN P = E+0x2e, у VIEW_OUT P = E+0x2c
(слова режима нет):

| Смещение | Поле | Статус |
|---|---|---|
| P+0x00 | u16 длина Format pattern вместе с `s` и точкой; у Date, Time — 20, у Date/time — 40 (Field length) | установлено |
| P+0x04 | u16 `0xFFFF` — знак `s` в шаблоне | установлено |
| P+0x08 | u16 `0xFFFF` — Leading zeros | установлено |
| P+0x0a | только VIEW_IN: u16 `0xFFFF` — Hidden input (Characteristics) | установлено (шаг 47) |
| P+0x0c (VIEW_IN), P+0x0a (VIEW_OUT) | u16 длина Units в байтах с нулём, u16 0, текст UTF-16LE | установлено |

Конец блока (E+0x18 + размер) — три ссылки на стили по 4 байта (u16 Id таблицы,
u16 номер элемента: `PS_BorderedShap`, `PS_Text`, `PS_Fill_Color`). Они идут
сразу за текстом Units и бывают не выровнены (Units `mm/s`, `[s]` в
A603A0097). За ними, на границе 4 байт, — метка `00 FE FF 9F` (наблюдение:
всегда), за меткой — ссылка на `FONT` (u16 номер элемента, u16 Id таблицы) —
установлено. У VIEW_IN между Units и ссылками ещё 4 нулевых байта — наблюдение.

Текста Format pattern в файле нет. Его можно собрать по формату, длине, числу
знаков, знаку и типу тега: у Real и LReal — `s`, девятки, точка, девятки; у
целого — без точки (знаки после запятой — сдвиг); Hexadecimal — `F`, Binary —
`1`, String — `?` на символ. Так собраны шаблоны всех полей A603A0097 и шагов
07–14 — совпали с TIA. Field length у Decimal в файл не попадает (шаг 40
совпал с базой).

## Тег

Ссылки элемента (R ссылок за именем):

- первая ссылка на `VAR` — тег; слова ссылки — `0x60, 0` у VIEW_IN, `0, 0` у
  VIEW_OUT (наблюдение); без тега ссылок нет (шаг 00);
- ссылки на `VAR` нет, первая — на `ADAPTVALUECHANG`: его первая ссылка — на
  `VAR` или на элемент `VARLIST` с именем тега (`IO Field_2` A603A0097 →
  `Step_Number`, как в TIA) — установлено на двух полях;
- иначе тег не найден, в окне — `? (<таблица> <номер с единицы>)`.

Тип тега — код записи VAR. У тегов ПЛК A603A0097 у кода есть бит `0x80`
(`0x82` Int, `0x84` Real) — значение бита не проверено, при выборе «Real или
целое» он не учитывается.

Вторая и третья ссылки VIEW_IN (обе — Id таблицы 0, у третьей слова `0x60,
0x8000`) — не разобраны.

## Limits

В разделе Limits у TIA два цвета: High limit violated и Low limit violated
(Openness: `AboveUpperLimitColor`, `BelowLowerLimitColor`). Пределы — Range
тега (Upper 2, Upper 1, Lower 1, Lower 2), а не свойство поля.

- Цвета TIA пишет, только если у тега задан Range или тег идёт через
  VARLIST (`IO Field_2` A603A0097). Нет — у поля только ссылка на тег (шаги
  63–65), цветов в файле нет — установлено.
- С Range у VIEW_IN ссылки: `VAR (0x60, 0)`, `0 (0, 0)`,
  `ADAPTVALUECHANG (0, 0x3c)`, `LIMIT` без имени `(0xf, 0xf)`, `0 #3 (0xe, 0xe)`,
  `LIMIT` с именем `тег~N` `(0, 0x8000)` — наблюдение (7 полей A603A0097, шаг 66).
- Цвета — в элементе `ADAPTVALUECHANG` первой ссылки поля на эту таблицу: за
  ссылками список (как у номеров экранов, [таблица-adaptvaluechang.md](таблица-adaptvaluechang.md)):
  u16 (0x12), u16 K, u32 вид — 3, K пар по 8 байт: u32 ключ, R, G, B, 0. Ключ 4 —
  High limit violated, 5 — Low limit violated, 0 — цвет фона поля (не читается) —
  установлено (шаги 66–67, 9 полей A603A0097 — 7 с Range у тега и `IO Field_2` с тегом через VARLIST на двух экранах, в том числе 255, 0, 0 / 255, 255, 0).
  Список другого вида программа не считает цветами (у всех известных полей вид 3).
- Оба элемента `LIMIT` хранят пределы Range тега: у двух пределов — Lower 2 и
  Upper 2 (тип 2 i16 или 5 f64; совпали у 7 тегов A603A0097), у четырёх — тип 3,
  в порядке Lower 2, Upper 2, Lower 1, Upper 1 (шаг 66). Байт флагов за ссылками:
  `03 27 03 00` (без имени, два предела), `83 a7 0f 00` (четыре) — гипотеза о
  том, какие пределы заданы. Программа пределы не читает.

Испорченный элемент с цветами (пары не помещаются, ссылка за последний
элемент) — предупреждение с таблицей и смещением, поле остаётся, цвета «не
прочитано».

## Flashing

Flashing Standard — ещё одна ссылка элемента: `TIMER` (Id 0x6c), элемент 0, слова
`0, 105` (шаг 50, элемент на 8 байт длиннее). None — такой ссылки нет — установлено
на одном поле Input/output. У поля Output шага нет: правило то же, не проверено.

Ссылка на `TIMER` не всегда мигание: у служебных объектов `HmiScreenItemData` и
`HmiScreenItemData_1` (`VIEW_OUT`, код I/O field) — слова `0, 55`, 292 ссылки в 155
копиях; слово 105 встретилось только на шаге 50. Поэтому программа сверяет слово.

Advanced на TP700 в файл не попадает: шаг 59 отличается от базы только заголовком.

## Security

- Allow operator control — бит `0x08000000` стиля окна (E+0x00): установлен —
  управление запрещено (шаг 55) — установлено.
- Authorization — ссылка элемента на `SECURITY_MONITO`; за ссылками его элемента u32
  номер права с нуля: 0 User administration, 1 Monitor, 2 Operate (шаги 60–62) —
  установлено. Ссылки нет — право не задано. Имён своих прав в файле нет, в окне — `?`.

Элемент права не сходится — предупреждение с таблицей и смещением, поля нет.

## Tooltip

Пара `INFO_HANDLER` с Id `VIEW_IN` и номером элемента поля с нуля, текст — строка языков
([таблица-info-handler.md](таблица-info-handler.md)): шаг 53, копии `11`–`15`
`data/real/steps-screen-props/` — установлено. Поля Output с подсказкой не встречались,
программа ищет пару по элементу поля в любой таблице. Несколько языков у подсказки поля
на реальном файле не проверены. Подсказка, заданная через Openness, — с разметкой
`<body><p>…</p></body>`, показывается как есть.

## Чего нет в файле

- Fill pattern (Transparent): на TP700 Comfort в TIA поле недоступно, файл с
  Transparent совпал с Solid (шаг 22).
- Стили рамки Dash, Dot, DashDot, DashDotDot записаны тем же кодом, что Solid
  (шаги 41–44).
- Field length у Decimal (шаг 40).
- Fit to size (шаг 49) и Layer (шаг 58): копии отличаются от базы только заголовком.
- Имя стиля и признак Use design color schema не найдены, а значения стиля
  компилируются в обычные записи: на шаге 56 файл вырос на 640 байт — новые записи
  `PS_BorderedShap`, `PS_Text`, `PS_Fill_Color`, `FONT`, `TILED_PICTURE` на 388 байт
  больше; назначение этой записи не установлено.
