# SCREEN — экраны

Экраны панели (в TIA: Screens, Screen management → Pop-up screens, Slide-in
screens, Permanent area): имя, размер, ссылки и список объектов. Программа читает
таблицу в `Parsing/Panel/Screens/ScreenParser.cs`. Номер экрана — в
[таблица-adaptvaluechang.md](таблица-adaptvaluechang.md), стартовый экран — в
[таблица-gui.md](таблица-gui.md), Visibility экрана — в
[таблица-limit.md](таблица-limit.md).

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md):
установлено на файлах, наблюдение, гипотеза. Общее устройство таблиц —
[общая-структура.md](общая-структура.md).

## Запись

`Id` = 0x7. Элемент на запись; порядок записей компилятор меняет (в шаге 03
`Screen_2` переместился с четвёртой записи на вторую) — наблюдение.

| Смещение | Значение | Статус |
|---|---|---|
| +0x00 u16 | вид записи: 3 — экран, 1 — служебная запись pop-up | установлено на файлах |
| +0x02 u16 | длина имени в символах; у служебной записи 0 | установлено на файлах |
| +0x04 | имя UTF-16LE, нули до кратности 4 | установлено на файлах |
| далее u32 | R — число ссылок | установлено на файлах |
| далее | R ссылок по 8 байт (u16 Id таблицы, u16 номер элемента, два слова): у экрана — `SOFTKEY` (0x28) и, если есть, `FUNC_LIST` (0x2a; гипотеза: функции событий экрана) или `LIMIT` (0x11, слова `10 00 00 00`: Visibility экрана — установлено на шагах `data/real/steps-animations/`, [таблица-limit.md](таблица-limit.md)); у одного экрана A603A0097 — `ADAPTDEMULTIPLE` (0x39); у pop-up, slide-in и служебной записи ссылок нет | наблюдение; ссылка на `LIMIT` установлена |
| +0x00 от конца ссылок | 8 байт: у всех записей, кроме служебной, `40 00 00 40 00 00 00 00`, у служебной записи `00 00 00 40 00 00 00 00` | наблюдение, не разобрано |
| +0x08 u16, +0x0a u16 | **ширина** и **высота** в пикселях | установлено на файлах (pop-up 400×200, как в TIA) |
| +0x0c…+0x11 | 6 нулевых байт | наблюдение |
| +0x12 u16 | N — число объектов | установлено на файлах |
| +0x14 | N пар (u16 номер элемента, u16 Id таблицы) — объекты экрана: `VIEW_BUTTONS` 0x17, `VIEW_OUT` 0x3, `VIEW_OCX` 0x4, `VIEW_COMBOBOX` 0x33, … | установлено на файлах (новая кнопка — новая пара) |
| после пар | хвост; последние 20 байт у всех записей — `FFFFFFFF \| xxxxxxxx \| RR GG BB 00 \| 00100000 \| 00000000`; у записей с объектами перед ними бывают ещё байты (в `samples/pdata.fwc` хвост 32 и 44 байта) | наблюдение на 15 файлах `samples/` и `data/real` (V17 и V21); кроме цвета не разобрано |
| длина − 12 | **цвет фона** (Background color): байты R, G, B; 4-й байт (всегда `00`) не читается | установлено: шаг `02_bg_color` (Screen_1 18, 52, 86 → `12 34 56`, единственное отличие от `01_roundtrip`), A603A0097 — 49 из 49 экранов совпали с BackColor из XML TIA (`998_LOGIN` `B6B6B6`, остальные `FFFFFF`); у Permanent area, pop-up, slide-in и служебной записи цвет тоже есть (обычно 182, 182, 182, у pop-up CCB-A13 181, 182, 181) |

## Виды записей

- **Обычный экран** — у него есть номер в `ADAPTVALUECHANG`. В Project1 высота
  экранов 420 из 480 при Permanent area 60 px; в A603A0097 и CCB-A13 Permanent
  area нет (высота 0), экраны — полная высота панели. Высота экрана хранится в
  записи как есть и при смене Permanent area сама не пересчитывается: после шага
  `steps-screen-props/15_overview_height` (Permanent area 60 → 80 через
  Openness) экраны и в TIA, и в файле остались 420 — установлено. При этом TIA
  требует высоту экрана = высота панели − высота Permanent area: повторный
  импорт экрана 420 на этой копии TIA отклоняет («The screen size does not
  match the device»; наблюдение сессии our-tia-mcp). 420 в файле после шага 15 —
  несохранённое после смены Permanent area состояние экранов.
- **Запись 0, `Overview`** — объекты **Permanent area**: кнопка, добавленная в
  Permanent area (шаг 07), появилась только в ней, остальные экраны не
  изменились. Установлено. В ней же `VIEW_OCX` с именем `Logo`, два `VIEW_OUT`
  (гипотеза: дата и время), `VIEW_COMBOBOX` (гипотеза: имя экрана) и `VIEW_OCX`
  со ссылками на `FUNC_MSGWIN` и `TIMER` (гипотеза: индикатор алармов из Global
  screen), `VIEW_DYN` 0 (ссылается на элемент 0 `ADAPTVALUECHANG`; в CCB-A13 —
  единственный объект; в нём высота Permanent area —
  [таблица-view-dyn.md](таблица-view-dyn.md)). Размер записи — вся панель
  (800×480), а не Permanent area. Цвет фона (длина − 12) — цвет Permanent area:
  шаг `steps-screen-props/14_overview_color` (52, 86, 120 → `34 56 78`) —
  установлено. Имя `Overview` во всех файлах.
- **Pop-up screen** — номера нет; на запись ссылается служебная запись
  (первое слово 1, имени и ссылок нет, размер 0): её единственный объект — пара
  (номер записи pop-up, Id `SCREEN`). Установлено на шаге 05 и сверено:
  A603A0097 — одна служебная запись на `No_Authorization_Msg_PopUpScreen`,
  CCB-A13 — семь на `UZ70`…`UZ90`.
- **Slide-in screen** — имена `Slide-in screen top`, `left`, `bottom`, `right`:
  их задаёт TIA, переименовать нельзя (подтвердил пользователь); английские во
  всех файлах, в том числе в проектах с русским и польским. Объект в
  slide-in — пара в её записи (шаг 06).

## Чего в таблице нет

- **Шаблон** (Template). Объекты шаблона вливаются в список объектов экрана:
  шаг 03 добавил в `Screen_2` кнопку и выпадающий список `Template_2`, шаг 04
  убрал их; между шагами 03 и 04 изменилась только запись `Screen_2`. Ссылки
  на шаблон, его имени и признака «объект шаблона» нет. Имени шаблона нет и в
  выгрузке ПЛК (`Project1_upload`), и на картах ПЛК — только в `PEData.plf`
  исходного проекта.
- **Global screen**. Окно алармов, добавленное в Global screen (шаг 08), не
  попало в `SCREEN`: появились элемент `VIEW_OCX`, элемент `SCREEN_SYS` с
  единственным объектом — этим окном, и элемент `MSG_WNDACTIVATO` со ссылкой
  на новый `SCREEN_SYS`. Три прежних окна алармов — тоже в `SCREEN_SYS`.
  `SCREEN_SYS` программа не читает.

## Что делает программа

- Читает все записи: вид, имя, ссылки (Id таблицы и номер элемента —
  `Screen.References`; по ссылке на `LIMIT` читается Visibility), ширину, высоту,
  объекты и цвет фона (длина − 12); слова ссылок и остальной хвост не читает.
- Запись короче 4 байт, первое слово не 3 и не 1, R > 0x20 или имя, ссылки,
  размер и объекты не помещаются в элемент — `FwxFormatException` с таблицей и
  смещением: предупреждение, записи до сбоя остаются.
- После объектов меньше 12 байт — цвет фона не читается, запись остаётся (на
  листе цвет `?`); после таблицы одно сводное предупреждение: число таких записей,
  первая запись и её смещение (и тогда, когда разбор оборвала следующая запись).
- Лист «Экраны» в `panel_data.xlsx`: Name, Number, Start screen, Width, Height,
  Background color (`182, 182, 182`, ячейка залита этим цветом), `Visibility tag`,
  `Visibility from`, `Visibility to`, `Visibility` ([таблица-limit.md](таблица-limit.md);
  нет анимации — пусто), `Tooltip <язык>` на каждый язык панели
  (подсказка из `INFO_HANDLER`, текст как есть; нет — пусто), Вид; служебные записи не выводятся; у записи 0 без номера имя и вид —
  `Permanent area`, Height — высота из `VIEW_DYN` (не прочитана — `?`), а не
  высота записи.
