# Анимации I/O field

Программа извлекает настройки Appearance, Control enable, Visibility и
движений I/O field. Вкладка **Animations** показывает их без редактирования;
холст не воспроизводит анимации. Произвольные Tag connections не разобраны:
Process value показывает уже прочитанный тег поля.

## Основание и границы проверки

Установлено на 26 контрольных FWC из
`data/real/animations-iofield-20261113/` (вне git): TIA V21, TP700 Comfort,
Runtime 17.0.0.0; каждая принятая конфигурация скомпилирована без ошибок и
предупреждений и сопоставлена с обратным экспортом XML. Проверены отдельные
настройки, их сочетания, Input/output и Output. Appearance дополнительно
сверена с XML у 10 полей A603A0097 (TP1900 Comfort, V21).

Дополнительно 14 ноября 2026 на TP700 и TP1900 Comfort (TIA V21 Update 1,
Runtime 17.0.0.0) проверены целые границы Real, UDInt 2147483646…2147483647
и Single bit 31. На TP700 также проверены символические и абсолютные связи
с тегами ПЛК. Контрольные FWC, обратные XML, результаты компиляции и сравнения
байтов — `data/real/animations-real-udint-plc-20261114/` (вне git).

В проверенном вводе Appearance для Real −15.5…−2.25 редактор TIA сохранил
−15…−15; импорт XML с дробными границами отклонён. Принятый FWC с диапазоном
UDInt выше 2147483647 в этих опытах не получен: XML-импорт Appearance отклонён,
компиляция условий и движений завершилась ошибкой. Range с LReal код не
поддерживает. Другие версии TIA, несколько языков и выполнение на ПЛК или
панели не проверены.
Импорт Tag connections для Width и ForeColor в исходном опыте не изменил
элементы FWC относительно базы; это не вывод для всех панелей.

## Appearance

Установлено: ссылка поля ведёт на `ADAPTDYNATTRIBU`, затем на `SYMB`.
Первая ссылка `SYMB` на `VAR` отличает Appearance от Flash on limit
violation, где она ведёт на `LIMIT`. Читатель — `AppearanceAnimationReader`.

`E` — конец заголовка ссылок `SYMB`: u32 3 (наблюдение), u32 число ссылок,
ссылки по 8 байт. Раскладка после него установлена на контрольных копиях:

| Смещение | Значение |
|---|---|
| `E+0x00` | u16 число состояний N |
| `E+0x02` | u16 режим: 1 Range, 4 Single bit |
| `E+0x04`, Range | N пар u32 From, To |
| `E+0x04`, Single bit | u32 инвертированная маска, ровно один нулевой бит; N = 2 |
| После диапазонов или маски | 4 байта заголовка цветов; байт +2 — размер записи 9 |

Остальные байты заголовка цветов не интерпретируются: байт +1 не установлен
как универсальное число записей. Далее N + 1 записей по 9 байт: R, G, B, 0
текста; R, G, B, 0 фона; флаги мигания. Запись 0 — обычный вид, запись k + 1 —
диапазон или состояние k. Установлено: 0 No, 1 Slow, 2 Medium, 3 Fast;
неизвестный код показывается как `? (0xXX)`.

Код читает границы как i32 для Int, DInt, SInt и Real, как u32 — для остальных
поддержанных целочисленных типов; биты массива и `0x80` типа ПЛК исключает.
У Real на TP700 проверены отрицательные границы и пределы i32, на TP1900 —
отрицательные границы. Отрицательные DInt проверены отдельно; поддержка кода
не означает проверки всех типов и предельных значений.

## Visibility и Control enable

Установлено: обёртка `VIEW_DARK` хранит заголовок ссылок и одну пару дочернего
объекта. Второе служебное слово каждой ссылки (ссылка +0x06) задаёт роль:
0 — Visibility, `0x19` — Control enable. Обе роли встречаются в одной обёртке.
u32 после пары объекта не установлен как вид анимации.

`FieldConditionReader` читает условие по ссылке:

- `LIMIT`: от конца ссылок E байт `E+0x01`, бит `0x08` — Visible или Enabled;
  снят — Invisible или Disabled. From и To — VARIANT по 16 байт на `E+0x08`
  и `E+0x18`; значение на +0x08 VARIANT. В контрольных условиях обе границы
  имеют тип 5 f64; типы 2 i16 и 3 i32 поддерживает код, в этих опытах они
  не проверены.
- `SYMB`: u16 1 на `E+0x00`, u16 4 на `E+0x02`, положительная маска одного
  бита на `E+0x04`. На `E+0x0a` байт размера значения 2; на `E+0x0c` и
  `E+0x0e` — два 16-битных состояния для бита 0 и 1 (в опытах значения 0/1,
  знаковость не установлена). Ненулевое второе значение означает
  Visible или Enabled при установленном бите.

## Движения

Установлено: ссылки `VIEW_MOVE` со вторым служебным словом `0x19` задают X,
`0x1a` — Y. Id таблицы 0 — допустимая неиспользуемая ось. Direct movement
ссылается на `VAR` осей; диапазоны и координаты для него не извлекаются.

Диапазонное движение ведёт на `VIEW_MOVE_ADAPT`. Его первая ссылка — тег
`VAR`. От конца ссылок: `+0x00` u32 2 (наблюдение), `+0x04` не разобрано;
`+0x08` и `+0x10` f64 From, To; `+0x18`, `+0x1a`, `+0x1c`, `+0x1e` —
i16 Start X, Start Y, End X, End Y.

Установлено: Horizontal и Diagonal с нулевым изменением Y дают одинаковые
элементы FWC. Вкладка показывает Horizontal / Diagonal movement при изменении
только X, Vertical / Diagonal movement — только Y, Diagonal movement — обеих
осей; исходный тип TIA в неоднозначном случае не восстанавливается.

## Сбои и представление

Установлено кодом: `IoFieldAnimationParser` после `IoFieldParser` обходит
обёртки экранов до глубины 8, только вокруг распознанных полей. Общая обёртка
читается один раз. Если список дочерних объектов прочитан, сбой настройки не скрывает поля
от внешней обёртки.

Обнаруженные ошибки ссылок и раскладки дают предупреждение с таблицей
и смещением. Это проверка распознанных связей анимаций, а не полная
валидация всех ссылок файла. Поле и остальные прочитанные настройки
сохраняются. Отсутствие анимации отличается от сбоя: у Appearance непрочитаны
диапазоны, у условия — состояние, у движения — вся настройка. Неизвестная роль
условия даёт предупреждение и пропускается, остальные ссылки продолжаются.
Id 0 неиспользуемой оси не считается повреждением.

Предупреждения входят в текст чтения ядра и вкладку **Ошибки** окна; **Info**
фильтрует только информационные строки. Окно показывает «Appearance не
прочитана», «Условие анимации не прочитано» или «Движение поля не прочитано».
Новых колонок Excel и обычных строк текста чтения анимации не добавляют.
