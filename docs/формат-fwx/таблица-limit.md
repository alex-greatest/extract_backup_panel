# LIMIT — Visibility и Range тегов

Таблица содержит несколько видов записей: Visibility экрана, условия
I/O field и пределы Range HMI-тега. Visibility читает `LimitParser` по ссылке
из [SCREEN](таблица-screen.md), условия поля — `FieldConditionReader`,
именованные Range — `TagRangeParser` после VAR.

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md):
установлено на файлах, наблюдение, гипотеза.

## На чём проверено

Шаговые копии Project1 (V21, TP700 Comfort, `data/real/steps-animations/`),
экран `Screen_2`; база — `data/real/steps-screens/08_global.fwc` (таблицы
`LIMIT` в нём нет):

| Шаг | Что изменено в TIA |
|---|---|
| 01_screen_visibility | Visibility на `Bool_I0_0`, Range 0…0, Visible |
| 02_screen_visibility_to1 | To 0 → 1 |
| 03_screen_invisible | Visible → Invisible |
| 04_tag_array_bool | тег `Array [0..22] of Bool_1` |
| 04_tag_int_to130 | тег `Tag_Int`, To 130 |
| 05_from_minus5 | From −5 |
| 06_from7_to7 | From 7, To 7 |
| 07_dint_to100000 | тег `DInt`, From 0, To 100000 |
| 08_dword_plc_md26 | тег ПЛК `DWord_MD26` |

Шаг 01 по сравнению с базой: новая таблица `LIMIT` (Id 0x11) с одним
элементом, запись `Screen_2` в `SCREEN` длиннее на 8 байт (вторая ссылка),
остальные таблицы те же (у `LICENSE` изменилось одно число). На шагах 02–08
меняется только элемент `LIMIT` — установлено.

Ограничения TIA (наблюдение в интерфейсе): у Visibility экрана только режим
Range — Single bit недоступен для Bool, Int, DInt, массива Bool и тега ПЛК
DWord; From должно быть меньше To (равенство допускается); тег Real в списке
не предлагается.

## Ссылка из SCREEN

Вторая ссылка записи экрана: `11 00 <k> 00 10 00 00 00` — Id `LIMIT`, номер
элемента k, слова 0x10 и 0 (0x10 — наблюдение; гипотеза: «свойство
видимость»). У экрана без анимации ссылки на `LIMIT` нет — установлено.

## Элемент без имени

56 байт при одной ссылке:

| Смещение | Значение | Статус |
|---|---|---|
| +0x00 u32 | 1 | наблюдение |
| +0x04 u32 | R — число ссылок, у Visibility экрана 1 | наблюдение |
| +0x08 | R ссылок по 8 байт; первая — **тег**: u16 Id `VAR`, u16 номер записи `VAR` с нуля, два слова 0 | установлено (5 разных тегов, внутренние и ПЛК) |
| +0x00 от конца ссылок | 8 байт `03 7c 03 00 00 00 00 00` | не разобрано, кроме бита ниже |
| +0x01 бит 0x08 | **Visible** (1) / **Invisible** (0): `0x7c` / `0x74` | установлено (шаг 03, единственное отличие) |
| +0x08 | **From**: 16 байт — u16 тип, 6 байт, 8 байт значения | установлено (0, −5, 7) |
| +0x18 | **To**: так же | установлено (0, 1, 7, 130, 100000) |

Тип значения похож на VARIANT: 5 (`VT_R8`) — f64 — у всех Visibility экранов
(установлено на шагах); 2 (`VT_I2`) — i16 — в элементах `LIMIT` A603A0097, на
которые ссылается `ADAPTVALUECHANG`, а не экран (наблюдение; гипотеза, что это
VARIANT). Остальные биты байта +0x01 и байты +0x00, +0x02 от смены тега, типа
тега, диапазона и тега ПЛК не менялись.

## Другие элементы таблицы

Таблица общая, не только для экранов (наблюдение, A603A0097, 23 элемента; на
экраны там ссылок нет):

- элементы без имени с байтом `0x7c` или `0x74`, на которые ссылается
  `VIEW_DARK` (гипотеза: Visibility объектов);
- элементы без имени с байтом `0x27` (тип значения 2 или 5), на которые
  ссылается `ADAPTVALUECHANG`;
- элементы с именем — u16 3, длина и имя (`DB_ST7_HMI_…~3`), как запись `VAR`,
  затем u32 R, ссылки, заголовок и значения Range тега — установлено
  дополнительными опытами 16 ноября 2026, см. ниже.

Условия I/O field из `VIEW_DARK` читает `FieldConditionReader`: роли
Visibility и Control enable установлены на контрольных копиях V21 TP700
([анимации поля](анимации-поля-ввода-вывода.md)). Остальные перечисленные
элементы этот читатель не обрабатывает; Range тегов читает отдельный парсер.

## Range HMI-тега

Установлено на контрольных FWC TIA V21 Update 1, TP700 Comfort и XML A603:
`data/real/iofield-range-20261116/`. Сверены 42 FWC с XML, 16 сочетаний
постоянных границ DInt, отдельные и общие ссылочные границы, три режима
I/O field и тег без объекта на экране. Другие версии TIA и несколько языков
для Range не проверены.

Ранние наблюдения: оба LIMIT, именованный и без имени, хранят пределы тега.
У 7 тегов A603A0097 два предела Lower 2 / Upper 2 совпали с XML (типы 2 i16
и 5 f64); на шаге 66 четыре границы типа 3 записаны в порядке Lower 2,
Upper 2, Lower 1, Upper 1. В безымянных записях видели слова заголовка
`03 27 03 00` при двух пределах и `83 a7 0f 00` при четырёх. Их связь
с составом границ остаётся гипотезой; описанный ниже читатель разбирает
именованные записи.

`TagRangeParser` читает именованные LIMIT (первое u16 — 3). Первая ссылка
задаёт владельца VAR; имя LIMIT не используется для сопоставления.
`TagRangeReferences` разрешает VAR, посредники ADAPTLOOPBREAKE (до трёх;
у Diag_SelectIn A603 проверен один) и ссылку с Id таблицы 0 на предыдущую
ссылку того же элемента. Range хранится в `HmiTag.Range` независимо от
наличия I/O field.

Раскладка от конца ссылок E — установлена на этих файлах:

| Смещение | Содержимое |
|---|---|
| E+0x00…0x07 | Заголовок; остальные служебные поля не интерпретируются |
| E+0x02 u16 | Маска постоянных границ: 0x01 Upper 2, 0x02 Lower 2, 0x04 Upper 1, 0x08 Lower 1 |
| E+0x08 | По 0x10 байт на установленный бит, порядок: Lower 2, Upper 2, Lower 1, Upper 1 |

Размер записи должен точно совпадать с E + 0x08 + числом постоянных границ
× 0x10; неизвестные биты маски не принимаются. Значение: u16 тип, u16 0,
u32 0, данные на +0x08. Читаются типы 2 (i16), 3 (i32), 5 (f64), 0x12
(u16), 0x13 (u32); нечисловые и бесконечные значения отклоняются.

Ссылочная граница не занимает блок постоянного значения. В дополнительной
ссылке первое служебное слово равно 0, второе задаёт границу:

| Второе слово | Граница |
|---|---|
| 0x0f | Lower 2 |
| 0x0e | Upper 2 |
| 0xaf | Lower 1 |
| 0xb0 | Upper 1 |

Обратная ссылка владельца Diag_SelectIn A603 со словами 6, 0x8006
пропускается, только если разрешается в тот же VAR. Повтор одной границы,
неизвестная роль, неразрешимый тег или разные Range одного владельца —
ошибка формата с таблицей и смещением. Запись без разобранных границ тоже
отклоняется. Если владелец уже определён, его Range помечается
непрочитанным; после ошибки внутри записи парсер переходит к следующей.

В окне HMI tags → свойства → Range показаны число или имя тега, Const/Tag.
Выключенная граница — «не задано», нет именованного LIMIT — «нет данных
в FWC», ошибка — «не прочитано» и предупреждение. Отсутствие LIMIT не
доказывает отсутствие Range в проекте: это проверено на неиспользуемом теге.
В Limits I/O field остаются цвета; Excel не изменён.

## Visibility экрана в программе

- `LimitParser` читает только элементы, на которые ссылаются записи `SCREEN` (не служебные),
  после разбора `SCREEN`; результат — `FwxDocument.ScreenVisibilities`. Нет
  таблицы — Visibility нет, без сообщения.
- Элемент экрана короче 8 байт, первое u32 не 1, R = 0 или больше 0x20, ссылки
  и значения не помещаются, ссылка ведёт за последний элемент, элемент выходит
  за таблицу, его запись каталога смещений выходит за файл или даёт
  отрицательную длину — предупреждение с таблицей и смещением, у этого экрана
  Visibility не прочитана, остальные экраны читаются (каждый элемент читается по
  номеру, без обхода каталога; решение пользователя 2026-10-26). Если на
  испорченный элемент ссылаются несколько экранов, одинаковое предупреждение
  выдаётся на каждый. Элементы, на которые экраны не ссылаются, и их записи
  каталога проверяет общая проверка раскладки таблиц; условия I/O field
  дополнительно читает `FieldConditionReader`.
- Тип значения не 5 и не 2 — значение не читается, предупреждение
  `LIMIT: запись N @ 0x…: тип значения From 0x… не известен`, элемент остаётся.
- Лист «Экраны»: колонки `Visibility tag` (имя тега), `Visibility from`,
  `Visibility to` (числом, дробное — текстом), `Visibility` (`Visible` /
  `Invisible`). Ссылки на `LIMIT` нет — пусто; ссылка есть, элемент не прочитан
  — `?` во всех четырёх; ссылка тега не на `VAR` или записи нет — `?` в
  `Visibility tag`, без предупреждения; значение не прочитано — `?`.
