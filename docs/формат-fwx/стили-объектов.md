# Стили объектов — PS_BorderedShap, PS_Text, PS_Fill_Color, FONT

Цвета, рамка, выравнивание и шрифт объекта лежат не в его элементе, а в общих
таблицах стилей: элемент объекта ссылается на запись каждой. Одинаковые
сочетания значений — одна запись; новая появляется только при новом сочетании
(шаг 15: фон 255, 0, 0 — новая запись `PS_Fill_Color` 9 вместо 8). Программа
читает их в `Parsing/Panel/Screens/` (`BorderStyleReader`, `TextStyleReader`,
`FillStyleReader`, `FontReader`, общий `StyleElement`); пока — только для I/O
field ([поле-ввода-вывода.md](поле-ввода-вывода.md)).

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md).
Проверено на шагах `data/real/steps-iofield/` 15–32, 41–45 и 48 (Project1, V21,
TP700 Comfort) и на 105 полях A603A0097 против выгрузки Openness. Таблица по
ссылке выбирается по Id из TOC: имена таблиц не уникальны (две
`PS_BorderedShap`).

## PS_BorderedShap (64 байта)

| Смещение | Поле | Статус |
|---|---|---|
| +0x14 | u16 Style: 1 — одинарная линия (Solid, а также Dash, Dot, DashDot, DashDotDot — один код), 2 — Double line | установлено |
| +0x16 | u16 Border width | установлено |
| +0x18 | R, G, B, 0 — Border color | установлено |
| +0x1c | R, G, B, 0 — Border background color | установлено |
| +0x20 | 4 × u16 Corner radius (всегда равны; TIA задаёт один) | установлено |
| +0x3a | u16 Id `TILED_PICTURE` (0x15c) и u16 номер элемента — картинка рамки (PNG 23×23 у поля шагов 70–72); картинки нет — `ffff 0000` (запись 0) | наблюдение (шаги 70b–72), программа не читает |
| остальное | не разобраны | — |

## PS_Text (32 байта)

| Смещение | Поле | Статус |
|---|---|---|
| +0x14 | R, G, B, 0 — цвет текста | установлено |
| +0x18 | байт по горизонтали: 0 Right, 1 Center, 2 Left | установлено |
| +0x19 | байт по вертикали: 0 Top, 1 Middle, 2 Bottom | установлено |

## FONT — шрифты по языкам Runtime

Установлено на одноязычных копиях Project1 и трёхъязычном опыте
`data/real/iofield-compatibility-20261115/` (TIA V21 Update 1, TP700 Comfort,
Runtime 17.0.0.0): элемент содержит заголовок и отдельный шрифт каждого языка.
Для English, Deutsch и русского подтверждены различающиеся размеры и
начертания. Обратный XML, FWC, `font-records.json` и
`font-fix-verification.json` находятся в каталоге опыта вне git.
Другие версии редактора TIA этим опытом не проверены.

| Смещение от начала элемента | Поле | Статус |
|---|---|---|
| +0x0a | u16 число языковых записей N | установлено при N = 1 и N = 3 |
| +0x0c | начало первой языковой записи R | установлено |
| +0x10 | u32 LCID первого языка, например `0x409` | установлено; прежнее указание +0x14 было ошибочным |

Установленная раскладка записи относительно R:

| Смещение | Поле | Статус |
|---|---|---|
| R+0x00 | u32 длина данных L, в проверенных записях `0x60` | установлено на контрольных файлах |
| R+0x04 | u32 LCID: `0x409`, `0x407`, `0x419` | установлено |
| R+0x08 | начало данных шрифта; непрочитанные поля не интерпретируются | наблюдение |
| R+0x10 | u32 высота = Font size × 7500 | установлено: размеры 16, 18 и 20 |
| R+0x18 | u16 вес: 400 Regular, 700 Bold | установлено |
| R+0x1c | u32 1 — Italic | установлено |
| R+0x20 | u32 1 — Underline | установлено |
| R+0x24 | u32 1 — Strikeout | установлено переключением в TIA и повтором |
| R+0x28 | имя UTF-16LE до нуля или конца языковой записи | установлено |

Следующая запись начинается на `R + 0x08 + L`. Одноязычный элемент имеет
116 байт, трёхъязычный — 324 байта при L = `0x60`.
`FontReader` сохраняет полные записи как LCID и `PanelFont` в `IoField.Fonts`;
`IoField.Font` остаётся первым шрифтом для прежних вызовов. Неполный или
выходящий за элемент дополнительный хвост остаётся неразобранным без нового
предупреждения; первый шрифт читается с прежней проверкой минимальной длины.
Повреждённые дополнительные записи контрольным опытом не проверены.

В окне язык выбирает шрифт и для холста, и для **Text format → Font**.
«Все языки», отсутствующий LCID или поле без языковых записей возвращают
первый шрифт FONT. Кеш ширин цифр различает выбранные шрифты.

Шрифт Arial TIA при компиляции заменяет на `Tahoma` (шаг 32 и немецкая
запись трёхъязычного опыта); Courier New записывает как есть. Окно использует
имя из FWC, а не исходное имя из XML.
