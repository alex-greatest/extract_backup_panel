# MSG_ANALOG_OBSE — пределы аналоговых алармов

Предел аналогового аларма: значение или тег предела, Limit mode и связь с
тегом срабатывания. Программа читает таблицу в
`Parsing/Panel/Alarms/MsgAnalogObseParser.cs`. Сам аларм — в `MSG_ANALOGCREAT`
([таблица-msg-analogcreat.md](таблица-msg-analogcreat.md)), связь — по ID.

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md).
Проверено на тех же шаговых копиях A603A0097 (V21), что и `MSG_ANALOGCREAT`;
таблица появляется только вместе с первым аналоговым алармом.

## Элемент

`Id` = 0x108. Элемент на **аларм**, а не на тег срабатывания: два аларма на
одном теге лежат в разных элементах.

| Смещение | Значение | Статус |
|---|---|---|
| +0x00 u32 | 1 во всех элементах | наблюдение, не разобрано |
| +0x04 u32 | R — число ссылок (1 или 2) | установлено на файлах |
| +0x08 | R ссылок по 8 байт: u16 Id таблицы, u16 номер элемента, два u16 | установлено на файлах |
| дальше u16 | **ID** аларма | установлено: ID 1 → 7 |
| u8 | **Limit mode**: 1 — Higher, 0 — Lower | установлено: Higher ↔ Lower в обе стороны |
| u8 | вид значения предела | 1, 2, 3 установлены, 0 — гипотеза, см. ниже |
| u32, у вида 3 — 8 байт | **значение** предела-константы; у предела-тега 0 | установлено: 100 → 200; float64 — на Project1 |

Ссылки идут **в разном порядке** (в одной копии поменялись местами), поэтому
программа узнаёт их по Id таблицы:

- `(0x123 MSG_ANALOGHANDL, 0, 0x4e, 0x8000)` — есть всегда; не разобрана;
- `(0x1 VAR, n, 0, 0x1a)` — **тег предела**, запись `VAR` номер n с нуля; есть
  только у предела-тега (установлено: `DB_ST7_Cylinders_BLOCKADES_Y5_BLOCK_NR`).

## Вид значения

| Байт | Аларм, тег срабатывания | Limit в TIA | Значение |
|---|---|---|---|
| 1 | ID 1, Int | 50 | u32 `0x32` |
| 2 | ID 2, Real | 12.5, затем 13 | float32 `0x41480000`, `0x41500000` |
| 0 | ID 3, UInt | 555 | u32 `0x22b` |
| 0 | ID 7, Int | тег | 0 |
| 1 | Project1 ID 4, Int | -7 | u32 `0xfffffff9` |
| 1 | Project1 ID 5, DInt | 1000 | u32 `0x3e8` |
| 2 | Project1 ID 7, Real | 10 | float32 `0x41200000` |
| 3 | Project1 ID 6, LReal | 1.5 | float64 `00 00 00 00 00 00 f8 3f` — 8 байт, элемент на 4 байта длиннее |

Байт задаёт тип значения, а не то, константа это или тег: 1 — целое со знаком
(установлено: Int `-7`, DInt `1000`), 2 — float32, 3 — float64 на 8 байт
(установлено на шаговой копии Project1, V21); 0 — целое без знака — гипотеза (у
предела-тега тоже 0). Остальные типы не проверены; незнакомый байт программа
выводит как `?`.

## Тег срабатывания

Тег срабатывания — HMI-тег, в записи `VAR` которого есть ссылка
`(0x108, номер элемента, 0, 0x8019)`; на каждый аларм тега — своя ссылка
(установлено: у `DB_ST7_A603_SQL_COMM_TRACE_O_FB_Active_State` две — алармы 7 и
1). Флаг `0x8019` тот же, что у ссылки тега срабатывания дискретного аларма на
`AREAPTR`. Одновременно в записи `VAR` растёт счётчик в последней ссылке
`(0, n, …)`.

У нового тега срабатывания `DB_ST7_Analog_Channel_2_Value` в элементе
`DATALINK_READWR` байт у конца сменился `0x07` → `0x1f` — наблюдение, не
разобрано, на вывод не влияет.

## Что делает программа

- Читает все элементы; каждый предел сразу добавляется в документ.
- Длина элемента не равна 8 + 8·R + 8 или R больше 0x20 — `FwxFormatException`
  с таблицей и смещением: предупреждение, код 1. Пределы до сбоя выводятся; у
  алармов без предела Trigger tag, Limit и Limit mode — `?`.
- Limit на листе: имя тега предела; иначе целое — числом, float — текстом
  (`12.5`, `13`, как в TIA). Limit mode — `Higher`, `Lower`, незнакомый — `?`.
- Ни один тег `VAR` не ссылается на элемент — Trigger tag `?`.

Данные ПЛК для листа не нужны: тег срабатывания и тег предела — HMI-теги
панели, а адреса в таблице Analog alarms TIA нет.
