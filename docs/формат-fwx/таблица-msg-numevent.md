# MSG_NUMEVENT — дискретные алармы

Дискретные алармы панели (в TIA: HMI alarms → Discrete alarms): ID, текст,
класс, Report и поля вывода в тексте. Программа читает таблицу в
`Parsing/Panel/MsgNumEventParser.cs`. Класс аларма — номер записи в
`MSG_NUMHANDLER` ([таблица-msg-numhandler.md](таблица-msg-numhandler.md)),
теги срабатывания и квитирования — в `AREAPTR`
([таблица-areaptr.md](таблица-areaptr.md)), тексты — в `STRINGSTORE`
([таблица-stringstore.md](таблица-stringstore.md)).

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md):
установлено на файлах, наблюдение, гипотеза.

## На чём проверено

| Файлы | TIA, панель | Языки | Алармов |
|---|---|---|---|
| A603A0097 (`A603A0097_V21`), шаговые копии 10–12.10.2026 | V21, TP1900 Comfort | English, русский, polski | 352 → 355 |
| `samples/card/pdata.fwc` (бэкап CCB-A13) | Runtime V17, TP1500 Comfort | русский | 2000 |
| Project1 (`samples/pdata.fwc`, `samples/plc/`) | V17, V21 | English | таблицы нет |

На A603A0097 владелец по шагам менял в TIA по одному свойству (имя, класс,
Report, тег срабатывания, квитирование HMI и PLC, теги-массивы), после каждого
шага панель компилировалась; лист сверен со списком Discrete alarms из TIA. У
CCB-A13 проекта TIA нет: проверена только согласованность (все 2000 ID есть в
`AREAPTR`).

## Элемент

`Id` = 0x1c. Элемент на аларм, в порядке создания алармов, а не по ID
(наблюдение: ID 40, 99, 194 — в конце, как в TIA).

| Смещение | Значение | Статус |
|---|---|---|
| +0x00 u32 | 0 во всех файлах | наблюдение |
| +0x04 u32 | R — число ссылок, по две на поле вывода (0, 2, 4) | установлено на файлах |
| +0x08 | R ссылок по 8 байт: u16 Id таблицы, u16 номер элемента, два u16 | установлено на файлах |
| дальше u32 | номер строки **текста** аларма в `STRINGSTORE`, один для всех языков | установлено на файлах |
| u32 | номер второй строки: имя соединения панели (`HMI_ST7`, `HMI1`) у всех алармов | наблюдение; не выводится |
| u16 | **ID** аларма | установлено на файлах |
| u8 | младшие 5 бит — **номер класса** в списке `MSG_NUMHANDLER`; старшие 3 — число полей (R/2) | установлено на файлах |
| u8 | бит `0x40` — **Report = On** | установлено: у аларма 1 включён только Report |
| u16 на поле | код поля, затем нули до кратности 4 | см. ниже |

Элемент кончается ровно после кодов полей.

Вторая строка у всех алармов A603A0097 — `HMI_ST7`, у CCB-A13 — `HMI1`; так
называется единственное соединение каждой панели. Info text здесь ни при чём:
у аларма 1 он пустой. Гипотеза: соединение тега срабатывания; проверить нельзя,
в обоих проектах соединение одно.

## Поля вывода

В тексте `STRINGSTORE` поле — метка из четырёх символов: ESC, `T`, номер поля
с единицы, `0xFF` (`1B 54 01 FF`). На поле две ссылки:

- первая — элемент `DATALINK` (Id 0x9): связь тега поля с ПЛК. У поля
  текстового списка бывает `0` (аларм 30, поле 2);
- вторая — `00 00 nn 00 00 00 19 00` / `… 1a 00`; не разобрана.

Связь в `DATALINK` — отдельная копия связи HMI-тега: путь символа (или адрес)
совпадает со связью тега в `DATALINK_READWR`, отличаются цикл и служебные байты.
По совпадению находится имя тега поля: у аларма 30 —
`DB_ST7_Axis_Axis_Receive_FAULT_CODE`, как в TIA (установлено на одном поле).

Код поля: бит `0x8000` — поле текстового списка, иначе поле тега. У поля тега
младший байт — длина поля (аларм 30: `0x7906` → 6, в TIA `<Tag : 6, …>`;
установлено на одном поле, старший байт `0x79` не разобран). У поля списка
младший байт 0, 1, 2, 3 — гипотеза: номер текстового списка в панели.

Имени текстового списка в `pdata.fwc` нет (строки `SINAMICS_S120_FW5.2` нет
ни в UTF-16, ни в ASCII), есть только его тексты. TIA показывает поля так:
`<Tag : 6, DB_ST7_Axis_Axis_Receive_FAULT_CODE><Text list, SINAMICS_S120_FW5.2>`,
`<Text list, Trace_FB_Status>, <Text list, Trace_FB_State>`.

## Что делает программа

- Читает все элементы по порядку; каждый аларм сразу добавляется в документ.
- Длина элемента не сходится с R, R нечётно или больше 0x20, число полей в байте
  класса не равно R/2 — `FwxFormatException` с таблицей и смещением элемента:
  предупреждение, код 1, алармы до сбоя выводятся.
- Лист «Дискретные алармы» в `panel_data.xlsx`: ID, текст на каждом языке с
  подписями полей (`<Tag : 6, имя>`, `<Text list, ?>`), класс, теги, биты,
  адреса, Report; строки по возрастанию ID.

## Чего в pdata.fwc нет

Имени аларма (Name: `DiscreteAlarm_1`), имени текстового списка и имени
своего класса. Их нет и в ПЛК — ни в `PEData.plf`, выгруженном с ПЛК, ни на
карте ПЛК (проверено: `Project1_upload`, карта CCB-A03 целиком). Есть только в
`PEData.plf` исходного проекта TIA с панелью
([../формат-plf/алармы-hmi.md](../формат-plf/алармы-hmi.md)).
