# Таблица VAR

`VAR` — теги HMI: одна запись на тег. Программа читает из неё имя, код типа
и число элементов и пишет их на лист «Теги» в `panel_data.xlsx`.

Раскладка установлена на реальных файлах TIA Portal V17 / TP700 Comfort:
14 пошаговых копий `pdata.fwc`, в каждой следующей добавлен один
внутренний тег известного типа (`data/real/steps/`; последняя скопирована в
`samples/pdata.fwc`), и `data/real/pdata.fwc` — более раннее состояние
проекта с тегами `Tag_*` и двумя другими массивами. Во всех 15 файлах
раскладка сходится на каждой записи без исключений. Все теги в этих файлах —
внутренние (Connection `<Internal tag>`); PLC-теги ещё не исследовались.

Соседние документы: [общая-структура.md](общая-структура.md),
[таблица-stringstore.md](таблица-stringstore.md).

## Таблица

Обычная таблица с каталогом смещений: заголовок 0x34 → каталог → блок
данных (см. [общая-структура.md](общая-структура.md)). В
`samples/pdata.fwc`: `Id` 0x1, смещение 0x98, 16 элементов, 768 байт.
Таблицы `DATALINK_READWR` во внутреннем проекте нет.

## Запись

`p` — начало записи, `n` — длина имени в символах.

| Смещение | Разм. | Значение | Статус |
|---|---|---|---|
| p+0x00 | 2 | всегда `3` | наблюдение |
| p+0x02 | 2 | `n` — длина имени в символах | установлено |
| p+0x04 | 2n | имя тега, UTF-16LE, без нуля | установлено |
| p+0x04+2n | — | нули: до кратности 4 от `p`, затем ещё 4 байта | наблюдение |
| t+0x00 | 2 | код типа | установлено |
| t+0x02 | 2 | число элементов | установлено |
| t+0x04 | 4 | `Data4` | гипотеза: смещение значения в буфере тегов |
| t+0x08 | 4 | всегда `0` | наблюдение |

Начало хвоста `t = p + align4(4 + 2n) + 4`. Хвост — 12 байт и кончается
ровно на конце элемента.

Пример, `Tag_Int` из `samples/pdata.fwc`:

```
03 00                          3
07 00                          n = 7
54 00 61 00 67 00 5f 00        "Tag_Int"
49 00 6e 00 74 00
00 00 00 00 00 00              нули: 0x12 → 0x14, затем ещё 4
02 00                          код 0x0002 = Int
01 00                          1 элемент
06 01 00 00                    Data4 = 0x106
00 00 00 00                    0
```

## Коды типов

Каждый код подтверждён тегом, тип которого виден в колонке Data type в TIA.

| Код | Тип | | Код | Тип |
|---|---|---|---|---|
| 0x02 | Int | | 0x0b | Bool |
| 0x03 | DInt | | 0x10 | SInt |
| 0x04 | Real | | 0x11 | USInt |
| 0x05 | LReal | | 0x12 | UInt |
| 0x07 | DateTime | | 0x13 | UDInt |
| 0x08 | WString | | | |

Это все типы из выпадающего списка Data type в TIA V17 для внутреннего тега
Comfort (по скриншоту владельца; байтами это не проверяется).

**Массив** — бит `0x2000` в коде типа. Подтверждены `0x200b` (Array of
Bool), `0x2005` (Array of LReal) и `0x2002` (Array of Int) в пошаговых
файлах, `0x2007` (Array of DateTime) — в `data/real/pdata.fwc`. Число
элементов у массива `[0..22]` равно 23; в `data/real/pdata.fwc` у
`[0..88]` — 89, у `[0..33]` — 34.

Нижняя граница в записи не хранится. TIA не даёт задать её у HMI-тега:
тег, заданный как `[5..22]`, TIA сохранил с типом `Array [0..22] of Int`, а в
записи только 23. Поэтому программа выводит `Array [0..N-1] of <тип>`.

## Что наблюдается, но не используется

- **Порядок записей не совпадает с порядком добавления тегов.** Например,
  `DateTime` стоит раньше `Bool`. Поле `Data4` растёт строго по порядку
  записей. Гипотеза: записи упорядочены по смещению значения в буфере.
- **`Data4` у одного тега меняется между компиляциями:** у `Bool` сначала
  `0x10c`, потом `0x11a`. Это вычисляемая раскладка, а не идентификатор.
- **`Data4` плюс размер значения последнего тега равно размеру буфера
  значений** — полю заголовка `PostTablesPadding1` (см.
  [общая-структура.md](общая-структура.md)). Это основание гипотезы
  «`Data4` — смещение значения в буфере». Шаг между соседними тегами не
  равен размеру типа: между значениями есть промежутки (например, Real
  0x134 → UDInt 0x13c). Их правило не установлено.
- **`@DiagnosticsIndicatorTag`** (SInt) есть в каждом файле, хотя в таблице
  HMI tags TIA его нет. Это скрытый системный тег; выводится как обычный.

## Как программа обрабатывает запись

- Запись выходит за пределы таблицы `VAR` (каталог указывает в соседнюю
  таблицу), первое слово не 3, длина записи не сходится с длиной имени, между
  именем и хвостом не нули, последнее слово не 0, массив с 0 элементами —
  ошибка формата. Это предупреждение с кодом возврата 1; теги, прочитанные до
  сбоя, остаются в выводе.
- Неизвестный код типа, в том числе с другими старшими битами, — `?` в
  колонке Data type, без предупреждения.

## Чего мы не знаем

- Как выглядят PLC-теги: первое слово, связь с `DATALINK_READWR`, адрес.
- Где лежат Acquisition cycle, Logged, Comment, Source comment и Access
  mode. В записи `VAR` их нет.
- Что означает `Data4`.
- Совпадают ли коды у других версий TIA и других панелей.
