# Таблица VAR

`VAR` — теги HMI: одна запись на тег. Программа читает из неё имя, код типа
и число элементов и пишет их на лист «Теги» в `panel_data.xlsx`.

Раскладка установлена на реальных файлах TIA Portal V17 / TP700 Comfort:
14 пошаговых копий `pdata.fwc`, в каждой следующей добавлен один
внутренний тег известного типа (`data/real/steps/`; последняя скопирована в
`samples/pdata.fwc`), и `data/real/pdata.fwc` — более раннее состояние
проекта с тегами `Tag_*` и двумя другими массивами. Во всех 15 файлах
раскладка сходится на каждой записи без исключений. Все теги в этих файлах —
внутренние (Connection `<Internal tag>`); PLC-теги ещё не исследовались.

Запись PLC-тега разобрана позже на копиях TIA V21 (`data/real/steps-v21/`)
и проекте `A603A0097_V21`, см. раздел «Запись PLC-тега».

Соседние документы: [общая-структура.md](общая-структура.md),
[таблица-stringstore.md](таблица-stringstore.md),
[таблица-datalink-readwr.md](таблица-datalink-readwr.md).

## Таблица

Обычная таблица с каталогом смещений: заголовок 0x34 → каталог → блок
данных (см. [общая-структура.md](общая-структура.md)). В
`samples/pdata.fwc`: `Id` 0x1, смещение 0x98, 16 элементов, 768 байт.
Таблицы `DATALINK_READWR` во внутреннем проекте нет.

## Запись

`p` — начало записи, `n` — длина имени в символах.

| Смещение | Разм. | Значение | Статус |
|---|---|---|---|
| p+0x00 | 2 | всегда `3` | наблюдение |
| p+0x02 | 2 | `n` — длина имени в символах | установлено |
| p+0x04 | 2n | имя тега, UTF-16LE, без нуля | установлено |
| p+0x04+2n | — | нули: до кратности 4 от `p`, затем ещё 4 байта | наблюдение |
| t+0x00 | 2 | код типа | установлено |
| t+0x02 | 2 | число элементов | установлено |
| t+0x04 | 4 | `Data4` | гипотеза: смещение значения в буфере тегов |
| t+0x08 | 4 | всегда `0` | наблюдение |

Начало хвоста `t = p + align4(4 + 2n) + 4`. Хвост — 12 байт и кончается
ровно на конце элемента.

Пример, `Tag_Int` из `samples/pdata.fwc`:

```
03 00                          3
07 00                          n = 7
54 00 61 00 67 00 5f 00        "Tag_Int"
49 00 6e 00 74 00
00 00 00 00 00 00              нули: 0x12 → 0x14, затем ещё 4
02 00                          код 0x0002 = Int
01 00                          1 элемент
06 01 00 00                    Data4 = 0x106
00 00 00 00                    0
```

## Коды типов

Каждый код подтверждён тегом, тип которого виден в колонке Data type в TIA.

| Код | Тип | | Код | Тип |
|---|---|---|---|---|
| 0x02 | Int | | 0x0b | Bool |
| 0x03 | DInt | | 0x10 | SInt |
| 0x04 | Real | | 0x11 | USInt |
| 0x05 | LReal | | 0x12 | UInt |
| 0x07 | DateTime | | 0x13 | UDInt |
| 0x08 | WString | | | |

Это все типы из выпадающего списка Data type в TIA V17 для внутреннего тега
Comfort (по скриншоту владельца; байтами это не проверяется).

**Массив** — бит `0x2000` в коде типа. Подтверждены `0x200b` (Array of
Bool), `0x2005` (Array of LReal) и `0x2002` (Array of Int) в пошаговых
файлах, `0x2007` (Array of DateTime) — в `data/real/pdata.fwc`. Число
элементов у массива `[0..22]` равно 23; в `data/real/pdata.fwc` у
`[0..88]` — 89, у `[0..33]` — 34.

Нижняя граница в записи не хранится. TIA не даёт задать её у HMI-тега:
тег, заданный как `[5..22]`, TIA сохранил с типом `Array [0..22] of Int`, а в
записи только 23. Поэтому программа выводит `Array [0..N-1] of <тип>`.

## Запись PLC-тега

Найдено на копиях TIA V21 / S7-1500 (`data/real/steps-v21/`) и на
реальном проекте `A603A0097_V21` (527 записей, 3 языка). Статусы
«установлено на файлах» / «наблюдение» / «гипотеза» — как в
[таблица-datalink-readwr.md](таблица-datalink-readwr.md).

**Единая грамматика** (установлено на всех 527 записях A603 и всех копиях):
после имени и нулей до кратности 4 идёт **u32 N — число ссылок**, затем N
ссылок по 8 байт `[u16 Id таблицы][u16 номер элемента][u16][u16]`, затем
хвост 12 байт. «4 нулевых байта» у внутреннего тега — это N = 0.

| Ссылки | Записей в A603 | Что это |
|---|---|---|
| N = 0 | 8 | внутренний тег |
| `(0x35, i, 0, 0x80e3) (0, 0, 0, 0x00e3)` | 489 | PLC-тег: ссылка на `DATALINK_READWR[i]` и завершающая |
| `(0x32, …) (0x35, i, …) (0, 1, 0, 0xe3)` | 22 | то же + указатель аварий (AREAPTR) |
| `(0x34, 0, 6, 6) (0x35, …) (…)` | 1 | ссылка на SYMB, смысл не установлен |
| `(0x35, …) (0, 0, 0, 0xe3) (0x27, i, 0x34, 0x8000)` | 6 | + обратная ссылка из ADAPTLOOPBREAKE |
| `(0x09, 0x0b, 0, 0) (0, 0, 0, 0x8000)` | 1 | `Screen Number`: указатель области, ссылка на `DATALINK[11]` |

Первое слово блока у PLC-тега — 2 или 3. Программа берёт ссылку на
`DATALINK_READWR` (Id таблицы — из TOC), а остальные не использует. Тег со
ссылкой только на другую таблицу (`Screen Number`) попадает в лист, но
данные ПЛК для него «неизвестно».

Хвост — как у внутреннего тега, но **код типа = код типа HMI | 0x80**
(Bool `0x8b`, Int `0x82`, массив — ещё и 0x2000) — установлено на 518 из 518
связей A603. Число элементов совпадает с числом в `DATALINK_READWR`.

Пример `Word_IW46` (`01_bound`), блок после имени:

```
02 00 00 00 | 35 00 2e 00 00 00 e3 80 | 00 00 00 00 00 00 e3 00
```

Порядок элементов `DATALINK_READWR` меняется от компиляции к компиляции
(в копии A603 индексы разные у 517 из 527 тегов): связывать только по
ссылке из записи.

## Раскладка значений в буфере

`Data4` — смещение значения тега в буфере значений сразу после таблиц (см.
[общая-структура.md](общая-структура.md)). Правило для скалярных тегов,
проверено на 21 файле (14 копий V17, `samples/pdata.fwc`, 6 копий V21) без
расхождений — установлено на файлах.

Теги берутся в порядке возрастания `Data4`. Для тега с размером значения `S`
и выравниванием `A = min(S, 8)`:

```
Data4 = floor_A(Data4_предыдущего + S_предыдущего + S)
```

То есть перед значением тега лежит область размером с само значение
(назначение неизвестно), а значение выравнивается вниз до кратного `A`.
Размер `S` по коду типа HMI: Bool 2, SInt/USInt 1, Int/UInt 2,
DInt/UDInt/Real 4, LReal/DateTime 8.

- Пример: после `Date_QW4` (0x7f0, S=8) тег `Date_MW12` лежит на
  0x7f0 + 8 + 8 = 0x800.
- `PostTablesPadding1` в заголовке = конец значения последнего тега.
- Строки и массивы правилом не покрыты: зазоры перед ними 6, 8, 30, 32, 46
  байт, правило не найдено.
- Значение по умолчанию у DateTime, Date, LDT, Time_Of_Day,
  LTime_Of_Day — double 1.0 (`00 00 00 00 00 00 f0 3f`), у остальных нули —
  наблюдение.

## Что наблюдается, но не используется

- **Порядок записей не совпадает с порядком добавления тегов.** Например,
  `DateTime` стоит раньше `Bool`. У внутренних тегов `Data4` растёт строго
  по порядку записей. У PLC-тегов это не так: `Word_IW46` стоит в `VAR`
  вторым среди PLC-тегов, а его `Data4` последний. Значит, гипотеза
  «записи упорядочены по смещению значения» для PLC-тегов неверна.
- **`Data4` у одного тега меняется между компиляциями:** у `Bool` сначала
  `0x10c`, потом `0x11a`. Это вычисляемая раскладка, а не идентификатор.
- **`Data4` плюс размер значения последнего тега равно размеру буфера
  значений** — полю заголовка `PostTablesPadding1` (см.
  [общая-структура.md](общая-структура.md)). Правило промежутков между
  значениями найдено, см. «Раскладка значений в буфере».
- **`@DiagnosticsIndicatorTag`** (SInt) есть в каждом файле, хотя в таблице
  HMI tags TIA его нет. Это скрытый системный тег; выводится как обычный.

## Как программа обрабатывает запись

- Запись выходит за пределы таблицы `VAR` (каталог указывает в соседнюю
  таблицу), первое слово не 3, длина записи не сходится с именем и числом
  ссылок, между именем и N не нули, последнее слово не 0, массив с 0
  элементами — запись пропускается, разбор продолжается. После таблицы одно
  предупреждение с числом пропущенных и первой причиной, код возврата 1.
- Тег со ссылкой не на `DATALINK_READWR` остаётся в выводе; одно сводное
  предупреждение с числом таких тегов, код 1.
- Неизвестный код типа, в том числе с другими старшими битами, — `?` в
  колонке Data type, без предупреждения.

## Чего мы не знаем

- Смысл 12 байт `00 00 e3 80 … e3 00` в записи PLC-тега.
- PLC-массивы, строки и структуры: код типа и раскладка.
- Где лежит Logged. Cycle, режим доступа и адрес — в
  [таблица-datalink-readwr.md](таблица-datalink-readwr.md); Comment и
  Source comment в файл не попадают.
- Правило `Data4` для строк и массивов.
- Совпадают ли коды у других версий TIA и других панелей.
