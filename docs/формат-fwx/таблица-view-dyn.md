# VIEW_DYN — высота Permanent area

Раскладка рабочей области панели; программа читает из таблицы только высоту
Permanent area (в TIA: Screen management → Permanent area → Height) — в
`Parsing/Panel/Screens/ViewDynParser.cs`. Экраны и запись `Overview` с
объектами Permanent area — [таблица-screen.md](таблица-screen.md).

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md):
установлено на файлах, наблюдение, гипотеза.

## На чём проверено

Шаговые копии Project1 (V21, TP700 Comfort,
`data/real/steps-screen-props/`): `15_overview_height` — Height Permanent area
60 → 80 (через Openness, `HmiTarget.ImportScreenOverview`); в `VIEW_DYN`
изменилось одно слово `3C 00` → `50 00`. Кроме него изменились только
`STRINGSTORE` (на одну строку больше, 0x2b5 → 0x2b6) и элемент 13
`VIEW_BUTTONS` (номер строки текста 0x2b5 → 0x2b6) — наблюдение: побочное
от повторного импорта Permanent area с кнопкой, к высоте не относится. Шаг
`14_overview_color` (цвет Permanent area) `VIEW_DYN` не меняет. Таблица есть во
всех 63 файлах `samples/` и `data/real/` (V17 и V21): один элемент 36 байт.

| Файлы | Высота | Ширина × высота панели |
|---|---|---|
| Project1 (`samples/pdata.fwc`, шаговые копии) | 60 (80 на шаге 15) | 800 × 480 |
| A603A0097 (`samples/a603/`, `steps-tooltip-langs/`) | 0 | 1366 × 768 |
| CCB-A13 (`samples/card/`) | 0 | 1280 × 800 |

После шага 15 экраны Project1 и в TIA, и в файле остались 800×420 (80 + 420 >
480): Openness-импорт Permanent area экраны не пересчитывает, а сами экраны не
пересохранялись. TIA требует высоту экрана = высота панели − высота Permanent
area: повторный импорт экрана 420 на этой копии отклоняется («The screen size
does not match the device»; наблюдение сессии our-tia-mcp). В A603A0097 и CCB-A13 Permanent area нет,
экраны — во всю панель.

## Элемент

`Id` = 0x5. Во всех файлах один элемент длиной 0x24 (36 байт); на него
ссылается объект `VIEW_DYN` 0 записи `Overview` таблицы `SCREEN`.

| Смещение | Значение | Статус |
|---|---|---|
| +0x00 u32 | всегда 1 | наблюдение |
| +0x04 u32 | R — число ссылок, во всех файлах 1 | наблюдение |
| +0x08 | ссылка: `ADAPTVALUECHANG` (0x5f) элемент 0, слова 0, 0 | наблюдение |
| +0x10 (+0x00 от конца ссылок) | u16 0, u16 0x5000 — одинаково во всех файлах | наблюдение, не разобрано |
| +0x14 u16 | 0 во всех файлах | гипотеза: левая граница рабочей области |
| **+0x16** (+0x06 от конца ссылок) u16 | **высота Permanent area** в пикселях, 0 — Permanent area нет | установлено на файлах |
| +0x18, +0x1a u16 | ширина и высота панели; равны размеру записи `Overview` в `SCREEN` и размеру панели в `GUI` | наблюдение |
| +0x1c u32 | 0 | наблюдение |
| +0x20 u16, +0x22 u16 | номер записи `SCREEN` (с нуля) и Id `SCREEN` (7): запись стартового экрана | наблюдение: шаг `steps-screens/01` (стартовый `Screen_2`) — 1 → 3, A603A0097 — 0x31 |

## Что делает программа

- Читает только высоту Permanent area из элемента, на который ссылается
  пара объектов записи `Overview` (SCREEN, запись 0) с Id `VIEW_DYN`. Пары нет
  или она ведёт за последний элемент — `FwxFormatException` со смещением
  таблицы: предупреждение, высота «неизвестно».
- Нет таблицы — высота «неизвестно», без сообщения (как у `GUI`). Нет записи
  `Overview` (SCREEN нет или её разбор оборвался раньше — об этом предупреждает
  SCREEN) — тоже без своего сообщения.
- Элемент короче 8 байт, R > 0x20, ссылки или высота не помещаются в элемент —
  `FwxFormatException`: предупреждение с таблицей и смещением, высота
  «неизвестно».
- Лист «Экраны»: у строки Permanent area Height — эта высота (у записи
  `Overview` в `SCREEN` размер всей панели), не прочитана — `?`. Width — из
  записи `SCREEN`.
- Окно: Permanent area на холсте — полоса этой высоты; над обычными экранами —
  затемнённая полоса её цвета, как в редакторе экранов TIA (высота 0 или не
  прочитана — полосы нет, на месте Permanent area — подсказка).
