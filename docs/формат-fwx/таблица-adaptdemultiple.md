# ADAPTDEMULTIPLE — условие и событие Cleared

Элемент «ссылка + значение». Через него экран ведёт к функциям события
Cleared; на него же ссылается список Loaded ([таблица-func-list.md](таблица-func-list.md)).
Программа читает только элементы, на которые ссылается экран
(`Parsing/Panel/Screens/FunctionListReader.Cleared`).

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md).
Проверено на тех же копиях, что `FUNC_LIST`.

## Элемент

| Смещение | Значение | Статус |
|---|---|---|
| +0x00 u32 | 0 | наблюдение, не проверяется |
| +0x04 u32 | R = 1 | наблюдение (во всех файлах) |
| +0x08 | ссылка 8 байт | установлено |
| за ссылкой u32 | значение | наблюдение |

Два вида элементов (наблюдение):

| Ссылка | Значение | Назначение |
|---|---|---|
| `VARSYS` (0x71) CurScreen, слова без флага | номер экрана | условие Loaded (гипотеза: «текущий экран = N»), не читается |
| `FUNC_LIST` или одна `FUNC_*`, слово 4 `0x8000` | 0 | **Cleared**: список или одна функция — установлено (шаги 10, 11, 13; `300_Service` A603A0097) |

Cleared с одной функцией идёт без `FUNC_LIST` — прямо на `FUNC_*`
(шаг 10, A603A0097); с двумя и больше — через `FUNC_LIST` с R = 0 (шаг 11).
Элементы `ADAPTDEMULTIPLE` с `FUNC_QUITMSG` и `FUNC_MSGWIN` есть и в пустом
проекте (системные, не читаются).

## Как читает программа

- Первая ссылка экрана на `ADAPTDEMULTIPLE` — Cleared; ссылка элемента на
  `FUNC_LIST` — функции списка, на другую таблицу — одна функция.
- Ссылка за последний элемент (в сообщении — имя экрана), элемент вне
  таблицы, R не 1, Id таблицы ссылки нет в TOC, ссылка ведёт не на
  `FUNC_LIST` и не на таблицу `FUNC_*` — `FwxFormatException`:
  предупреждение, событие «не прочитано». Во всех 26 ссылках экранов на
  `ADAPTDEMULTIPLE` в 84 копиях (`data/real`, `samples`) цель — `FUNC_LIST`
  (17) или `FUNC_*` (9) со словом `0x8000`; элементы со ссылкой на `VARSYS`
  (577) экраны не используют.
