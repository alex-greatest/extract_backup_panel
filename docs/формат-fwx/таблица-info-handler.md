# INFO_HANDLER — тексты-подсказки

Тексты-подсказки элементов других таблиц: Tooltip экрана и объекта экрана, по
наблюдению — ещё Info text дискретного аларма. Таблица хранит только пары
«чей элемент → номер строки языков», сами тексты лежат в
[таблица-stringstore.md](таблица-stringstore.md). Программа разбирает таблицу в
`Parsing/Panel/InfoHandlerParser.cs` (`FwxDocument.InfoTexts`), но пока нигде не
выводит.

Статусы — как в [таблица-datalink-readwr.md](таблица-datalink-readwr.md):
установлено на файлах, наблюдение, гипотеза.

## На чём проверено

- Шаговые копии Project1 (V21, TP700 Comfort, `data/real/steps-screen-props/`),
  сверенные с TIA:
  - `04_tooltip` — подсказка `Screen_1`;
  - `11_object_tooltip` — ещё подсказка поля ввода-вывода;
  - `12_template_button_tooltip` — ещё подсказка кнопки шаблона;
  - `13_tooltip_ui_plain` — подсказка `Screen_2`, введённая в интерфейсе TIA.
- A603A0097 (V21, TP1900 Comfort, три языка Runtime,
  `data/real/steps-tooltip-langs/01_tooltip_langs`) — подсказка `998_LOGIN` на
  трёх языках.
- Остальные образцы `samples/` — таблица пустая (N = 0); `samples/card/pdata.fwc`
  (CCB-A13, Runtime V17) — 2000 пар на `MSG_NUMEVENT`, с TIA не сверено.

## Элемент

`Id` = 0x82. Во всех файлах один элемент; без пар его длина 44 байта.

| Смещение | Значение | Статус |
|---|---|---|
| +0x00 u16 | всегда 3 | установлено на файлах |
| +0x02 u16 | длина имени в символах (15) | установлено на файлах |
| +0x04 | имя `InfoTextHandler` UTF-16LE, нули до кратности 4 | наблюдение |
| +0x24 u32 (от конца имени +0) | во всех файлах 0, назначение неизвестно | наблюдение |
| +0x28 u32 (от конца имени +4) | N — число пар | установлено на файлах |
| +0x2c (от конца имени +8) | N ключей по 4 байта: u16 номер элемента, u16 Id таблицы | установлено на файлах |
| за ключами | N номеров строк языков по u32, в том же порядке | установлено на файлах |

Ключи и номера строк лежат двумя массивами подряд, а не парами. Порядок пар —
порядок файла; на шагах Project1 пары шли по возрастанию Id таблицы и номера
элемента (наблюдение).

## Ключ

| Id таблицы | Таблица | Что | Статус |
|---|---|---|---|
| 0x7 | `SCREEN` | подсказка экрана; номер элемента — номер записи `SCREEN` с нуля ([таблица-screen.md](таблица-screen.md)) | установлено на файлах |
| 0x2 | `VIEW_IN` | подсказка поля ввода-вывода | установлено на файлах |
| 0x17 | `VIEW_BUTTONS` | подсказка кнопки; у кнопки шаблона одна пара на все экраны (запись кнопки общая) | установлено на файлах |
| 0x1c | `MSG_NUMEVENT` | CCB-A13: элементы 0…1999 по порядку, строки с 0x387 через 3, все пустые; похоже на Info text дискретных алармов | гипотеза |

Id таблиц взяты из TOC известных файлов. У TextField подсказок нет.

## Текст

- Номер строки — `Idx` строки языка
  ([таблица-stringstore.md](таблица-stringstore.md)). На каждый язык Runtime
  своя строка с тем же номером (проверено на 0x409, 0x419, 0x415). Язык
  проекта, которого нет в Runtime, в файл не попадает. Установлено на файлах.
- Подсказка, введённая в интерфейсе TIA, хранится простым текстом: символы как
  есть, перенос строки — CRLF (`Line1 A&B <x>\r\nLine2`). Установлено на файлах.
  В интерфейсе TIA подсказка — только текст, без форматирования.
- В шаговых копиях подсказки, заданные через Openness, хранятся с разметкой
  (`<body><p>TipScreenOne</p></body>`). В реальных проектах такого не бывает:
  это след способа, которым подсказку задавали в шагах.

## Что делает программа

- Читает каждый элемент таблицы и добавляет пары в порядке файла; имя и u32 (0)
  не читаются и не проверяются.
- Нет таблицы — текстов нет, без сообщения.
- Элемент короче 4 байт, первое слово не 3, число пар, ключи или номера строк не
  помещаются в элемент — `FwxFormatException`: предупреждение с таблицей и
  смещением (`запись 1: первое слово 7, ожидалось 3`, `запись 1: 65535 текстов не
  помещаются в 44 байт`); пары не добавляются.
- Подсказки экранов (Id `SCREEN`) — колонки `Tooltip <язык>` листа «Экраны» и
  свойства экрана в окне, текст как есть; остальные тексты не выводятся.
