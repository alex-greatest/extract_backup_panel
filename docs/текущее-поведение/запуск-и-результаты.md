# Запуск и результаты

Программа читает скомпилированную конфигурацию панели из TIA Portal и
извлекает из неё теги и строки языков, а все таблицы файла сохраняет в
hex-виде. Проверено на проекте TIA Portal V17 с панелью TP700 Comfort.

## Что нужно сделать

Скомпилируйте проект в TIA. Программа читает `pdata.fwc` прямо из папки
`Generates` проекта; путь к нему и выходные пути заданы в начале
`src\FlexRt\Program.cs`, аргументов командной строки нет. Запуск из корня
репозитория или кнопкой Run в Rider:

```
dotnet run --project src/FlexRt
```

Чтобы разово прочитать другой файл, задайте переменную окружения
`FLEXRT_INPUT`, например
`FLEXRT_INPUT=samples/pdata.fwc dotnet run --project src/FlexRt`. Без неё
снова читается файл из `Generates`.

## Что видно в консоли

Для `samples\pdata.fwc` (список таблиц сокращён):

```
Файл:    samples/pdata.fwc (107372 байт)
Таблиц:  67
  0x1    VAR                      элементов: 16     offset: 0x98 size: 768
  ...
Строк языков: 625
Тегов: 16
[Языки -> XLSX] 1 языков, 625 строк -> D:\projects\extract_backup\data\out\PDATA.xlsx
[Теги -> XLSX] 16 тегов -> D:\projects\extract_backup\data\out\panel_data.xlsx
[Explode -> HEX] 264 файлов -> D:\projects\extract_backup\data\out\pdata
```

Строка таблицы — её номер, имя, число элементов, смещение и размер.

## Какие файлы получаются

`panel_data.xlsx` — лист «Теги» с колонками как в таблице HMI tags в TIA:
Name, Data type, Connection, PLC name, PLC tag, Address, Access mode,
Acquisition cycle, Logged, Source comment, Comment. Заполнены Name и Data
type; остальные колонки пока пустые. Data type пишется как в TIA: `Int`,
`Array [0..22] of LReal`. Неизвестный тип — `?`. Строки идут в порядке
файла, он не совпадает с сортировкой в TIA. На лист попадает и скрытый
системный тег `@DiagnosticsIndicatorTag`.

`PDATA.xlsx` — лист на каждый язык с именем вида `0x409`, колонки `idx` и
`str`. Текст пишется как текст, значение длиннее 32767 символов обрезается.

Папка `pdata` — отдельная папка на каждую таблицу файла, `0x<номер>_<имя>`.
Внутри `header.hex.txt` и по файлу `<номер>_<всего>.hex.txt` на элемент. Если
таблица не подходит под раскладку с каталогом смещений, создаётся один
`raw.hex.txt` со всеми её байтами. Перед записью папка `pdata` удаляется
целиком, поэтому в ней только результат последнего запуска. Положенные туда
вручную файлы тоже удалятся.

## Сообщения и код возврата

Если файл не читается совсем (нет файла, нет заголовка или TOC), программа
пишет `Не удалось прочитать ...` с местом ошибки и завершается с кодом 1.

Если не разобралась одна таблица, печатается
`ПРЕДУПРЕЖДЕНИЕ: не разобрано - <таблица> @ <смещение>: <причина>`. Остальное
обрабатывается; теги и строки, прочитанные до сбоя, попадают в Excel.

Если таблица сохранена целиком, печатается предупреждение про
`raw.hex.txt`. Ошибка одного экспорта выводится как `[<экспорт>] ОШИБКА: ...`
и не отменяет остальные. Если тегов или строк нет, соответствующий Excel
пропускается сообщением `... пропуск`, а его файл от прошлого запуска
удаляется. Если экспорт Excel закончился ошибкой, старый файл остаётся.

Код `0` — ни предупреждений, ни ошибок. Код `1` — ошибка чтения,
предупреждение разбора, таблица в `raw.hex.txt` или ошибка экспорта.

## Ограничения

- Проверено только на внутренних тегах; PLC-теги не исследованы.
- Цикл опроса, Logged и комментарии не извлекаются.
- Проверен один проект с одним языком.
