# Что умеет программа

Обновлено: 16 октября 2026.

## Нужно на входе

- Бэкап панели (`pdata.fwc`) — обязательно.
- Данные ПЛК — по желанию, одно из двух; дают имена и комментарии ПЛК:
  - проект ПЛК (`PEData.plf`) из TIA;
  - копия карты памяти ПЛК — папка, в которой лежит `SIMATIC.S7S`.

## Умеем

- Все HMI-теги: имя, тип, соединение, адрес, режим доступа, цикл.
- С проектом или картой ПЛК: имя ПЛК, тег ПЛК, комментарий из ПЛК.
- С карты имя ПЛК — имя CPU из конфигурации оборудования (`TM50`); не нашлось — имя папки карты.
- Строки всех языков панели.
- Системные события (HMI alarms → System events): лист «Системные события» —
  ID и текст на каждом языке панели, по возрастанию ID. Сверено с TIA: Project1
  (английский) и A603A0097 (английский, русский, польский) — все 585 совпали.
- Дискретные алармы (HMI alarms → Discrete alarms): лист «Дискретные алармы» —
  как список в TIA: ID, текст на каждом языке (с полями `<Tag : 6, имя тега>`),
  класс, тег, бит и адрес срабатывания, квитирование HMI (тег, бит, адрес) и PLC
  (тег, бит), Report. Сверено с TIA на A603A0097 (355 алармов, правки по шагам:
  имя, класс, Report, квитирование, массивы); CCB-A13 (2000 алармов) читается
  теми же правилами. Адрес символьного тега — с данными ПЛК (`PEData.plf` с борта
  или карта), без них «неизвестно»; у абсолютных тегов адрес считается по панели
  и без данных ПЛК. Если таблица тегов алармов в бэкапе повреждена, у затронутых
  алармов вместо `<No tag>` пишется `?` — тег мог быть, но не прочитан.
  Аларм (дискретный и аналоговый) может срабатывать и по внутреннему тегу панели:
  тег остаётся внутренним на листе «Теги», предупреждения нет, адрес срабатывания
  у дискретного — номер бита, как в TIA (проверено на Project1).
- Аналоговые алармы (HMI alarms → Analog alarms): лист «Аналоговые алармы» —
  как список в TIA: ID, текст на каждом языке (с полями), класс, тег
  срабатывания, Limit (число или тег предела), Limit mode, Report. Данные ПЛК не
  нужны: всё берётся из бэкапа панели. Сверено с TIA на шаговой копии A603A0097
  (4 аларма: пределы Int, Real, UInt и тег).
- Классы алармов (HMI alarms → Alarm classes): лист «Классы алармов» — ID,
  Display name на каждом языке, Name, State machine, Log (имя журнала алармов
  или `<No log>`), E-mail address, четыре цвета фона (`255, 0, 0`, ячейка
  закрашена этим цветом, на тёмной заливке текст белый) и тексты состояний Incoming, Outgoing, Acknowledged на
  каждом языке. Если в Runtime settings панели выключены цвета классов, цветов в
  бэкапе нет — пишется «цвета классов выключены». Сверено с TIA по шагам на
  A603A0097 и Project1 (V21). Строка «Классов алармов» в консоли и на «Сводке».
- Группы алармов (HMI alarms → Alarm groups): на листах «Дискретные алармы» и
  «Аналоговые алармы» колонка Alarm group — номер (ID) группы аларма, без группы
  `<No alarm group>`; лист «Группы алармов» — ID групп, назначенных алармам, и
  сколько дискретных и аналоговых алармов в каждой. Строка «Групп алармов» в
  консоли и на «Сводке». Сверено с TIA по шагам на Project1 (V21): группы 1, 2,
  17 и 31, группа вместе с Report.
- Экраны (Screens, Pop-up screens, Slide-in screens, Permanent area): лист
  «Экраны» — имя, номер экрана (Number), стартовый экран (`Yes`), ширина,
  высота и вид: `Screen`, `Pop-up screen`, `Slide-in screen`, `Permanent area`.
  Сначала Permanent area, потом экраны по номеру, потом остальные в порядке
  бэкапа.
  Строки «Экранов» (только экраны с номером) и «Стартовый экран»
  (`Root screen (1)`) в консоли и на «Сводке». Сверено с TIA по шагам на Project1
  (V21): стартовый экран, смена номера, pop-up, slide-in, Permanent area; на
  A603A0097 и CCB-A13 с TIA не сверялись: у большинства экранов номер совпал с
  числом в начале имени (47 из 49 и 6 из 9), у остальных номер другой.
- Картинки панели (PNG и JPEG): все картинки бэкапа файлами в папке `images`
  (`PICTURE_5.png`, `TILED_PICTURE_1.png`), без привязки к экранам и объектам;
  одинаковые не объединяются. Строка «Картинок» в консоли и на «Сводке».
  Проверено на Project1, A603A0097 (76 картинок, из них 4 JPEG) и CCB-A13 (105).
- Текст, начинающийся с апострофа (`'Project ID' area pointer…`), попадает в
  Excel целиком, с апострофом.
- Сверху листа «Теги» — статистика: сколько тегов, сколько найдено в ПЛК,
  сколько есть в панели, но нет в ПЛК, внутренних, с абсолютной адресацией,
  для скольких данные ПЛК неизвестны.
- Первый лист «Сводка»: модель панели, версия Runtime, IP панели, соединения и
  IP ПЛК, откуда данные ПЛК, имя ПЛК, модель CPU и IP CPU (с карты), число тегов и DB.
- У тегов с абсолютным адресом в DB в PLC tag — имя DB (`AlarmsDB`).

- HMI-тег с пользовательским типом: TIA кладёт в панель только используемые
  элементы, отдельными тегами (`xxxx_1.Element_1`); они находятся в ПЛК — член
  DB и член тега входов (`1.Element_1`). Неиспользуемых элементов в бэкапе нет.
  Проверено и с `PEData.plf`, и с карты ПЛК — результат одинаковый.

## Не умеем

- Comment HMI-тега — его нет ни в бэкапе, ни в ПЛК; колонка убрана.
- У системных событий — только ID и текст, других свойств нет.
- Имя дискретного и аналогового аларма (`DiscreteAlarm_1`, `Analog alarm`), имя текстового списка в тексте
  (пишется `<Text list, ?>`) и имя своего класса аларма (на листах алармов
  пишется его Display name, на листе «Классы алармов» в Name — `?`) — их нет ни в бэкапе панели, ни в ПЛК (ни с борта, ни на карте). Есть
  только в исходном проекте TIA с панелью.
- Имя группы алармов (`Alarm_group_1`) — в бэкапе панели только номер группы,
  имени нет; есть только в исходном проекте TIA. Группа, не назначенная ни одному
  аларму, в бэкап не попадает, поэтому её нет и на листе «Группы алармов».
- Классы System и Diagnosis events на листе «Классы алармов» — в таблицах
  классов бэкапа их нет, где лежат их свойства, не разбиралось. Common alarm class и Flashing у цветов не искали.
- Шаблон экрана (Template) — ни имени шаблона, ни того, какой шаблон у экрана:
  объекты шаблона в бэкапе просто вливаются в экран. Имени нет и в выгрузке из
  ПЛК, и на карте ПЛК — только в исходном проекте TIA.
- Какой экран или объект показывает картинку и как картинка называется в
  проекте TIA — в бэкапе выгружаются только сами файлы.
- Global screen как экран: его окна алармов в бэкапе — отдельные системные окна,
  на лист «Экраны» они не попадают.
- Logged и Tag table.
- Несколько ПЛК из отдельных выгрузок.
- Панель с несколькими соединениями с ПЛК вместе с данными ПЛК (`PEData.plf`
  или карта) — пока сознательно не поддерживается: сообщение, файлы не
  создаются. Без данных ПЛК такая панель читается.
- Модель CPU из `PEData.plf`; версию Runtime из папки `Generates` проекта TIA
  (файла `BuildInfo.txt` там нет).

## Не проверено

- TIA кроме V17/V19/V21, панели кроме TP700 и TP1500, ПЛК кроме S7-1500/1200.
- Карта ПЛК: реальная CCB-A03 (S7-1500F, TIA V19) и тестовая из своего проекта (V21) —
  по ней результат совпал с `PEData.plf` один в один; S7-1200, карты
  других версий TIA и с защитой ноу-хау не проверены. Сверено только по
  именам HMI-тегов, проекта TIA этой карты нет.
- Системные события: зачем в A603A0097 у 3 событий есть лишняя запись в конце
  таблицы, неизвестно.
- Дискретные алармы: CCB-A13 с TIA не сверен (проекта нет); теги срабатывания в
  областях I/Q с абсолютным адресом (область M сверена); длина поля тега в тексте сверена на одном
  поле.
- Аналоговые алармы: проверены на шаговых копиях A603A0097 и Project1, реальных
  бэкапов с ними нет. Пределы на тегах Int, DInt, Real и LReal сверены с TIA;
  другие типы не проверены — если вид значения незнакомый, в Limit пишется `?`.
- Группы алармов: проверены только на шаговых копиях Project1 — в реальных
  бэкапах (CCB-A13, A603A0097) группы алармам не назначены.
- Классы алармов: Log и E-mail сверены с TIA на одном журнале и адресе (A603A0097)
  и на двух журналах и двух адресах у разных классов (Project1). Если в бэкапе
  повреждена таблица журналов или писем, у классов без найденного журнала или
  адреса в Log или E-mail пишется `?` и выдаётся предупреждение.
- Экраны: шаги сделаны только на Project1 (V21, TP700); CCB-A13 (V17, TP1500) и
  A603A0097 (TP1900) читаются, но с TIA не сверены. Индикатор алармов из Global screen,
  похоже, лежит вместе с Permanent area — не проверено.
- Картинки других форматов (BMP, GIF, SVG и т. п.) в бэкапах не встречались;
  если встретится, картинки той же таблицы после неё не выгрузятся, будет
  предупреждение.
- Бэкап, скомпилированный старой версией TIA, может содержать меньше системных
  событий, чем показывает проект сейчас: в копиях A603A0097 от 30 мая нет 5
  событий 220010…220014, после перекомпиляции они появились.
