# Как появился проект

Документ отвечает на вопрос «почему код выглядит так».

## Откуда взялся формат

Исходная точка — R-проект `rois286/Flex-RT-Configuration-Editor` для файлов
`PDATA.FWX` панелей WinCC flexible 2008. Из него взяты раскладка заголовка
файла, Table Of Contents, общая раскладка таблицы с каталогом смещений и
таблица `STRINGSTORE`. R-код не эталон и не источник требований: правильным
считается то, что подтверждено байтами реального файла и решением владельца.

## Сентябрь 2026: порт на C# и правила

Порт сделан как консольное приложение C# / .NET 10 с одним пакетом
`ClosedXML`. Решения, которые действуют до сих пор:

- Пути — статичные константы в начале `Program.cs`, аргументов нет:
  требование владельца «запустил и всё».
- Один запуск делает все экспорты. Экспорты независимы: сбой одного не
  отменяет остальные.
- Ошибка формата одной таблицы — предупреждение, а не остановка; что
  прочитано до сбоя, остаётся в выводе. Любое предупреждение даёт код 1.
- Таблица, не подходящая под каталог смещений, сохраняется целиком в
  `raw.hex.txt`.
- Размер таблицы считается по физическому порядку смещений.
- Строка языка целиком лежит внутри `STRINGSTORE`: поиск нулевого символа
  до конца файла однажды дал регрессию с чтением чужих байтов и
  квадратичным временем.
- Папки `Binary/`, `Model/`, `Parsing/`, `Export/`, зависимости в одну
  сторону; один тип — один файл; обязательные блоки у операторов
  проверяет сборка.

30 сентября 2026 года прежний разбор тегов `VAR` / `DATALINK_READWR`,
справочник типов и HTML-экспорт удалены: их раскладка была снята с WinCC
flexible и ничем не подтверждалась.

## 5 октября 2026: реальные файлы TIA Portal

Владелец перешёл на реальный проект: TIA Portal V17, панель TP700 Comfort.
Вход — `pdata.fwc` из папки `Generates`. Каркас формата (заголовок, TOC,
каталог смещений, `STRINGSTORE`) подошёл без изменений.

Раскладка `VAR` установлена заново, пошагово. Владелец создавал внутренние
теги по одному и после каждой компиляции сохранял копию `pdata.fwc`.
Сравнение 14 копий дало запись тега: имя, код типа, бит массива `0x2000` и
число элементов. Раскладка прежнего разбора к этим файлам не подошла.
Первая попытка с копиями `pdata.pwx` не дала данных: это 168-байтный
зашифрованный файл администрирования пользователей, а не конфигурация.

Решения владельца на этом этапе:

- Теги пишутся в новый файл `panel_data.xlsx`, лист «Теги», колонки как в
  таблице HMI tags в TIA. Пока заполняются Name и Data type.
- Выводятся все записи `VAR`, включая скрытый `@DiagnosticsIndicatorTag`.
- Неизвестный код типа — `?`, без предупреждения.
- Массив пишется как `Array [0..N-1] of <тип>`: TIA не даёт задать нижнюю
  границу, отличную от 0. Проверено тегом, заданным как `[5..22]`.
- Выходные файлы прошлого запуска не накапливаются: папка `pdata`
  удаляется перед hex-экспортом (имя hex-файла содержит число элементов, и
  после каждого нового тега рядом оставался прежний комплект), а Excel
  пропущенного экспорта удаляется. Удалена пустая папка `Resources/` от
  прежних HTML-шаблонов.
- Входной файл — `pdata.fwc` прямо в папке `Generates` проекта TIA, без
  копирования. Чтобы проверки могли подать на вход эталон, не трогая папку
  TIA, добавлена переменная окружения `FLEXRT_INPUT`, подменяющая входной
  файл.
- В обязательные проверки добавлена проверка Rider через MCP: ошибки и
  предупреждения устраняются, недоступность Rider сообщается явно.
- Синтетические образцы удалены. Проверка перед завершением идёт на
  реальном `samples/pdata.fwc`; для ошибок — его обрезанная копия
  `samples/bad.fwc`. Документация переписана под реальные файлы.
