# Карта памяти ПЛК (SIMATIC.S7S)

Копия карты памяти S7-1500 — альтернатива `PEData.plf`: из неё берутся теги
ПЛК, DB и комментарии. Всё ниже установлено на одной карте:
`samples/card/CCB-A03.zip` (архив копии карты; CPU 1515F-2 PN `6ES7 515-2FN03-0AB0`, данные TIA V19,
последняя загрузка в ПЛК 27.05.2026), сверено с панелью
`samples/card/pdata.fwc` (TP1500 Comfort, Runtime V17). Проекта TIA этой карты
нет: сверка — по именам HMI-тегов (TIA по умолчанию называет HMI-тег
`DB_член_член`).

## Папка

| Что | Содержимое | Статус |
|---|---|---|
| `S7_JOB.S7S` | 7 байт `PROGRAM`: вид карты | наблюдение |
| `s7p.web.apps` | пусто | наблюдение |
| `SIMATIC.S7S\OMSSTORE\<класс>\<0\|1>\<id>` | объекты загрузочной памяти | установлено кодом |

TIA (*Card Reader/USB memory → Add user-defined Card Reader*) показывает такую
папку как ПЛК с блоками и тегами, но проекта не создаёт: `PEData.plf` из неё
появляется только после выгрузки в проект и сохранения.

## Объекты

Объект начинается байтом `a6`, RID (u32 big endian, старший байт `0x89` или
`0x8a`), varint и байтом `a3` (`00 a3`, `20 a3`, `84 80 80 80 20 a3` — у всех
587 объектов карты; у 74 случайных совпадений `a6 89/8a` в данных, в том числе
внутри потоков с незнакомым словарём, байта `a3` нет — установлено: без этой
проверки 2 DB из 95 теряли интерфейс). Старшие 16 бит RID — класс: `0x8a0e` —
DB, младшие — номер DB (95 из 95, номера совпали со ссылками панели —
установлено); `0x89fd` — UDT; `0x8a12`, `0x8a13`, `0x8a20`, `0x8a21`, `0x8a24`,
`0x8a32` и др. — блоки кода и системные (наблюдение).

Таблица тегов лежит в своём файле (`00000003\1\…`), объект `a6 00 00 00 5x`:
`0x50`… — коды областей, как в `DATALINK_READWR` (наблюдение).

## Модель CPU

В объекте оборудования (`OMSSTORE\00000002\0\0000005A`) открыто лежат название
`0e "CPU 1515F-2 PN"` (байт длины, строка) и через 0x3a байт заказной номер
`*6ES7 515-2FN03-0AB0` — наблюдение. Модули ввода-вывода в соседнем объекте
перечислены без названия `CPU`. Программа берёт первое `CPU …` с байтом длины
и первый `6ES7 …` не дальше 0x100 байт за ним. Объект `00000077` содержит
имя `MyPLC` (назначение неясно) — не используется. Имя ПЛК в выводе — имя
объекта CPU: атрибут `a3 81 69 00 15`, байт длины, строка (`05 " TM50"`, без
пробелов по краям — `TM50`); тем же именем названы объекты станции и интерфейсов,
из него построены PROFINET-имена `tm50.x1` — наблюдение.

## IP CPU

Объект оборудования с именем `Network Parameters` (в `00000002\0\0000003F`) —
сетевой интерфейс CPU. Через 0x20 байт после имени: метка
`a0 01 00 14 30 00 00 10 01 00 00 00`, затем IP `c0 a8 01 01` = 192.168.1.1,
маска `ff ff ff 00`, шлюз `c0 a8 01 01` и PROFINET-имя `tm50.x1` — наблюдение;
IP совпал с адресом ПЛК в соединении панели CCB-A13. Объекты «Network Parameters»
есть у каждого устройства сети; у CPU короткий RID объекта (`0x4d` — X1
192.168.1.1 `tm50.x1`, `0x4e` — X2 192.168.0.11 `tm50.profinet`), у устройств —
`0x08ddxxxx`. Программа берёт адреса объектов с RID меньше 0x10000, без повторов
и нулевых — наблюдение на одной карте.

## Сжатие

Данные объектов — потоки zlib с предустановленным словарём (флаг FDICT,
заголовок `78 7d`, за ним Adler-32 словаря). Словари не хранятся на карте; взяты
из S7CommPlusDriver (Thomas Wiens, LGPL-3.0), Adler-32 всех совпал —
установлено. Используются четыре:

| ID | Словарь | Что в потоке |
|---|---|---|
| `ce9b821b` | IntfDescTag_90000001 | таблица тегов `<IdentContainer>` |
| `e2729ea1` | TagLineComm_90000001 | комментарии тегов `<CommentDictionary>` |
| `66052b13` | DebugInfo_IntfDesc_98000001 | интерфейс блока `<BlockInterface>` и отладочные данные `<DebugInfo>`; берётся первый поток с корнем `BlockInterface` |
| `3c55436a` | LineComm_98000001 | комментарии членов `<InterfaceLineComments>` |

Остальные потоки (код сетей, ссылки, `IdentES` и др.) не нужны. Поток
комментариев блока без комментариев распаковывается в 0 байт (наблюдение).

## Тег ПЛК

`<Ident Name LID>`, тип `<SimpleType>` или `<UserDataType>` (в TIA — в
кавычках), адрес `<SimpleAccess Range Width ByteNumber BitNumber>`: Range —
Input, Output, Memory, Timer, Counter; Width — Bit, Byte, Word, DWord, у таймера и
счётчика `None` с номером в `ByteNumber` (`%T0`, `%C0` — карта тестового проекта).
`LID` — ID символа, на который ссылается панель (первое слово пути
`DATALINK_READWR +0x28` без вида в старшем полубайте): 8 из 8 тегов CCB-A13 и все
теги тестового проекта, включая член тега входов пользовательского типа —
установлено. LID уникален внутри области. Комментарий — в
потоке того же файла, `RefID` = LID.

## Интерфейс блока

Дерево `<Part>`. Исходная часть — `DBSource` (глобальный DB), `BlockSource`
(FB), `DataTypeSource` (UDT): члены в `Payload/Root`, атрибуты члена — как в
PEData.plf (`ID Name RID Type LID`). Вложенные члены — внутри элемента члена или
в части `SubParts[SubPartIndex]` ближайшей части, у которой есть `SubParts`
(у `Structure` своих нет — установлено на `HMIDataCCD_DB.050_Robots`). Член с
`SubPartIndex` на исходную часть — мультиэкземпляр FB или UDT. У
instance-DB верхняя часть `Values`, первая из её `SubParts` — FB. Разделы FB
(Input, Static…) — члены без `LID`; у системных F-блоков `*_C` пустые разделы
опущены, а члены разделов лежат прямо внутри элемента раздела (наблюдение: DB30000,
30007–30010). Части без `Kind` (`IEC_TIMER`, `DTL`, `GEOADDR` …) — ссылки на
системные типы без членов: путь внутрь них (`DB.Timer.ET`) не разрешается.
Части, ссылающиеся друг на друга по кругу, — ошибка DB. Имя блока — `Block` или
`BIVE:имя/guid` в `Info` или `VersionElement`.

Комментарии членов — `<Comment Path="51:60">`: цепочка ID, как ключи
комментариев PEData.plf. Член FB или UDT комментируется у FB или UDT, член
глобального DB — у DB (наблюдение).

## Сверка с проектом TIA

Карта `PLC_1` тестового проекта, записанная TIA через *Card Reader*
(`samples/plc/PLC_1-card.zip`), с панелью того же проекта даёт лист «Теги»,
совпадающий ячейка в ячейку с листом по `PEData.plf`: 47 из 47 PLC-тегов, имена,
типы, адреса (в том числе `%T0`, `%C0`), комментарии; имя ПЛК `PLC_1`, IP
192.168.1.1 и 192.168.0.1 — как в проекте. Установлено.

## Сверка с панелью

Из 501 PLC-тега панели: 481 найден (из них у 109 имя члена в ПЛК другое —
переименования `Mode` → `ModeMotor` и т. п., LID при переименовании не
меняется), 18 — «отсутствует в файле ПЛК» (DB918 на карте нет, DB1230 и часть
`HMIDataCCD_DB` перестроены после сборки панели), 2 абсолютных (в PLC tag —
имя DB по адресу: `AlarmsDB`, `HMI_Ack_To_PLC`).

## Не установлено

- Правило «RID объекта CPU меньше 0x10000» проверено на одной карте.
- Члены системных типов (`IEC_TIMER`, `DTL` …) на карте не хранятся.
- Один нераспаковываемый поток со словарём (в любом блоке) — вся карта не
  используется.
- Имя ПЛК из объекта CPU установлено: на карте, записанной TIA из тестового
  проекта (`samples/plc/PLC_1-card.zip`), объект CPU называется ` PLC_1` — это имя
  ПЛК в проекте. `MyPLC` есть и там — системное имя служебного объекта.
- Карты S7-1200, других версий TIA, с защитой ноу-хау; словари других версий
  (`…_90000001` у интерфейсов) не встречались.
