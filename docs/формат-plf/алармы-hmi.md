# Дискретные алармы панели в PEData.plf

Что о дискретных алармах есть в `PEData.plf` **исходного проекта TIA с
панелью**. Программа это не читает: в рабочем сценарии владельца есть только
бэкап панели и программа ПЛК (выгрузка с ПЛК или карта), а в них данных панели
нет. Документ — для сверки и на случай, если понадобится имя аларма.

Статусы — как в [общая-структура.md](общая-структура.md). Всё найдено на
`A603A0097_V21` (TIA V21) по шаговым копиям 10–12.10.2026: каждое утверждение
проверено правкой в TIA.

## Где данные панели, а где нет

| `PEData.plf` | Панель, HMI-теги, алармы |
|---|---|
| исходный проект `A603A0097_V21`, `Project1` | есть |
| выгрузка с ПЛК `Project1_upload` | нет: 1 ПЛК, 48 тегов ПЛК, больше ничего |

На карте ПЛК CCB-A03 (распакованы все 128 файлов и 650 потоков) нет ни
алармов, ни классов, ни имени панели: из 517 HMI-тегов панели CCB-A13 буквально
нашлись только 10 — те, чьё имя совпадает с тегом ПЛК.

## Объект дискретного аларма, класс 0x00c01009

По объекту на аларм (355 в A603A0097), одна живая версия.

- Начало секции имени: `u32 @ +0x28` − 4 (у аларма `+0x70`). Секция:
  `u32` конец секции, `u32` смещение строки автора, `u32` смещение
  мультиязычного блока или 0, две отметки времени .NET, `u32` A — смещение строки
  **имени**, `u32` B — смещение второй строки (пустой у всех). Смещения — от
  начала секции, строки — байт `длина + 1` и UTF-8.
- Сразу за концом секции: `u32 0x21` и `u32` **ID аларма**. Установлено на всех
  355: имена `11` (переименованный аларм 99), `VVVV`, `Discrete alarm_1` прочитаны
  верно. Порядок строк в секции разный (у новых алармов автор и
  мультиязычный блок стоят перед именем), поэтому нужны смещения, а не порядок.
- Связи — на слоте `+0x68` − 4: `u16` длина списка = 4 + 16·n, `u16` n, n записей
  `[тип][класс цели][ID цели][0]`:

| Тип связи | Куда ведёт | Что это |
|---|---|---|
| `0x12003` | `0x101006` | устройство HMI (`HMI_RT_2`) |
| `0xc0204b` | `0xe51008` | HMI-тег срабатывания |
| `0xc0204d` | `0xc01002` | класс аларма |
| `0xc02001` | `0xe51008` | HMI-тег квитирования с панели |
| `0xc02047` | `0xe51008` | HMI-тег квитирования из ПЛК |

По всем 355 алармам класс, тег срабатывания и теги квитирования совпали с
`MSG_NUMEVENT` и `AREAPTR` панели.

## Класс аларма, класс 0x00c01002

Секция с `+0x50`, смещение имени — `u32` сразу за второй отметкой времени
(`+0x6e`). Имена: Errors, Warnings, System, Diagnosis events, Safety warnings,
Acknowledgement, No Acknowledgement, свои. У своих классов ID лежит на `+0xe9`
(64, 65) — гипотеза, два объекта.

## Текст аларма, класс 0x00c81005

Объект `DiscreteAlarmText` с текстом на каждом языке проекта в виде XML
`ProjectText` (UTF-16). Поле вывода — `<field ref="N"/>` и описание:

```
<fieldinfo name="0" domaintype="HMIAlarmTag"><reference index="1"/>
  <domaindata><format displaytype="Decimal" length="6"/></domaindata></fieldinfo>
<fieldinfo name="1" domaintype="HMICommonTextList"><reference index="0"/>
  <subreference index="1"/><domaindata><format length="5"/></domaindata></fieldinfo>
```

`index` — номер записи во втором списке связей объекта (последний список у
конца объекта, тип `0x1202a`): текстовый список `0xe81005`
(`SINAMICS_S120_FW5.2`) или HMI-тег `0xe51008`. У списка тег поля — в
`subreference`.
