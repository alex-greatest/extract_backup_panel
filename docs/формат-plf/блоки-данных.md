# Блоки данных (DB) в PEData.plf

Как по символьному пути из `DATALINK_READWR` панели (см.
[../формат-fwx/таблица-datalink-readwr.md](../формат-fwx/таблица-datalink-readwr.md))
найти член DB и показать его как в TIA: `DB_ST7_HMI_MANU.Axis.Button.Homming`.
Найдено на `A603A0097_V21` (S7-1500): из 265 символьных тегов DB разрешено
264, все 264 пути совпали с сохранённым TIA текстом пути (объект 0x25021) —
установлено. Номера DB 20 из 20 совпали с Openness-экспортом.

## Объекты

| Класс | Что внутри |
|---|---|
| 0x221002 | DB: `03 "DB"`, имя, комментарий; номер — `u16 N` и `0e 8a` после 12 байт `ff`; связь 0x12003 → ПЛК |
| 0x22160c | корень интерфейса: XML `<Root>` с членами `<Member ID Name RID Type StdO LID/>` |
| 0x22160b | вложенные члены: XML `<Member ParentId="a:b:c">…` |
| 0x22160d | комментарии членов: ключи — цепочки ID (UTF-16), значения — мультиязычные тексты, см. ниже |
| 0x25021 | список путей HMI: номер DB, цепочка ID, имена, полный путь как в TIA |

Пользовательские типы проекта (для членов тегов I/Q/M такого типа): корни
`0x22160c`, владелец которых по связи `0x222609` — объект UDT `0x221003`; имя — из
`BIVE:имя/guid`, ПЛК — связь владельца на объект ПЛК (установлено на тестовом
проекте с `User_data_type_1`).

Связи DB: `0x22260e` — корень интерфейса на момент компиляции HMI
(предпочтительный, гипотеза), `0x22260a` — текущий корень, `0x2204c` → FB
(у instance-DB члены берутся из корня FB), UDT-корни — по `0x22260f`,
имя UDT в строке `BIVE:<имя>/<guid>`.

## XML

Лежит открыто (BOM `ef bb bf` + `<Root`) или цепочкой чанков
`[varint длина][zlib 78 xx…]`; каждый чанк распаковывается в 4096 байт,
последний добит нулями — установлено.

Член: `LID` — номер внутри родителя (с 9), `ID` — номер внутри корня,
`ParentId` — цепочка ID через `:`. Тип: `Type="\"UDT\""` — UDT, `Array[l..u] of X`,
`String[n]`; у скаляров `RID = 0x020000TT` (TT: 01 Bool, 02 Byte, 04 Word,
05 Int, 08 Real, 13 String, 34 USInt, 35 UInt — установлено; 07 DInt — по
одному источнику). `StdO` — смещение в битах внутри родителя.

## Путь из панели

Слова пути (`+0x28` элемента `DATALINK_READWR`): `0x2xxxxxxx` —
промежуточный член (LID в младших битах), `0x4xxxxxxx` — конечный член,
`0x5xxxxxxx` — индекс элемента массива от нижней границы, `0x60000000` +
`0x7… длина` — хвост строки. На каждом уровне ищется член с этим LID; у UDT —
переход в его корень; индекс — `[i]` к последнему имени. Имя с символом,
кроме букв, цифр и `_`, берётся в кавычки (`"Scan Requested"`), как в 0x25021.

## Комментарии членов, объект 0x22160d

Установлено на 650 объектах пяти проектов. Корень интерфейса связан с
владельцем (DB, UDT или FB) связью 0x222609, владелец с объектом комментариев —
связью 0x222618. Комментарий члена UDT лежит у UDT, члена FB — у FB; DB хранит
только комментарии своих членов.

- `u32@0x34` — указатель `p` (обычно 0x48).
- От `p`: `[u32][u32 n][u16][u32]`, n заглушек `1f 00 00 80`, n смещений
  ключей (от `p − 4`).
- Ключи — UTF-16 с нулём, цепочка ID через `:` (`52:51:51`).
- За самым дальним ключом — n смещений значений (от конца этого массива), затем
  значения — мультиязычные тексты подряд. Ключ i соответствует значению i.

Ключ для члена — цепочка ID от корня, где член найден (у члена UDT — от корня
UDT). Пример: `Cylinders.Y1.Ext` в `DB_ST7_HMI_MANU` — ключ `52:51:51`, текст
"Extend Y1 HMI Manual Command". Сверено с Openness-экспортом: 16 из 16
комментариев членов, определённых в самом DB, — установлено. Ещё 49
комментариев членов UDT и FB-instance экспорт DB не содержит, поэтому они не
подтверждены независимо.
