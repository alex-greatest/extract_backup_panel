# Сетевой интерфейс и IP ПЛК в PEData.plf

Нужен, чтобы выбрать в проекте ПЛК тот ПЛК, к которому идёт соединение
панели: в `pdata.fwc` у соединения есть только IP ПЛК (см.
[../формат-fwx/соединения.md](../формат-fwx/соединения.md)). Статусы:
установлено на файлах, наблюдение, гипотеза. Программа читает IP интерфейсов
в `Parsing/Plc/Devices/PlfDeviceParser.cs` (связи — общим поиском `PlfRelations.Scan`).

## Интерфейс, класс 0x0010101d

IP лежит в объекте сетевого интерфейса в открытом виде, но байты в
обратном порядке: u64 little-endian, значимы младшие 32 бита. Поэтому
поиск `c0 a8 00 03` ничего не находит, а `03 00 a8 c0` находит.

Блок адреса (интерфейс `PLC_2`, 192.168.0.3):

```
21 00 00 00 | 3c 00 00 00 | 03 00 a8 c0 00 00 00 00 | 00 ff ff ff 00 00 00 00 |
01 00 a8 c0 00 00 00 00 | 01 00 00 01 06 00 08 00 00 | 1b "plc_1.profinet interface_1"
```

| Поле | Значение | Статус |
|---|---|---|
| `[u32 0x21][u32 L]` | начало блока, L = 0x3c / 0x27 / 0x47 | наблюдение |
| u64 | **IP** | установлено на файлах: 192.168.0.1 у `PLC_1`, 192.168.0.3 у `PLC_2`, 192.168.0.2 у панели |
| u64 | маска 255.255.255.0 | наблюдение |
| u64 | маршрутизатор 192.168.0.1 | наблюдение |
| 9 байт | флаги | не расшифровано |
| строка | имя при создании интерфейса | наблюдение: у `PLC_2` осталось `plc_1…`, для привязки не годится |

Связи интерфейса (16-байтовые записи, как у тега):

| Тип связи | Цель |
|---|---|
| `0x00102042` | DeviceItem интерфейса |
| `0x00012003` | **ПЛК**, класс 0x10101c |
| `0x00102046` | подсеть, класс 0x10101e; только у подключённого интерфейса |

## Алгоритм IP → ПЛК

1. Для каждого живого объекта 0x10101d взять связь 0x12003 → ID ПЛК.
2. В объекте найти ровно один блок `[u32 0x21][u32 L]`, 32 < L < 0x100,
   прочитать три u64. Старшие 32 бита IP и маски должны быть 0, IP не 0.
3. Таблица IP → ПЛК. Если IP даёт несколько ПЛК — оставить интерфейсы со
   связью на подсеть; если всё ещё несколько — «неоднозначно».

Результат: в исходном проекте 192.168.0.1 → `PLC_1`, 192.168.0.3 →
`PLC_2`, 192.168.1.1 — неоднозначно (второй, неподключённый интерфейс у
обоих ПЛК). Виртуальные интерфейсы имеют IP 0.0.0.0.

## Важно: IP в выгруженном проекте

В проекте, выгруженном из PLCSIM, у `PLC_1` IP **192.168.50.79**, а не
192.168.0.1, как в исходном проекте и в бэкапе панели — установлено на
файлах. В `Project1_plc_only` IP интерфейса тоже сменился с 192.168.1.1 на
192.168.50.79 (две версии объекта). Гипотеза: адрес интерфейса PLCSIM.
С реальным ПЛК IP выгрузки, вероятно, совпадёт с IP в панели, но это не
проверено. Если IP не совпадает, ПЛК по IP не выбрать.

## Риск: связь интерфейса с ПЛК

В `A603A0097_V21` связь 0x12003 у интерфейсов ведёт не к объекту ПЛК
(0x10101c), а к объекту класса 0x101018. Поэтому выбор ПЛК по IP там не
работает; сопоставление идёт по правилу «один ПЛК и одно соединение».
Цепочка 0x101018 → ПЛК не разобрана.

## Чего мы не знаем

- Что лежит, если IP задаётся на устройстве или по DHCP.
- Значение флагов после маршрутизатора.
- Совпадает ли IP при выгрузке из реального ПЛК.
