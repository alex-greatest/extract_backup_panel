# Файл проекта TIA: PEData.plf

`System\PEData.plf` в папке проекта TIA Portal — база объектов проекта:
устройства, ПЛК, таблицы и теги ПЛК, HMI и всё остальное. Нужен FlexRt,
чтобы по тегу панели найти имя тега ПЛК, имя ПЛК, тип, адрес и комментарий:
в `pdata.fwc` их нет. Программа читает этот файл в `Parsing/Plc/Plf/`, путь —
константа в `Program.cs` или переменная окружения `FLEXRT_PLC`.

Всё ниже найдено на трёх проектах TIA Portal V21 с ПЛК S7-1500 (CPU 1515-2
PN). Статусы — как в
[../формат-fwx/таблица-datalink-readwr.md](../формат-fwx/таблица-datalink-readwr.md):
установлено на файлах, наблюдение, гипотеза.

| Проект | Что это |
|---|---|
| `Desktop\Project1_upload` | ПЛК, выгруженный из PLCSIM в новый проект — главный сценарий «проект из ПЛК» |
| `Desktop\Project1_plc_only` | Save as исходного проекта, панель удалена |
| `Desktop\extract_backup_data\Project1` | исходный проект с панелью и долгой историей правок; позже — второй ПЛК `PLC_2` |

Соседние документы: [тег-плк.md](тег-плк.md), [сеть.md](сеть.md).

## Заголовок, 0x62 байта

```
40 00 00 00 01 00 00 00 | GUID файла, 16 байт | 34 08 00 00 00 00 00 00 | … | 00 | SHA-256 | ff
```

| Смещ. | Значение | Статус |
|---|---|---|
| 0x00 | `0x40` в `.plf`, `0x80` в `.idx` | наблюдение |
| 0x08 | GUID файла; одинаков у `.plf` и `.idx` одной пары, у Save as сохраняется | наблюдение |
| 0x40 | `00` | наблюдение |
| 0x41..0x60 | SHA-256 от байт 0x00..0x40 | установлено на файлах: совпало у всех |
| 0x61 | `ff` | наблюдение |

## Кадры

С 0x62 файл — цепочка кадров до конца файла:

```
[u32 size][data …][ff][SHA-256, 32 байта]
```

- Полная длина кадра `4 + size + 28`. Поле `size` считает u32, data и
  байт `ff`, то есть всё, что хэшируется.
- SHA-256 считается от `buf[pos .. pos+size)` и лежит сразу за ним.
- Цепочка ровно кончается на конце файла.

Установлено на файлах: 862, 4650 и 3875 кадров, ни одного несовпадения
SHA-256, проверено двумя независимыми скриптами. Ключа у хэша нет.

**Повреждённый файл** — любое из: неверный SHA-256 заголовка; кадр выходит
за конец файла или `size < 8`; цепочка не кончается ровно на конце файла;
у кадра нет `ff` или SHA-256 не совпал; в файле нет ни одного COMMIT. На
испорченных копиях (изменённый байт, усечение, испорченный заголовок) все
случаи обнаруживаются.

## Объект в кадре

```
+0x00 u32 класс объекта
+0x04 u32 ID объекта (внутренний, не ID символа ПЛК)
+0x08 u32 0
+0x0c u32 8 или 0x21; 0xFFFFFFFF — объект удалён
+0x18 GUID объекта, 16 байт
```

Известные классы:

| Класс | Объект |
|---|---|
| `0x0002105c` | тег ПЛК |
| `0x00021062` | таблица тегов ПЛК |
| `0x0010101c` | ПЛК (программная часть) |
| `0x0010101d` | сетевой интерфейс |
| `0x0010101e` | подсеть |
| `0x00070014` | COMMIT, строка `$$COMMIT$` |
| `0x00070015` | CLOSE, строка `##CLOSE##` |

## Версии, удаление, транзакции

- **Файл только дописывается.** Объект с той же парой (класс, ID)
  встречается много раз; актуальна последняя версия — установлено на
  файлах: у тега `DInt_QD6` в исходном проекте две версии, `%QD6` и
  `%QD50`, актуальна вторая.
- **Удаление** — новая версия объекта длиной 49 байт с `+0x0c = 0xFFFFFFFF`
  (надгробие). Объект выбрасывается.
- **Транзакция** закрывается кадром COMMIT. Кадры после последнего COMMIT
  не учитываются: незавершённая транзакция. В конце файла может стоять
  CLOSE — при штатном закрытии проекта (гипотеза).
- Без этих правил из файла с историей правок получился бы мусор: в
  исходном проекте 551 кадр класса тега, из них живых тегов 48.

## Строки и сжатие

- Строки в объектах: один байт `длина + 1`, затем UTF-8. Пример
  `0a "Bool_I0_0"`. Строки длиннее 126 байт не встречались.
- Некоторые объекты содержат zlib-потоки (`78 xx`) с длиной перед ними в
  .NET 7-bit varint; внутри XML. Данные тегов, ПЛК и интерфейсов не сжаты,
  для FlexRt распаковка не нужна.

## PEData.idx

Индекс живых объектов: записи (класс, ID, GUID объекта, смещение кадра в
`.plf`). Для каждого живого объекта есть запись со смещением его последнего
кадра. Для чтения `.plf` индекс не нужен. Разобран частично.

## Чего мы не знаем

- Смысл `+0x0c` (8 / 0x21) и `+0x16` в заголовке объекта.
- Другие версии TIA, другие CPU, проекты с паролем или know-how protection.
- Можно ли читать файл, пока проект открыт в TIA: копия читалась целой, но
  хвост теоретически может быть недописан — поэтому учитываются только
  кадры до последнего COMMIT.
