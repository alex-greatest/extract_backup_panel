# Тег ПЛК, таблица тегов и ПЛК в PEData.plf

Как в [общая-структура.md](общая-структура.md) найти тег ПЛК и прочитать
его имя, комментарий, ПЛК, тип, адрес, область и ID символа. Статусы:
установлено на файлах, наблюдение, гипотеза.

Проверено на семи проектах (V17 и V21, S7-1500 и S7-1200, авторы
`Alexander`, `Hustler`, `zedqz008`, `PBasiaga`):

| Проект | Тегов ПЛК | Разобрано |
|---|---|---|
| `extract_backup_data\Project1` | 51 | 51 |
| `Project1_upload`, `Project1_plc_only` | 48 | 48 |
| `A603A0097_V21`, `A603A0097` | 203 | 203 |
| `半自动驱动轴装配线03_06_2026` (_V21) | 3282 | 3282 |

У `A603A0097_V21` все 203 тега совпали с Openness-экспортом
(`A603A0097\openness_export\…`) по имени, таблице, типу, адресу и
комментарию — установлено.

## Строки и тексты

- **Строка:** varint (LEB128) «длина + 1», затем UTF-8. Префикс 0 —
  строки нет, 1 — пустая. Двухбайтные префиксы встречаются: `e5 03` = 485 —
  установлено.
- **Мультиязычный текст** (комментарий) — установлено на 77 тыс. блоков:

```
[varint X][u32 A = X − длина varint][u32 A − 16][ff ff ff ff][u32 n]
[n × u16 LCID][n × u32 смещение от поля A][n × (u32 длина, UTF-8)][16 байт хвоста]
```

  X — длина всего блока. Первое смещение `16 + 6n`. Пустой текст — 33 байта
  `21 20 00 00 00 10 00 00 00 ff ff ff ff 00 00 00 00` + 16 байт. Пустые
  языки пишутся не все. Встречалось n от 0 до 5; у тегов ПЛК — не больше двух
  языков (`I_ST7_AutoMode`: 0x409 текст, 0x415 пусто). Программа берёт
  первый непустой текст.

## Тег ПЛК, класс 0x0002105c

### Слоты заголовка объекта

| Слот | Что | Статус |
|---|---|---|
| +0x38 | начало блока доступа | установлено |
| +0x44 | граница блока доступа (длина блока — u32 перед ним, может быть меньше) | установлено |
| +0x4c | начало секции имени | установлено |
| +0x50 | секция за именем | установлено |
| +0x58 | начало связей | установлено |

Все слоты в пределах [0x60, длина объекта]. Фиксированных позиций нет:
`u32@0x7a == 0x1e` — частный случай.

### Секция имени

В первых 0x40 байтах от слота +0x4c ищется поле, перед которым стоит байт
`0x48` — старший байт двух отметок времени .NET (UTC). Поле:

- `0x1e` — имя, затем (если есть) комментарий;
- `0x1e + X` — комментарий длиной X, затем имя.

Секция кончается на `+0x50 − 4` или `+0x58 − 4` (допускаются нули до
границы). Раскладки: «только имя» (116 в A603), «имя, комментарий»
(2459 в S7-1200), «комментарий, имя» (823 в S7-1200) — установлено.

### Связи

На `+0x58 − 4`: `u16 0x54, u16 n`, затем n записей
`[u32 тип][u32 класс цели][u32 ID цели][u32 0]`. `0x0002205a` → таблица
тегов (0x21062), `0x00012003` → ПЛК (0x10101c) — установлено.

### Блок доступа

```
[1][0][ID символа][01][u32][шесть u32][01][u32][строка 1][строка 2][u32 хвост]
```

- Шесть u32: 0, индекс области (I1 Q2 M3 T4 C5), класс размера (X1 B2 W3 D4,
  у T/C −1), байт или номер, бит (−1 у не-Bool), **область**
  (0x50..0x54) — установлено.
- Два варианта: «семейство, затем адрес» (u32 = 0x39 и 0x32) и «адрес,
  затем семейство» (u32 = 0x32 и 0x32 + префикс адреса; 106 тегов A603).
  Различаются по строке: адрес начинается с `%` — установлено.
- Хвост = 0x5e + префикс строки типа — установлено, кроме одного тега.
- В старых версиях объектов бывает блок без ID и области (адрес не
  разрешён): программа считает такой тег неразобранным.

### Тип данных

- Форма 1: сразу за блоком доступа `[u32 0x39 + префикс][01][строка]`.
- Форма 2 (20 тегов в двух проектах): `[u32 0x39][01][25 00 0c …]`, строка
  типа — после `0c 00 00 00 00 00 00 00 0c 00 00 00`.
- UDT записан в кавычках: `"PD_TEL3_IN"`.

## Таблица тегов, класс 0x00021062

Имя — строка после поля 0x1e/0x1f за байтом 0x48 (как у тега). Программа
таблицу тегов не выводит.

## ПЛК, класс 0x0010101c

Имя ПЛК — строка сразу после строки типа CPU (`S71500.CPU`, `S71200.CPU`) и
комментария (мультиязычный текст или пустая строка `01`). Установлено на всех
32 живых объектах ПЛК семи проектов. Строки перед типом разные:

```
P/U/B:   … 01 | 0a "Alexander" | 0a "Alexander" | 0b "S71500.CPU" | <ML> | 06 "PLC_1"
S7-1200: … 01 | 08 "Hustler" | 0b "S71200.CPU" | <ML> | 05 "OP10" | 0a "Alexander"
A603:    … 04 "PLC" | 0b "S71500.CPU" | 01 | 13 "A603A0097-plc-17u1" | 0a "Alexander"
```

Слот +0x58 и числа перед строками (`0x43`, `0x2e`) для этого не годятся:
`0x43` = 0x2f + длина строк авторов. Тип CPU, не кончающийся на `.CPU`
(ET 200SP, Software Controller и т.п.), не проверялся.

## Сопоставление с панелью

- Символьный тег I/Q/M/C/T: (ПЛК, область, ID символа) — установлено:
  10 из 10 в A603, 47 из 47 в Project1.
- Абсолютный: адрес (+ тип). Абсолютный HMI-тег может не иметь тега ПЛК
  (в A603 так 236 тегов) — это нормально.
- Член DB: по пути из панели, см. [блоки-данных.md](блоки-данных.md).
- ПЛК выбирается по IP соединения, см. [сеть.md](сеть.md).

## Чего мы не знаем

- Тип CPU кроме `S71500.CPU` и `S71200.CPU`.
- Теги ПЛК с двумя и более непустыми языками; varint длиннее 2 байт.
- Устойчивость ID символа при изменении программы ПЛК после загрузки панели.
