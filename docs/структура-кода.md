# Структура кода FlexRt

FlexRt — одно консольное приложение .NET. Папки `src/FlexRt/` разделяют
ответственность внутри проекта; отдельными библиотеками они не являются.
Namespace совпадает с путём папки: `Parsing/Plc/Plf/Tags/` —
`FlexRt.Parsing.Plc.Plf.Tags`.

## Как данные проходят через приложение

1. `Program.cs` вызывает `FwxReader.Read` для `pdata.fwc`: заголовок, TOC,
   затем `STRINGSTORE`, `VAR`, `DATALINK_READWR`, `DATALINK`,
   `CONNECTION_OMSP`, `DEVICE_OMSP`. Результат — `FwxDocument`.
   `PanelFilesReader.Read` берёт модель панели и версию Runtime из файлов
   рядом с `pdata.fwc`.
2. `PlfReader.Read` читает проект ПЛК `PEData.plf`: ПЛК и их IP, теги ПЛК,
   DB; если путь ПЛК — папка, `CardReader.Read` читает карту ПЛК
   (`SIMATIC.S7S\OMSSTORE`). Результат обоих — `PlcProject`.
3. `TagMatcher.Match` находит для каждого тега панели тег или член DB ПЛК.
4. Три независимых экспорта: `panel_data.xlsx` (листы «Сводка», «Теги»,
   «Ошибки»), `PDATA.xlsx`, hex-файлы.

## Зависимости

`Binary` ← `Model` ← `Parsing` ← `Export` ← `Program.cs`. Модели — только
данные. `Parsing/Panel` и `Parsing/Plc` друг от друга не зависят, общее у них —
`Parsing/Codes`. `Parsing/Plc` наружу отдаёт только `PlfReader` и
`CardReader`, остальное — `internal`.

## Если добавлять извлечение новых данных

Новая таблица панели: модель записи в `Model/Panel/`, список в
`FwxDocument`, парсер в `Parsing/Panel/` через `FwxDocument.FindTable` и
`FwxReader.CheckedItems`, строка `TryParse` в `FwxReader.Read`. Новые данные
проекта ПЛК: парсер в подпапке `Parsing/Plc/` по роли, объекты — через
`PlfFile`, связи — `PlfRelations.Scan`, подключение — в `PlfReader.Read`
(`Parsing/Plc/Plf/`); данные карты ПЛК — в `Parsing/Plc/Card/`, подключение —
в `CardReader.Read`.
Новые колонки листа «Теги» заполняются в `TagRowFormatter`.

Таблицы с одинаковым именем бывают (`PS_BorderedShap`, `Id` 0x161 и 0x169):
`FindTable` вернёт первую. Форматы описаны в `docs/формат-fwx/`,
`docs/формат-plf/` и `docs/формат-карты/`.
